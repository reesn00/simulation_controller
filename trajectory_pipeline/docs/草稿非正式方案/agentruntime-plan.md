针对引入 **Langfuse** 作为核心监控与可观测性平台，同时使用 **MCP 协议** 调用 Obscura（并预留后期平滑切换至 browser-use）的系统架构，以下提供完整的方案设计与功能详述。

---

### 一、 整体架构拓扑与职责划分

系统整体划分为五大职能层，形成“基础设施承载、状态图驱动认知、外部门禁硬控、标准协议操作浏览器、全链路可视化监控”的闭环：

1. **宿主与沙箱执行层（AgentScope Runtime）**
   * 作为生产级服务宿主，负责会话（Session）生命周期管理与标准 API 发布。
   * 提供独立沙箱环境，隔离托管以 MCP 模式运行的 Obscura 浏览器后台进程，防止高并发访问、复杂 DOM 渲染或恶意脚本引起的内存泄漏与进程崩溃。
2. **认知与状态流转层（LangGraph）**
   * 负责宏观检索逻辑编排（规划、检索动作、内容提炼、终审生成）。
   * 维护 Agent 运行时状态（检索目标、已访问 URL 清单、提取数据、失败重试计数、动态模型配置等），并通过状态快照提供随时断点重试与流转控制能力。
3. **外部判断与恢复控制层（External Gatekeeper & Guardrails）**
   * **核心控制枢纽**：完全脱离 LLM 推理，位于 MCP 客户端与 LangGraph 之间。
   * 在浏览器返回数据送达 LLM 之前，以纳秒级纯规则代码拦截、分析页面特征（CF、验证码、登录/付费阻断、死循环等），并执行现场修复、状态改写或流程强行重定向。
4. **浏览器执行层（Obscura MCP Server / 未来兼容 browser-use）**
   * Obscura 以标准 MCP Server 规范运行，向外暴露标准的浏览器操作工具集（导航、点击、取文本、执行脚本、轮换出口网络等）。
   * 对上层调用屏蔽浏览器内部底层实现，通过标准 MCP 工具规范为后期无缝引入 browser-use 打下基础。
5. **可观测与评估监控层（Langfuse）**
   * 作为统一的中枢观测系统，以非侵入方式全面穿透各层，采集 LangGraph 图节点流转、外部守卫拦截事件、LLM 思考推理、MCP 工具调用的完整执行链条。

---

### 二、 Langfuse 监控体系详细设计与功能

方案采用 Langfuse 原生 SDK 配合回调体系，将所有执行细节映射到层次分明的 Trace 树中。

#### 1. 结构化 Trace 树形设计
每次检索任务在 Langfuse 中生成一条独立的根 Trace（包含用户 Task ID 与 Session ID），其下细化为多级嵌套结构：
* **节点级 Span（LangGraph Nodes）**：记录状态机中每一个节点的进入与退出，如“检索规划节点”、“浏览器执行节点”、“结果提炼节点”，直观展现 Agent 的流转阶段。
* **门禁拦截级 Event（Gatekeeper Events）**：当外部规则触发拦截时，记录专门的“守卫拦截事件”，上报拦截原因（如 CLOUDFLARE_BLOCKED、LOGIN_WALL_DETECTED）、介入前后页面关键特征、以及采取的修复动作。
* **工具调用级 Span（MCP Tool Calls）**：记录经由 MCP 协议发往 Obscura 的每次请求，包含具体的 Tool 名称、输入参数、响应延迟以及底层返回的原始状态码。
* **大模型调用级 Generation（LLM Generations）**：精细记录每次大模型推理，包括系统提示词版本、输入上下文、实际模型输出、分词耗时，以及精准计算的输入/输出 Token 数量与财务成本。

#### 2. 核心监控看板与分析功能
* **安全墙与阻断特征归因看板**：按域名、拦截类型统计 Cloudflare 5秒盾、图形验证码、付费墙的发生频率，快速排查哪些目标站点需要调整代理策略或人工补录凭据。
* **模型动态升配与成本监控**：实时追踪标准模型与高阶模型在任务中的调用占比。精确分析在外部控制层触发“模型能力升级”后，任务的恢复成功率与额外带来的 Token 成本变化。
* **链路级重放与异常审查**：在 Langfuse Web 界面中展开任意失败任务，可逐帧复盘 Agent 的思考链与页面的被拦截状态。支持一键将特定步骤的 Prompt 与页面上下文发送到内置的 Playground 中重测或做打标评估（Evaluation）。

### 三、 外部判断与代码控制引导机制（核心亮点）

为了从根本上消除 LLM 在面对反爬防御、登录墙时的幻觉与盲目重试，**所有异常判断与决策优先交由外部硬编码逻辑裁决**：

#### 1. 外部规则检测机制（零 Token 消耗）
在 MCP 客户端接收到 Obscura 响应的瞬间，执行轻量规则嗅探：
* **Cloudflare / WAF 拦截判定**：检测底层网络响应码（403/503）、网页标题中包含的安全质询特征字符串（如“Just a moment...”）、以及 DOM 树中的 Turnstile 特征指纹。
* **验证码拦截判定**：扫描 DOM 结构中主流人机验证组件的典型锚点（如 reCAPTCHA、hCaptcha 等特征节点）。
* **登录墙与付费墙判定**：识别页面跳转特征（重定向包含 login/auth）、大面积模态遮罩层（Overlay 覆盖度过大且页面滚动受限）、或页面文本中明确出现的订阅限制词汇。
* **模型能力失配与行为死循环判定**：外部控制器维护一个滑动窗口，检测到当前 Agent 在同一域名下连续多步动作重复、或者连续提取出的有效正文为空时，判定为当前模型无法理解此复杂页面结构。

#### 2. 分层恢复与引导策略
根据拦截程度不同，实施分级处理：
* **第一层：静默本地自愈（对 LLM 完全透明）**
  * 命中 CF/WAF 时：外部控制层立即挂起当前流转，直接通过 MCP 发出切换代理 IP 或清理指纹指令，并在 Obscura 端强制重新请求。若重试成功，正常数据放行给 LLM，大模型完全感知不到底层曾经发生过被拦截与换 IP 过程。
* **第二层：图级逻辑重定向（改写状态并引导）**
  * 命中付费墙、强制登录、不可自动突破的验证码时：外部代码阻断页面数据灌入 LLM，并向 LangGraph 的状态中注入标准化的“系统引导指令”（例如：“目标站点存在高阻隔付费墙，已被系统拦截，请立即调整检索策略，从搜索引擎寻找备用信源”）。
  * LangGraph 的条件路由边检测到阻断标识，强行将流程引流至“重新规划节点”，从而彻底切断 LLM 在该网页上原地打转的可能性。
* **第三层：模型升配接管（Model Escalation）**
  * 当外部控制器判定模型连续多次未能提取出正确格式、或遭遇极其复杂的单页交互应用（SPA）时，外部控制器触发“升配策略”。
  * 动态改写 LangGraph 状态中的模型标识（例如从通用轻量模型切换为高阶推理模型），由高智能模型接管后续更复杂的多步动作与推理任务。

### 四、 针对未来演进至 `browser-use` 的解耦设计

方案将浏览器完全抽象为 **MCP 标准服务端**，实现极高的模块解耦度：
* **协议层一致性**：无论是当前极度轻量、低内存开销的 Obscura，还是未来主打复杂视视觉交互、多模态点击的 browser-use，均对外暴露一致的 MCP 协议接口。
* **平滑替换保障**：
  * AgentScope Runtime 仅需调整沙箱中启动的 MCP 服务镜像与启动参数；
  * Langfuse 维持现有的 Tool 监控维度与日志收集机制不变；
  * 外部守卫控制层只需保持原有针对 WAF、登录墙的判定规则库；
  * 上层 LangGraph 状态图模型与条件边逻辑完全无需修改，即可实现底层浏览器引擎的无缝替换或双引擎热切。
