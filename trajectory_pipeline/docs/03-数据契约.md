# 数据契约（P1/P2/P3）

与存量 C1/C2/C3 的目录、命名、schema **全不重叠**，并存不冲突。

| 契约 | 落点 | 内容 | 产出方 |
|---|---|---|---|
| **P1 观察存档** | `output/pipeline/<task_id>__<hash>.json` | 动作 + 工具参数 + **观察原文全文**（真实回放，非 LLM 转述） | [`executor/archive.py`](../executor/archive.py) |
| **P2 单条样本** | `output/pipeline/samples/<id>.json` | 六件套 + provenance + gate 标记 | [`assembler/builder.py`](../assembler/builder.py)（切条形状在 `schema.py`） |
| **P3 训练视图** | `output/pipeline/views/<id>_{messages,openai,meta}.json` | 训练框架可读形态 | [`assembler/views.py`](../assembler/views.py) |
| **T 完整任务视图** | `output/pipeline/task_views/<task_id>__<hash>.json` | per-run 三视图合一（LS 上传 / 任务级复核） | [`assembler/task_view.py`](../assembler/task_view.py) |
| 负样本池 | `output/pipeline/negative.jsonl` | 失败分支样本（带 `branch`） | [`executor/branches.py`](../executor/branches.py) |
| 复核队列 | `output/pipeline/review_*.jsonl` | 人工裁定（`verdict` + `reviewed_by`） | [`executor/review_queue.py`](../executor/review_queue.py) |

**工具声明的唯一真源是 [`toolcatalog/`](../toolcatalog/)**（不是 executor、
不是 assembler、也不是从 P1 反推）——P2 的 `six.tools`、P3 的
`openai.tools`、T 的 `openai.tools` 三处都是它的投影，所以逐字一致。
它挂在 `trajectory_pipeline/` 顶层而不是 `assembler/` 下，是因为
**P3 与 T 互不 import**（契约测试用 AST 强制），工具声明得有个两边都能用
的地方。口径见 [`toolcatalog/__init__.py`](../toolcatalog/__init__.py)
的模块 docstring 与 [`contracts/P3-views.md`](contracts/P3-views.md)。

**投影要按「面」取**（2026-10-20 方案 15 §5.5）：一份工具声明有两个身份——
**工具面**（执行层叫哪些名字、收哪些参数）与**方言**（属于哪套实现）。
后者**不是第二个独立轴**，由前者**一对一折算**（P1 的 `driver` → 面），
所以填错的机会只有一处、且那处由代码产生。两个面：`obscura-1`
（13 条声明 / 11 可见，`click(tag, label)`）与 `camoufox-1`
（16 条 / 14 可见，`click(role, name)` + 采集面 3 条）。**同名工具在两个面里
参数不同**——拿错面 = 声明与真实调用对不上，报告上看不出异常。

字段级契约文档在 [`contracts/`](contracts/)（**P1 / P2 / P3 三份都已写**：
[`P1-observation.md`](contracts/P1-observation.md) 由
[`tests/contract/test_p1_contract.py`](../tests/contract/test_p1_contract.py) 双向盯住，
`P2-sample.md` 由 `test_p2_contract.py`、`P3-views.md` 由 `test_p3_contract.py`
各配一份——文档与代码不同步就红）。P1 的实际形状以 `RunRecord.to_json()` 为准，
路径形状以 `archive.DEFAULT_ROOT` 为准（**平铺单文件，不是 `observations/<run_id>/` 目录**——那是设计方案早期为动作流分片预留的形状，实现从未采用，文档已对齐）。

> **观察是真实回放，不是 LLM 转述**——这条一旦破，rationale 就没有锚。

## P1 里三处「不给就不可判定」的字段

2026-10-09 按 rubric v1.1 补齐，实施记录见 [`03-rubric修订与实施方案.md` §9](设计方案/03-rubric修订与实施方案.md)。它们都不是「多存点信息」，每一处缺了都会让评分器把两件相反的事当成同一件：

| 字段 | 缺了会怎样 |
|---|---|
| `run_config`（整个 `RunConfig` 快照） | `--max-candidates 5` 与默认 20 跑出的两批**在存档里一模一样**，而覆盖完整性差 4 倍。`per_site_timeout_s` 更隐蔽——它连 `--help` 都查不到，却是 D-8 唯一的时限判据。缺它判 **DEGRADED**（`run_config_missing`） |
| 观察的 `elements_total` / `links_total` | 存档把交互元素裁到 80 条。「目标真不在这一页」与「目标恰好落在裁剪区外」同形——**两种相反的错判产出同一个分数**，而打分器看起来完全正常 |
| outcome 的 `site_url` / `play_page_url` | `outcome.url` 是**一字段三语义**（导航失败=候选 URL、找控件失败=`landed_url`、到播放页=`player_obs.url`）。读档的人得回查控制流才知道它指哪一层；丢了其中一个，另一个再也恢复不了（实测存档里有 http→https 跳转过的站） |

## 正文 `body_text` 落盘全文，不落摘要

早期只留前 400 字符，理由「体积失控、需要时重抓」——站不住：站点会下线改版（重抓拿到的是另一个页面）、被反爬时根本重抓不回来、rationale 的实体核查会把落在摘要外的实体判成幻觉（那不是幻觉，是**没存**）。P1 是批次唯一真值源，证据链断裂不可逆，体积只是磁盘（D8 已隔离产物路径）。

## 动作 + 工具参数落在 `steps[]`

顶层 `steps[]` 是搜索阶段，`visits[i].steps` 里是站点阶段。语义见 [`executor/actions.py`](../executor/actions.py)。三条口径：

- **`observe` 不是动作**，是上一个动作的观察回执。一次动作 + 紧随的 observe = 一个 step。记成动作会让模型学出「调用 observe」这种它不该发出的动作。
- **动作里没有 `ref`**——它是 obscura 的会话内句柄（导航前有效），进训练数据等于让模型学随机数。点击目标一律语义化为两个槽（obscura 面 `{tag, label}`、camoufox 面 `{role, name}`），这是**结构保证**（`Action` 没有可放 ref 的字段），不是序列化时过滤。实测 ref 从来没进过 P1（成功路径只记 `PLAYER_OK` 的 evidence，带 ref 的 `FIND_PLAY_CONTROL` 结论不记账），所以 `steps[]` 比 P1 原来有的**更多**。
  ⚠️ **键名逐面不同**：`obscura-1` 面写 `{tag, label}`、`camoufox-1` 面写 `{role, name}`（D12）。P4（2026-10-20）把**槽位名统一**成 `role`/`name`、**值域仍逐面不同义**（obscura 面的 `role` 槽装的是 HTML 标签名），投影只有一处（[`common/elements.py`](../common/elements.py) 的 `element_json`，键名表由 `toolcatalog.DIALECTS` 逐面给出）。新旧批次**不可混池**：`input` 与 `textbox` 在两套词表里对不上，而批次区分仍靠 `driver`（P6 批次元数据尚未落地）。
- **`origin` 区分「模型会选」与「执行器自己做的」**——会话隔离用的 `new_tab` 标 `infrastructure`：模型永不输出它，但它是真发生过的动作，删掉 P1 就无法回放。

另有一个容易漏的字段：**`user_prompt` = 用户开口说的那句**（persona 渲染后的原文），与 `query`（拿去搜的检索串）是两件事。六件套第 ③ 件要的是前者——它曾只活在计划文件里，于是 P2 拿不到用户轮次，而存档里看不出任何异常。空串 = 手工路径（与 `provenance` 空 dict 同款约定）。

## P2 切条的四条口径

见[架构总览](01-架构总览.md)「模块 5 · 组装」一节。要点：

- **一条 = 一个决策单元**（搜索阶段一条 / 每个站点一条）。
- **读 P1 不 import `executor`**——P1 贵、P2 便宜，重建一批 P2 必须独立于 executor 的当前版本。由 `tests/contract/test_p2_contract.py::TestNoExecutorImport` 用 AST 强制。
- **训练侧工具声明在 `toolcatalog` 侧冻结**，既不从 P1 反推，也不从 `executor.actions.TOOLS` import。`assembler.schema.TOOL_SPECS_BY_SURFACE` 与 `assembler.task_view.task_tools(surface)` 都是它的**投影**——手抄两份必然漂。
- **声明按「面」取**（2026-10-20 方案 15 §5.5）：面由 P1 的 `driver` **一对一折算**（`surface_of_driver()`），落在 P2 顶层 `tool_surface` 与 P3/T 的 `meta.tool_surface`。**认不出的 `driver` 直接抛**——不猜、不静默回落。
- **能力声明 ≠ 动作空间**（默认面 `obscura-1`）：`toolcatalog` 里 13 条，只有 6 条是执行端真发得出、且有存档兜底的动作；另外 7 条是**能力声明**（模型被告知存在，但本项目没有任何真实调用产生过它们）。camoufox 面是 16 条（14 可见）——多了采集面 3 条（`snapshot` / `interactive` / `links`；**驱动层已实现**（P3-β，2026-10-20），但**没有任何一次真实调用**进得了训练动作流——采集面由执行器推、模型看不到——故 `exercised=False` 不变。「已实现」与「有过真实调用」是两件事，别把前者当成后者）哪些没用到由渲染侧按本条的 `actions[]` 现算，落进 `meta.tools_unused`——**逐个列名，不合成计数**。
- **缺件必须看得见**：闸门三值 `passed` / `failed` / **`not_run`**；老存档缺的键逐条记进 `degraded_from`。

### 六件套第 ⑥ 件「思考 + 结论」：**已接线，形状为与动作对齐的列表**

`six.rationales` 是**与 `six.actions` 按 `step_index` 对齐的 `Rationale` 列表**——
一条样本有 N 步就有 N 段思考（`docs/contracts/P2-sample.md` 记其字段契约）。
单向旧形状（`rationale: Rationale | None`）在
`schema.align_rationales` 里仍兼容旧 P2（磁盘上已有旧样本），但新样本一律列表。

⚠️ **接线范围**：执行期 `orchestrator._write_rationales` 已泛化为
`(steps_log, record, label)`，**站点访问步与顶层搜索步同走 writer**——
2026-10-11 起搜索步 settle 成功后也补记 rationale（此前恒 `null`，裁定为漏生成，
见[对齐账 §2.8](设计方案/02-rubric与代码对齐.md)）。

**生成位置与核查位置分置**：生成在执行期写 P1 的 `steps[i].rationale`
（模型从 `TRAJECTORY_LLM_*` 环境变量取）；闸门核查在组装期
（`schema.gate_of` 逐条跑三查）——因为**时序核查需要全序列**，
执行期那一刻后续步还不存在。

## 负样本池 / 复核队列的标签域（阶段 1 扩展）

2026-10-12 阶段 1 把登录墙合并态拆为细分，分支体系 10 → 13（活跃）+ 1 deprecated：

| 分支 | 归类 | 说明 |
|---|---|---|
| `login_required` | ② 的细分 | 登录后可免费看；agent 无登录态 → 不通过 |
| `blocked` | ② 的细分 | 地区限制 / 验证码 / 反爬环境阻断 |
| `broken` | ② 的细分 | 内容损坏（404 / 媒体不可解码 / duration=0），与 `unreachable_hard` **刻意分离** |
| `partial_free` | ④ 的细分 | 有免费部分（试看/预告），完整内容需付费 |
| `login_wall_or_blocked` | deprecated | 历史合并态；旧存档不回填（不虚构），新代码不再主动产出 |

- 标签全集 = `BRANCH_LABELS` 14 key（13 活跃 + deprecated）+ `success` = **15 类**；`all_branches()` = 13。
- 人工复核队列 `ReviewItem` 增三字段（`executor/review_queue.py`）：
  - `media_signal`: str —— 播放信号摘要（如 `duration=0`），暴露媒体损坏形态供复核；
  - `paywall_type`: str —— 付费墙类型（`paid_subscription` / `rental` / `purchase` / `trial` / `preview` / `none` / `unknown`）；
  - `screenshots`: tuple[str, ...] —— 复核截图路径列表（新体系 L2 定时截图 / L4 VLM 链路）。

## 黄金集契约（G1）

产出目录 `evaluation/golden/data/`（与 output/ 命名空间分离，随代码纳入版本控制）：

| 文件 | 内容 |
|---|---|
| `candidates.jsonl` | 候选样本：`golden_id` / `source_kind` / `task_id` / `run_id` / `url` / `site_url` / `play_page_url` / `code` / `persona` / `golden` / `retest` |
| `annotations.jsonl` | 人工标注：`golden_id` / `round`(1 初测, 2 retest) / `label` / `label_label` / `reviewed_by` / `reviewed_at` / `note` / `dimension_scores` / `interval_days` |
| `versions.jsonl` / `v<N>/manifest.json` | 冻结版本索引与 manifest（含 `label_schema_version`） |

- `annotate` 的 label 合法值由 `BRANCH_LABELS + success` **自动派生**（15 类）——新分支注册即生效，不维护第二份常量。
- D10 口径 C = **语义等价类一致**：`alignment.equiv_class(gold) == alignment.equiv_class(pred)`，映射唯一出处 `evaluation/golden/alignment.py::EQUIV_CLASS`（新增分支忘登记等价类 → fail-closed `KeyError` 当场红）。
- 等价类刻意分离：`broken` → `BROKEN_CONTENT`、`unreachable_hard` → `REACH_FAIL`，不是同一等价类。
- `manifest.json` / `versions.jsonl` 写 `label_schema_version`（1 = 11 类，2 = 15 类），跨版本对比 D10 前先核对。
- 对齐方案 §5.1 的 `code.media_signal` / `paywall_type` 等全可选字段：**阶段 4** `mcp_probe.media_probe` 落地后由 code dict 承接，缺省空值不破坏现有契约。
- **L4 VLM 复核字段不进 G1**：`vlm_review: VLMReviewResult | None`（含 `screenshots: tuple[str, ...]`）属于阶段 4 `cli mediabrowse` 输出（`output/pipeline/mediabrowse/P<id>__*.json`），落在 [`executor/probe/media_probe.py`](../executor/probe/media_probe.py) 的 `BrowserProbeResult` 上，不属 P1/P2/P3 也不进 G1。G1 仅承接 `code.media_signal` / `paywall_type` 等极小子集，全字段契约见 [架构总览 §L4 复核层](01-架构总览.md)。
