## 1. 分块结论

| 块 | 结论 | 一句话 |
|---|---|---|
| **黄金集** | 站点级底座可用；**轨迹交付层不可交付** | 冻结档不可变、切分单一真源、v16 计数一致；但 per-Run 后新长出的 `trajectories.jsonl` 没接任何门禁，分数在 `from-scout → labeled → freeze` 三段里静默丢失 |
| **评估器** | D-2/D-4/D-6 主体可信；**评估读取链在 per-Run 后粒度错误**；**D-10 零调用方** | 一个 run 多站点只按末条 outcome 打分；D-5 有 `skipped → 5 分` 白送口；D-10 完整实现却是死代码 |
| **评估后反馈** | gate/分诊/抽样骨架正确；**归因不可信、reflow 改判不可用** | calibration 金标变动只警告不拦、net 判据不看归因 ⇒ 净改善可被「改金标」伪造；reflow 改判链断在 worksheet / apply / refresh-label 三处 |

**一句话总判断**：站点级黄金集可以继续作为 D-10 的测量底座；**轨迹交付层当前不可对外交付**；**评估读取链在 per-Run 之后不能用于站点级结论**；**反馈回路的 gate 骨架可用，但「净改善」读数不可信、人工改判落不了地**。

### H-1 · per-Run 后评估读取链仍按「轨迹」打分，站点级结论被末条 outcome 代表

- **事实**：`split_archive(path)` 现在对一份存档返回 **0 或 1 条 `Sample`**（一条轨迹 = 一个 Run），但 `evaluate()` 直接 `dispatch[dim](sample)`（`cli.py:288`），**不展开 `sample.site_views()`**；`_score_one` 同样对整条 P2 文件跑四维评分。`evaluate()` 的 `row["url"]` 也取 `sample.outcome.url`（`cli.py:284`），即末条 outcome 的 URL。
- **失败场景**：实测 `E001__57bbf995.json` 切出 **1 个 Sample + 2 个 site view**：轨迹级 `d6=5 / d5=5`，而 site0（hao123）`d6=None`、site1（1905）`d6=5`。一个 run 里「A 站成功、B 站失败」会被轨迹级的成功分掩盖；`scout aggregate` 的 min 从「最差站点」退化成「最差 run」，站点级负样本在评分侧消失。
- **测试**：**零覆盖**。现有 `test_evaluation_cli` 用的是 per-unit 时代的存档形状。
- **状态**：**新发现**（per-Run 改造的遗漏波及）。

### H-2 · `from-scout` 链路：分数丢失 + `None→0` + 重复 golden_id + 无孤儿门禁

- **位置**：`evaluation/golden/builder.py:5325-5400`（`cmd_from_scout`）、`5343-5346`、`5397`；`780-838`（`_site_entries`）；`2185-2246`（`_labeled_rows`）、`2229-2232`；`2249-2327`（`_build_trajectory_dataset`）、`2283`、`2292-2301`；`2569-2636`（`_refresh_scores`）、`2620-2624`。
- **事实**：
  1. `dim_scores = {s["dimension"]: (s["score"] if s["score"] is not None else 0) ...}`（`5343-5346`）——**`None→0`**，直接违反 fail-closed；
  2. 每条 scout 记录都 `_trajectory_row(... site_outcomes=_site_entries(archive) ...)` 并 `candidates.append`，**无按 `(task_id, run_id)` 去重**；per-unit 时代的 scout 目录（r51：122 条 / 51 runs / 单 run 最多 16 条）会产出重复 `golden_id`；
  3. 直接 `_dump_jsonl(dst, candidates, force=args.force)`（`5397`），**无孤儿门禁**；
  4. `_site_entries` 只产结构字段，**不产 `status` / `dimension_scores` / `scores_detail`**；
  5. `_labeled_rows` 只遍历 `site_outcomes` 并拷 `site["dimension_scores"]`，**忽略轨迹行顶层 `dimension_scores`**（`2229-2232`）。
- **失败场景**：合成轨迹候选顶层 `dimension_scores={d2:5,d4:4,d5:3,d6:2}`，经 `_labeled_rows` 后两个站点行均变成 `status=None, scores={}, scorer_version=None`——**打分在冻结时被整段丢掉**；随后 `freeze --refresh-scores` 因 `if not cand.get("status"): raise GoldenError`（`2620-2624`）**退 2**。即使分数没丢，run 级分数也会被 `_site_entries` 平摊到该 run 的所有站点，与「逐站点评分」语义不符。
- **测试**：无「from-scout → labeled → freeze」链路的端到端测试。
- **状态**：**新发现**。

### H-4 · 金标变动可绕过「新基线」闸门，`net_improvement` 可被伪造

- **位置**：`calibration/gate.py:229-259`；`calibration/verify.py:245-306`、`402-420`、`544-666`、`604-618`、`655-666`、`787-794`；`builder.py:3197-3199`。
- **事实**：
  1. `assert_gold_comparable` 只读 manifest 的 `gold_refresh.baseline_reset` / `label_refresh.baseline_reset`；**fresh freeze 写 `{"enabled": False}`**（`builder.py:3198-3199`）⇒ 全新冻结的金标变动**不拦**；
  2. `verify.analyze` 对 **regression** 金标变化抛 `VerifyError`（`604-618`），但 **calibration** 金标变化只进报告不拦（`655-666`）；报告打印「⚠ 金标变了…净改善不可归因到评估器」（`787-794`），**退出码不变**；
  3. `_criterion_net` 只看 `net` 与 `paired`（`402-420`），**不看 `gold_changed`**；`criteria` 里没有归因判据（`655-666`）。
- **失败场景**（已用合成快照复现）：baseline 1 条 `disagree`；current 同 `golden_id` 因 gold 从 `blocked` 改成 `success` 而变 `agree`（pred 未动）；另加 1 条不变 calibration + 1 条不变 regression ⇒ `analyze` 返回 `gate: pass`、`net_improvement: pass 净改善 1`、`calib attribution: {gold_changed:1, pred_changed:0, both_changed:0}`、**退出码 0**。**改金标即可制造「评估器净改善」**。
- **测试**：无「gold_changed 但 pred 未变」的判据测试。
- **状态**：**新发现**。

### H-7 · `_refresh_label` 只刷站点行，轨迹级改判无路；`rows_matched` 记成 label 种数

- **位置**：`builder.py:2812-2889`、`2866-2870`、`2874`、`2882`。
- **事实**：只遍历 `parts`（站点行）；`changed_rows==0` 退 2（`2866-2870`）；`rows_matched = len(after_by_label)`（`2874`）——记的是**不同 label 的种数**（约 12），不是行数（294）；`baseline_reset=True` 无条件写（`2882`）。
- **失败场景**：per-Run 后人核主要落**轨迹级**标注；reflow 的 relabel 目标是轨迹行。`freeze --refresh-label` 不遍历 `trajectories.jsonl`，轨迹级改判**永远不生效**；如果站点行恰好没有 label 变化，命令还会因为 `changed_rows==0` 退 2，掩盖「轨迹级其实变了」。
- **测试**：无轨迹级 `--refresh-label` 测试。
- **状态**：**新发现**（与 H-3 同一条链，但独立成缺陷）。

### H-8 · `_refresh_gold` 的 `filled` 是全局守卫，会「部分刷新 + 静默清空其余行」并重置基线

- **位置**：`builder.py:2701-2770`、`2708-2716`、`2725-2743`、`2759`、`2764`。
- **事实**：
  1. `filled` 只要求**全表任意一条**标注有 `dimension_scores`（`2708-2716`），不是逐行守卫；
  2. 循环对每一行都执行 `golden["dimension_scores"] = dims`（`2736`）——**如果该行的 `ann` 没有分数，`dims=None`，会把该行已有的 golden 软维度分写成 `None`**；
  3. `changed_rows` 算出来了（`2740-2741`）但**没有任何 guard**；`baseline_reset=True` 无条件写（`2764`）；
  4. `filled` 把**轨迹级标注**也算进来，但循环只改站点行 ⇒ 只有轨迹级分数时，可能「站点全被清空 + 基线被重置」。
- **失败场景**：人只给 3 个站点填了软维度分，其余 291 行对应的标注是 label-only（reflow 写入的标注不带 `dimension_scores`）。`--refresh-gold` 通过全局 `filled`，随后把这 291 行的 `golden.dimension_scores` 全部写成 `None`，并宣告「金标变了 = 新基线」。**分数悄悄没了，且没有任何报错**。
- **测试**：无部分标注刷新测试。
- **状态**：**新发现**。
