# 02 · 感知与判定域

**职责：** rule / llm 两套 perceptor 读观察，给出 `access`（访问控制类型）/
`paywall`（付费形态）/ `player`（播放器状态）三组结论。
对应 [架构总览](../01-架构总览.md) 的**模块 3 感知层** + **四个判断点**。

**核心纪律：** LLM 是传感器不是驾驶员。**感知内容由 `Perceptor.decide` 给，
决策权在控制流**。本域的 `rule` 与 `llm` 是两个**可互换插件**，
`replay --perceptor both` 可回放对比。

## `page_quotes` 字段治理（增量二十一，P4a 第三轮）

**问题来源**：v.qq.com 70017001 实跑 → `access.evidence_quotes` 全 `""`，
LLM 把 region 文案套进了 `evidence` 字段而 `page_quotes` 留空，
**纯靠 `evidence` 反推 `access` 又把脏字段当 clean 喂回去**，
Perceptor `access` 落到 `""` → `BlockedRegion` 误判为 `""`。

**落点**：

| 处 | 修了什么 |
|---|---|
| `perception/llm_perceptor.py` regex | 字符集「开 / 否 / 闭」三配套（全加 ASCII 直引号 `"`），跨右书名号不再吞脏 |
| `perception/llm_perceptor.py` 三道 gate | 结构 / 业务 / 长度。业务 gate 命中 `_BUSINESS_QUOTE_HINTS` 4 类（品牌 / 业务词 / 付费提示 / region 文案）。三选一失败 → 该段只进 evidence 候选，**不再写进 `page_quotes`** |
| `_quotes_with_fallback` | L1（LLM 抽到 ≥1 段）> L2（LLM 抽 0 且 text ≥30，rule fallback）> L3（`[]`）。关键边界：fallback 是「LLM 啥都没抽到」的兜底，**不是「抽到了全短」的覆盖** |
| `perception/rule_perceptor.py` | `ACCESS_HINTS` region 段 +2 关键词（「当前设备不支持播放」/「设备不支持播放」） |
| `tests/unit/test_llm_perceptor.py` | +9 `TestExtractBusinessQuotes` + 4 `TestQuotesWithFallback` + 3 `TestPostProcessingFallbackDecide` = +16 contract |

**KPI（2026-10-12 当晚补跑）**：v.qq.com 10 URL 实跑
`cli proberun --task-id P021 --perceptor llm`：

- **分支分布**：blocked × 8 · no_play_control × 2
- **`page_quotes` 抽中率**：**8/10 = 80%**；region 文案（「当前设备不支持播放」
  +「错误码：」+「70017001.1」）全 8 例命中，3 段/段
- **Fallback 三层分布**：**L1=8 / L2=0 / L3=2** —— LLM 在 P4a 第二轮 prompt 下
  直接抽到 page_quotes，`_extract_business_quotes` **没让 fallback 救场**
  （L2 触发条件在 v.qq.com 上从未走到）；2 例 no_play_control 走 L3 空数组
  （合理：综艺/列表页本就不该填业务文案）
- **P3 v1 regression**：v.qq.com 70017001.1 仍稳定判 blocked（0/8 错判 broken）

**结论**：P4a 字段治理的「LLM 答得稳 + 代码接得住 + 写时落到对的位置」
三件全备成立。**fallback 是冗余防线而非主路径。**

作用在 `body_text` 上，够不着目标行；反而够得着 `error.html` 页脚这类噪声。
探针（INC43 `inc43_probe_body.py`）**只验了「body 里有没有付费墙信号」，
没验「目标行的 body 里有没有」——分层粒度不够导致假设错位**。

- **回滚**：④ 救济段（`llm_perceptor` 恢复 INC43 的 ②③ 范围，

- **保留**：`branches` 旁路的确定性通道（`paywall_word` + 强弱信号双门槛）——
  只服务 `_player_ok` 短语命中路径，本轮未误放行，
  3 条边界测试钉住（强信号放行 / 弱短语仍降级 / 无标记仍降级）

### 三条教训

1. **词表救济前先核对信号位置**：目标簇的证据在 `body_text` 还是

3. **簇 A 真正出路**（若做）：把 ④ 的 `page_quotes`（LLM 回传页面原文短语）
