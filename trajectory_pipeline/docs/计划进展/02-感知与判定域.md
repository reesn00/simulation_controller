## `page_quotes` 字段治理（增量二十一，P4a 第三轮）

**问题来源**：v.qq.com 70017001 实跑 → `access.evidence_quotes` 全 `""`，
LLM 把 region 文案套进了 `evidence` 字段而 `page_quotes` 留空，
**纯靠 `evidence` 反推 `access` 又把脏字段当 clean 喂回去**，
Perceptor `access` 落到 `""` → `BlockedRegion` 误判为 `""`。

**落点**：

| 处 | 修了什么 |
|---|---|
| `perception/llm_perceptor.py` regex | 字符集「开 / 否 / 闭」三配套（全加 ASCII 直引号 `"`），跨右书名号不再吞脏 |
| `perception/llm_perceptor.py` 三道 gate | 结构 / 业务 / 长度。业务 gate 命中 `_BUSINESS_QUOTE_HINTS` 4 类（品牌 / 业务词 / 付费提示 / region 文案）。三选一失败 → 该段只进 evidence 候选，**不再写进 `page_quotes`** |
| `_quotes_with_fallback` | L1（LLM 抽到 ≥1 段）> L2（LLM 抽 0 且 text ≥30，rule fallback）> L3（`[]`）。关键边界：fallback 是「LLM 啥都没抽到」的兜底，**不是「抽到了全短」的覆盖** |
| `perception/rule_perceptor.py` | `ACCESS_HINTS` region 段 +2 关键词（「当前设备不支持播放」/「设备不支持播放」） |
| `tests/unit/test_llm_perceptor.py` | +9 `TestExtractBusinessQuotes` + 4 `TestQuotesWithFallback` + 3 `TestPostProcessingFallbackDecide` = +16 contract |

**KPI（2026-10-12 当晚补跑）**：v.qq.com 10 URL 实跑
`cli proberun --task-id P021 --perceptor llm`：

- **分支分布**：blocked × 8 · no_play_control × 2
- **`page_quotes` 抽中率**：**8/10 = 80%**；region 文案（「当前设备不支持播放」
  +「错误码：」+「70017001.1」）全 8 例命中，3 段/段
- **Fallback 三层分布**：**L1=8 / L2=0 / L3=2** —— LLM 在 P4a 第二轮 prompt 下
  直接抽到 page_quotes，`_extract_business_quotes` **没让 fallback 救场**
  （L2 触发条件在 v.qq.com 上从未走到）；2 例 no_play_control 走 L3 空数组
  （合理：综艺/列表页本就不该填业务文案）
- **P3 v1 regression**：v.qq.com 70017001.1 仍稳定判 blocked（0/8 错判 broken）

**结论**：P4a 字段治理的「LLM 答得稳 + 代码接得住 + 写时落到对的位置」
三件全备成立。**fallback 是冗余防线而非主路径。**

## ✅ 已闭环 · M-26 · 媒体计数不再许诺成功（2026-10-23）

**病根（一句话）**：**媒体计数被当成了「成功」的充分条件**。代码层可以**否**，
不能**许**——媒体计数只能当**必要条件**。

**两处同病**（不是一处）：

| 位置 | 原文 | 后果 |
|---|---|---|
| [`llm_perceptor.py::decide`](../../perception/llm_perceptor.py) | `question == Q.PLAYER_OK and obs.video_tag_count >= 1` ⇒ 直接 `answer=True`、**不问 LLM** | 优酷「试看6分钟｜开通会员看完整视频」页 `video=1` ⇒ 被读成「能看正片」⇒ **5 份存档 5 条假成功**；网易号美食图文页 6 个 `<video>` 是**点广告后注入**的 ⇒ 同样被读成成功，而它**正文里连付费形态词都没有** ⇒ 词表修法抓不到 |
| [`rule_perceptor.py::_player_ok`](../../perception/rule_perceptor.py) | `media >= 1` ⇒ `answer=True` | 同一条病在规则版上；规则版**没有 LLM 可让**，于是它的「成功」是**纯计数许诺** |

**修法（已落）**：**两处短路整体删掉**——`video_tag_count >= 1` **永不许**直接
产出 `answer=True`：

1. **LLM 版**：④ 只剩一条路——问模型。媒体计数仍进 prompt 与 payload
   （`payload["media_count"]`），但它是**观察事实**，不是结论。
   「页面确实是播放页」由**别的**判据保证（模型判 + 到达路径），
   **不由媒体计数保证**。两处都留了**墓碑注释**（写清「这里原来有什么、
   为什么删」——不留的话下一个人会按「确定性事实优先」把它加回来）。
2. **规则版**：一律 `answer=None`（fail-closed）。它没有 LLM 可让，而 `False`
   更糟（会把「能看但判不出」写成**真负样本**进池）⇒ 落 `player_unverified`：
   **不进负样本池**、在人工复核队列里（这正是 W1 设计的正样本路径）。
   ⇒ 影响面实测：全库 `player.ok` outcome 按 (source, branch) 统计里
   **规则版判成功的条数 = 0** ⇒ **不碰任何既有数据**。
3. **防复发**：AST 守卫（`tests/unit/test_media_count_guard.py`）扫两个感知层
   模块，抓「`if` 判据里出现媒体计数 ⇒ 分支里 `return` 常量 `True`」这种形状；
   变异清单里两条对应变异（LLM 版把短路插回去 / 规则版 `None` ⇒ `True`）
   **实测都变红**。

**实跑读数**（2026-10-23，用**真 LLM** 把三份存档的 ④ 判定重放一遍，逐条读
evidence；脚本 `research/probes/m26_replay_player_ok.py`）：

**验收条件逐条对上**：① 优酷那 5 份存档重放 ⇒ 不再产 success ✅（读数
`paywall=True` / `preview`）；② 一份真·能看的页面仍判 True ✅——但**不是**由
计数许诺（模型判的）；③ 单元测试：付费形态 × 媒体计数 ≥1 ⇒ 不得返回 True ✅。

**⚠️ 剩余风险一 · 计数经**提示词**继续当正面证据 ⇒ 同一条图文页仍假成功**
（2026-10-23 实测，**本单最硬的读数**）：

网易号美食图文页（6 个 `<video>` 是点广告后注入的）**连问 8 次：7 次 True、
1 次 False**；其中一次 6 连问 **6/6 True**，evidence 全是
「检测到多个视频媒体元素，且未见付费门禁」。
⇒ **代码层的短路删了，④ 的结论却没变**——因为**提示词**第一句就是
「**结合代码测得的媒体元素数量**，判断它**是不是一个能正常播放的播放器页**」
（[`perception/questions.py`](../perception/questions.py) 的 `Q.PLAYER_OK`）。
计数**从提示词**进模型，模型**照提示词办事**——它看到「6 个 video 元素」
就把页面读成播放页。⇒ **代码层不再越权，但计数没退出判断，只是换了个入口。**
⇒ ⚠️ **本单不能修它**：提示词口径是 owner 定的（当时的施工单禁区明写「不许动
PLAYER_OK prompt」——**禁区原文不改写**）⇒ **单独立项 §Q-13**，请 owner 裁定。
⚠️ 附带一条：后端 `temperature=0.0` 仍**不是逐字确定**（同一观察 8 次里翻了
1 次面）⇒ 与台账 §M-08「judge 输出非确定性」同族；**禁止投票/集成**，
分歧必须暴露给人看。

**⚠️ 剩余风险二 · 模型判否 + `media ≥ 1` ⇒ 可能变成假负样本**
`component_unverified`。媒体计数不再兜底后，「有 `<video>` 标签但播放器没
正常工作」这种页面（标签在、播放器坏）会由模型判否 ⇒ 落 `component_unverified`
⇒ **进负样本池**。本单**没有**给 `component_unverified` 加前置事实——那与
2026-10-10「`video_tag_count` 不再是 `component_unverified` 的判据」的裁定
直接相关，**owner 未裁定** ⇒ 只**记账**，不动代码（见下方未闭环项表）。

**判定依据**：AST 守卫 `tests/unit/test_media_count_guard.py`；变异清单两条
`媒体计数不许许诺成功·LLM版` / `·规则版`（把短路插回去 ⇒ 必须变红）；
全量门禁 **3869 passed**、变异测试 **`PASS 51/51`**。见
[编年史 增量八十三](90-增量编年史.md)。

**顺带撞见的一条既有问题（非本单造成）**：`perception/replay.py` 的「旧判定」
列在 **31/135** 条 ④ 回放单元上**静默变空** ⇒ 单独立项 **§M-31**。
