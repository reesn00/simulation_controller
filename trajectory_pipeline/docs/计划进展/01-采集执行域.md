# 01 · 采集执行域

**职责：** 搜索 → 候选提取 → **camofox** 浏览器取 DOM → 落 P1 存档。
对应 [架构总览](../01-架构总览.md) 的**模块 2 执行层**。

**核心纪律：** 这一域产出的是**事实层**——它只负责把页面上真实存在的东西
原样记下来，**不判断**「这是不是播放站」。判断归感知层。

## 判断点 ① 真正根因 = 「窗口与候选集合错位」

**这是本域最重要的一条结论，且它推翻了一个此前的假设。**

2026-10-11 增量十二，第二批（`T013`/`T011`《功夫》，llm 感知，`plan_batch2`）
把根因钉死了——**模型根本没「空回传」，它答了 `selected` 非空（answer=True）**。
证据链：

1. 存档 `candidate_source=perceptor`、warning「选出 0/5 个候选，0 个记
   not_play_site，5 个模型未点名」——只有 `_apply_selection`（answer=True 分支）
   会产出；若空回传（answer=None）会走 heuristic 分支，`candidate_source`
   会是 `heuristic`。**模型给了选中项。**
2. 5 个候选全部 `unresolved`（kept=0）——`_apply_selection` 遍历候选时，
   模型选中的 URL **一个都没命中**候选的 `source_href`/`url`。
3. **错位机制**：`extract_candidates` 从全量 111 条 links 过滤出 5 个候选
   （`candidate_filter: engine_self=89, excluded_host:baidu.com=17`，111-106=5），
   而送给模型的窗口 `_link_window = _ordered_links[:20]` **只看排序后的前 20 条**——
   百度把导航（登录/新闻/地图/视频/贴吧/学术/设置…）排在结果之前，
   「含片名」的命中项提前后，窗口 20 条里**只有 hao123 一个候选**，
   爱奇艺/西瓜/搜狐/优酷四个真实候选排在 index≥50，**模型根本看不见**。
4. 模型在窗口里能选的，是「《功夫》完整版免费」这类**站内搜索链接**
   （`baidu.com/s?wd=…`）——它把这些当成「可看的站」选上，但它们是
   `baidu.com` 域，全被候选过滤剔除 → 模型的答案与候选集合零交集。
   **模型不是偷懒，是候选在它的视野之外。**
5. 顺带证实：T2 加的「空回传原文摘录」分支（`raw_selected`/`raw_rejected`
   全空）没有触发——因为根本没有空回传发生。存档里搜不到「模型原文摘录」
   正是这个原因，与改动本身正确与否无关。

**修复方向**：候选提取（代码层事实）与 LLM 视野（`_link_window`）
**必须同源**——要么让窗口先包含全部候选（把候选链接钉进窗口），要么
`_apply_selection` 之前先问 LLM「这 20 条里哪些是可看站」再把答案与候选
求交。当前「窗口 ≠ 候选集合」的错位会让任何模型都答不出正确结果。
方案见 [`../设计方案/05-候选提取与窗口同源修复方案.md`](../设计方案/05-候选提取与窗口同源修复方案.md)。

**防空回传的提示词两手**（保留，与上面那条无关——那是「候选不可见」，
这是「模型答不答」的另一条防线）：

- 提示词显式禁掉「两个数组都留空」，并要求回 `i`；
- `_render` 给每条链接编号，回指交给代码。

**空回传时把模型原文片段记进 evidence**——已做（2026-10-11，增量十二），
第二批未触发（因本批根本没有空回传）。这个改动仍然保留：万一将来真出现
selected/rejected 全空，`_select_play_sites` 空回传分支会把模型原文
**先 `strip_think` 再截前 120 字**记进 evidence（`_excerpt`，与
`_why_unparsable` 同一条红线；测试 `TestNoConclusionVsUnmatched` 守着
「剥 think 后的原文能看见、思考本身不落入」）。

这一步**曾经被一条红线破口挡住**（解析失败路径会把 raw CoT 写进 evidence），
该破口 2026-10-11 已修（增量十一第四项）——所以现在可以安全地做了。

## 三项「看着对」的修复（跑下一批时先看它们的 evidence）

| 原待办 | 现在的行为 | 封它的守卫 |
|---|---|---|
| 🔴 `FIND_PLAY_CONTROL` 要不回 ref | **代码按词表取回第一个非预告控件的 ref**，evidence 写明是代码补的 | `TestRef由代码取回` + 4 条变异 |
| 🟠 判断点 ① 回传格式对不上 | ① 改为**回编号 `i`** 而非 URL；两个数组都空时 evidence 改成「未作答」 | `Test回指编号而不是url` / `TestNoConclusionVsUnmatched` + 3 条变异 |
| 🟡 `hao123` 首页被当成播放站 | 新增**环节 ①.6 站点首页核**：path 为 `/` 记 `not_play_site`，不访问 | `Test站点首页核` + 1 条变异 |

⚠️ **这三项最容易「看着对」**：

- ref 取回写的是「词表说了算」——如果取回的那个 ref 点进去是广告位，
  **守卫没错而词表错了**；
- 首页核只看 path——某站若真把播放页放在根路径，这条会误伤
  （可复核，不是不可逆）。

## 采集侧：已修待验

- **正文缺失 / `steps` / `site_url` 缺件**（清空前实测 `no_body` 38 /
  `body_preview_only` 21 / `steps` 缺 24 / `site_url` 缺 65）在第二批**未复现**——
  降级样本 0 条。但那批只 3 个站，**样本量不足以说修好了**。
- **`TEXT_CONTENT_EXPR` 剥 script**（INC43 修复①）——`iqiyi ×3` 的
  textContent fallback 把 `<script>` 采进 body（2651 字符全 JS），
  撑过 `_sufficiency` 守卫造成**假恢复**。改为 clone body → 删
  `script/style/noscript/template` → 取 textContent。剥离后为空按原边界
  记 degraded——**诚实失败**，不再让 JS 文本撑过守卫。
  实测降级恢复 27/30 → **4/30**（收紧是有意的：上轮 27 里多数是 JS 假恢复，
  分支照旧判错且污染 LLM 输入）。
