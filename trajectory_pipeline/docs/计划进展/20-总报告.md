| **v2 轨迹合成管线** | `trajectory_pipeline/` | **当前唯一开发目标** |
| **v1 存量管线** | `archive/v1/` | **冻结**：只读参考，**不可 import、不可修改** |

**v1 是「远端 agent 当驾驶员，本地只当模拟用户 + 裁判」；v2 把那颗心脏换掉**——
**本地 agent runtime 当探索者、本地代码当护栏、camoufox 当浏览器**。
v2 要采集的是**可归因的证据**，而 v1 的观察经远端 LLM 转述后锚会被削弱。

### 4.2 控制流铁律：LLM 层做探索，代码层做护栏

**探索权在 agent runtime，护栏与调度在代码。两者分界是五样东西——一样都不许交出去：**

| | **执行器（代码）** | **agent runtime（LLM）** |
|---|---|---|
| 拥有 | 浏览器会话、红线闸门、预算、拦截与处置、分支记账、终局验收、落盘 | 动作选择、**看什么**、终局自报 |
| 没有 | 动作选择权 | 分支决定权、成功判定权、会话管理权、批次调度权 |

**代码必须保留的五样（归因地基）**：步数 / `llm_calls` / 超时预算 · **终止判定** ·
**处置映射** · **分支记账**（22 类封闭集，agent 永不直接产分支）· **fail-closed**。

**感知层不再当「传感器」**，退位成三块**静态资产**：判断题文本（进 agent 任务指令）·
分支记账映射表（不动）· 规则检测器（进 gatekeeper）。它在热路径上只剩一个岗位——
**终局验收**（④ `PLAYER_OK`：agent 报「到了」，代码判「真到了吗、播放器起没起」）。

**观察由谁发起，决定它进不进动作流**：执行器推的回执 = 观察（**不进**训练 `tool_calls`）；
agent 主动拉的读 = **动作**（进）。

> ⚠️ 旧表述「LLM 是传感器，不是驾驶员」**已作废**——A1/A2/A2b 把站内导航整段交给 agent 之后
> 它就不成立了。完整重定义见[设计方案 15](../设计方案/15-执行器与agent-runtime重新定义.md)。

### 4.5 分支封闭集与池归属（三条容易踩塌的判断）

- **每条分支都必须有对应样本入库**——负样本不是副产品。反过来，
  `unresolved` / `trailer_suspect` / `player_unverified` **不是负样本**，混进池里会污染它。
- **并池是写入时的动作，不是读取时的推导**——新分支**不回填历史存档**；
  批次边界前后分布会跳变，不记批次元数据就会读成「质量变好了」。
- **贴标签前核前置事实**（`branches.BRANCH_PRECONDITION`）——分支名是结论的标签，
  而定义里带前提。前置事实不成立就降级为 `unresolved`。**这张表要短。**

**fail-closed 的准确含义**：能力不可用时返回 `answer=None`，**绝不猜**；
且 **`None` 不中断采集，只有 `False` 才中断**——它管的是「结论」不是「采集」。

### 4.6 校准回路（方案 16）：读数怎么才可信

**六桶封闭集**（`evaluation/calibration/buckets.py`）——分歧卡只能落这六个桶：
`evaluator_logic` · `evaluator_prompt` · `rubric_ambiguous` · `rubric_missing` ·
`gold_defect` · `evidence_missing`；`rubric_*` / `gold_*` 由 `HUMAN_ONLY_PREFIXES`
强制人填，**机器名签名被拒**。

**闭环形状**：`agreement` 出全量快照 + 分歧卡 → `worklist build` 出分诊表 →
人判桶并 `triage import` → `verify` 判两轮判据（退 0/1/2）→ `gate` 冻结时闸门。
分诊档是**唯一写入口**（`golden/data/triage/triage.jsonl`）。

**四条闸门判据**：净改善 / 类回归 / 回归集 / **同桶清零**。
**金标变动 = 新基线**（`gold_refresh.baseline_reset=true`）⇒ `gate` 退 2，不许拿新尺子比旧尺子。
