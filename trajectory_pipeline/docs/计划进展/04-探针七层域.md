# 04 · 探针七层域（阶段 4 · L0–L7）

**职责：** 不依赖 LLM 感知层的**独立事实探针链**——L0 静态可达性 →
L1 ffprobe 媒体解析 → L2 真浏览器媒体探针 → L3 规则层 → L4 VLM 复核 →
L5 仲裁 → L6 人工复核 → L7 回流。

**为什么单开一个域：** LLM 语义判断在真实数据上覆盖率不够
（见 [02-感知与判定域](02-感知与判定域.md) 的触发矩阵——4 新分支只命中 53%），
**prompt 工程不再是有效路径，工具才是**。七层全部实跑实证通过。

## L4 双实现：Protocol 不变，只换类

> ⚠️ **动 Protocol 之前先读这条**：`VLMReviewer` Protocol /
> `VLMReviewInput` / `VLMReviewResult` 三处契约**零修改**——
> 「加真视觉支持」是**换实现类，不是换接口**。任何改 Protocol 的提案
> 都要先在本文档 §七层状态总表「L4」行把当前行级描述存档再改。
> 见 [避坑指南](../02-避坑指南.md)。

`MultimVLMReviewer`（增量三十四）的四条设计纪律：

1. **协议先行**——`VLMReviewer` Protocol 不变，`_run_l4_review_async` 调用点
   零修改（除新增 `reviewer_name` 关键字参数）。
2. **fail-soft + 无 key 自动降级**——无 key / API 失败 / 响应坏 / label 不在白名单
   → 调 `HeuristicVLMReviewer` 兜底，**显式打 `source="multim_fallback"` +
   `note="multim_fallback:<reason>"` 标签**，让 L5 仲裁 / 人工一眼看出
   「这本是 multim 通道，结果走了 heuristic」。
3. **不重叠 L3 rule**——内部不读 L3 词典；`_SYSTEM_PROMPT` 明令
   「不要套用任何关键词规则表」。
4. **截图字段预留**——`VLMReviewResult.screenshots` 默认空 tuple 不动；
   等 obscura 暴露 `browser_take_screenshot` 后填路径，契约不变。

## L5 仲裁：四步走

`arbitrate(result)` 4 步走：

1. **fail-closed 短路**——凭据 / 超时 4 类 note 直接短路，不进判层
2. **L3 + L4 + L2 各自解析**（L1 作为第四伙伴自增量二十八接入）
3. **L2 真播放一票否决**——真浏览器确认能播就否决其他源
4. **N-of-M 加权**——三源同分支时仲裁直落；冲突按 `source_weight × confidence` 取 max

**fail-closed 跳过条件**（L1 / L3 / L4 / L5 共用）：
`credential_leak` / `driver_missing` / `timeout` / `driver_error`
4 个 note 不走判层，凭据闸门原子性。

**凭据闸门口径**（增量二十三修的）：从「`scan_credentials` 永远不抛 →
except 子句是死代码」改为「**hits 非空即 fail-closed**」，修复后 78 条 contract 守住。

### 根因(代码侧)

「同页守卫」的本意是**对 component_unverified 严防误判**——
`component_unverified` 是「已落地播放页但无法验证」的兜底,**强证据**
要求(有前序 click 才算)。但**对其他分支**也走同页守卫是**过度延伸**——
`subscribe_wall` / `login_required` / `blocked` / `partial_free` 是「落地即
结论」,与「点击前后是否变」**无关**。

更要害:**对 component_unverified**,「同页」应当只针对「应当跳到播放页
但没跳」的场景——即**「URL 是着陆页(列表/搜索结果)」 + 「点击后没变」**。
但当前实现**无条件**触发,导致本来在 player 落地页(`/play/` `/movie/` 等)
的请求也被降级。

10 行的真实情况:
- LLM False 的理由是「页面是图文文章」/「播放器加载异常」/「页面没
  媒体元素」/「页面是美食指南文章」——**都是「落地即结论」语义**
- 应当走 `not_play_site` / `success` / `subscription_wall` / `trailer_only` /
  `component_unverified`(本意),**不**该走 unresolved
- 但当前代码:LLM False → 题绑定 `component_unverified` → 「同页守卫」
  触发 → 报 `点击播放控件前后是同一个页面` → **降级为 unresolved**
- 结果:**金标分布跨度极大的 10 行**(3 success / 4 subscription_wall /
  2 not_play_site / 1 trailer_only)全被这条降级逻辑吃掉

**方案 X — 窄化同页守卫的适用范围**:

**方案 Z — LLM self-reported 门**:

```python
_LANDING_PATH_HINTS = (
    "/list", "/lists/", "/search", "/search?", "/search/",
    "/category/", "/channel/", "/index", "/index.",
    "/tag/", "/tags/", "/browse", "/discover",
    "/explore", "/library", "/results", "/all",
)
# 也可加 host 形态:google.com/search、bing.com/search、baidu.com/s
# 与列表域名 soku.youku.com / search.bilibili.com

def _looks_like_landing_page(url: str) -> bool:
    if not url:
        return False
    parsed = urlparse(url)
    path = parsed.path.lower() + ("?" + parsed.query.lower() if parsed.query else "")
    if any(h in path for h in _LANDING_PATH_HINTS):
        return True
    # host 形态(具体站)
    if "search." in (parsed.netloc or "").lower():
        return True
    return False
```
