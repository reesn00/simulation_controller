### 一 · H-31 · 熔断的语义是「**别再发**」，不是「再试一次」

`llm/client.py` 对 4xx **不重试**这个决策**是对的**（key 错了重发结果一样）
——缺的是「**别再发**」。all80 批次里 401 从 08:48:39 持续到收尾，
**170 次**空请求，每次都等一个超时 ⇒ 判分全程 fail-closed。

**处置分四层，缺一层就漏**：

1. **熔断器本体**（[`llm/client.py::CircuitBreaker`](../../llm/client.py)）：
   连续 N 次**不可重试的** 4xx ⇒ 熔断；阈值 **3**（env `TRAJECTORY_LLM_CIRCUIT_THRESHOLD`）。
   ⚠️ **408 / 429 不计入**——**限流不是坏了**（把 429 算进去 ⇒ 后端限流被误判成
   后端坏了 ⇒ 整批判分不可信，**判错的代价比多发几次请求大得多**）。
   ⚠️ 熔断打开后**不抛异常**：返回 `None` + `"circuit:open"`
   ⇒ 原样进 `llm_calls[].error` ⇒ 读档的人看得见「**不是判不了，是熔断了**」。
2. **批次级共享**（[`cli.py::_make_circuit_breaker`](../../executor/cli.py)）：
   ⚠️ **熔断器是独立对象、不是客户端的字段**——客户端是**每 task 一个**
   ⇒ all80 那 170 次 401 是**跨 6 条 task** 打空的 ⇒ 逐 task 计数拦不住。
   ⚠️ **升配后端用自己那个**：它是**另一台机器另一份凭据**，主后端 401
   不代表升配也坏了（塞进同一个 ⇒ 主后端一坏连升配一起掐死）。
3. **写入时隔离**（[`executor/archive.py`](../../executor/archive.py)）：
   P1 存档**照落**（那是**证据**，人工复核要看的就是它），但
   `judgement_trustworthy is False` ⇒ **不并负样本池**
   ——「并池是写入时的动作」⇒ 判据必须在**写入这一刻**读，
   等下游推导会随代码版本漂。
4. **组装侧两边都挡**（[`assembler/schema.py`](../../assembler/schema.py)
   + [`assembler/task_view.py`](../../assembler/task_view.py)）：
   P2 不出样本、T 不出训练视图 ⇒ **漏一边就有一边进池**。
   ⚠️ 判据用**「显式 False」**：历史存档没这个键 ⇒ 缺键 = 不知道 ≠ 不可信
   （**不回填历史存档**——并池是写入时的动作）。

**批次层可见性**：该条 `warnings` 里一句「**本条判分不可信**（判断点全程 fail-closed，
分支不是站点的性质）⇒ **不进负样本池、不进训练集**」；页脚打「判分不可信」段；
**退出码非 0**——⚠️ **不能悄悄 exit 0**：那 6 条结构完整、看着最像正常轨迹，
正是「exit 0 ⇒ 调用方以为成功」的受害面。

### 二 · H-32 · 降级本来就是**按块记**的，错在**消费侧一刀切**

`Observation.degraded` **每个元素就是一个内容块的降级标记**——它**本来就是按块记的**。
问题出在消费侧：

```python
if obs.degraded:
    return []      # ← 任何一块坏了 ⇒ 整页候选作废
```

⇒ **新增** [`executor/degraded.py`](../../executor/degraded.py)：五块
（`body` / `links` / `elements` / `nav` / `other`），**只做分类**——
不造标记、不改标记、不吞标记（真源仍是各驱动写进 `Observation.degraded` 的那个列表）。
⚠️ **未知标记归 `other`——不猜它属于哪一块**：猜「无害」会让它悄悄作废整批数据，
猜「致命」又会误杀 ⇒ 归 `other` = **不否决候选**，但**原样留在 `degraded` 里**。

**消费侧只被「链接那块」否决**（[`executor/steps/search.py`](../../executor/steps/search.py)）：
`blocks_candidate_extraction()` 只认 `links` ∪ `nav` ⇒ body 乱码 / 正文缺失 /
元素枚举失败**动不了从 links 提取的候选**（all80 那 13 条 0 候选空跑就是被这一刀砍的）。
⚠️ **记账留痕**：链接类致命否决仍记 `degraded` 键（旧键不动），非致命降级**新增**
`degraded_other` 键 ⇒ **少产出的那一段看得见**，不会读成「这批素材差」。

**乱码先重取再判**（[`executor/browser/camofox_driver.py`](../../executor/browser/camofox_driver.py)）：
⚠️ **`innerText` 是浏览器已经解码过的文本**——页面编码不对时它回来就是乱的；
而**同一页的 HTML 源码**可能仍带着正确的 `<meta charset>` 声明。
⇒ 判乱码前**先重取 HTML**，**取到可读正文就用它**且**不记降级**；
**重取后仍乱（或取不到）才记 `body_mojibake`** ⇒ **「判不出」与「没查过」是两件事**。
⚠️ **不乱时不重取**：多一次 evaluate 往返是纯浪费。

## 增量一百三十一 · **H-36 闭掉**：评估侧的 LLM 失败**既有归因、也有熔断** —— 后端故障不再被读成「这批数据判不出来」

> owner 指令：「总目标：梳理后修复问题，**不再跑所有 batch**」。
> 本期闭 **H-36**：**归因 + 批次级熔断 + 汇总分栏 + 上传/刷新闸门**。

### 一 · 病根不是「忘了写」，是**熔断器数错了东西**

客户端的 `CircuitBreaker` **只数 4xx**（`NON_TRIPPING_4XX = {408, 429}`）
⇒ 2026-11-11 那 **578** 次「后端答了但正文为空」**一次都没触发**
⇒ 整批安静跑完 74 分钟、**退出码 0**、汇总只报 `quarantine=838（91 %）`
⇒ **后端故障被读成数据质量**（处置方向正好相反：前者修后端，后者补数据）。

⚠️ **归因与熔断必须一起做**：只加熔断 ⇒ 下次故障变成「静默少判几条」；
只加归因 ⇒ 下次故障变成「停得早但没人知道停在哪」。

### 二 · 归因：错误码 → 分类 → **一句人话**

[`llm/client.py`](../../llm/client.py) 加 `classify_llm_failure()` /
`describe_llm_failure()`：**9 类**（熔断 / 预算耗尽 / 形状异常 / 请求被拒 4xx /
后端错误 5xx / 限流 429 / 超时 / 连接失败 / 认不出 ⇒ unknown **不猜**）。

⚠️ **错误码的形状由 `_exchange` 决定**（`circuit:open` / `budget:*` / `shape:*` /
`http:<status>` / `transport:<ExcType>`）⇒ **码表只有这一份**，下游只消费分类。
⚠️ **空错误码仍写「LLM 返回空」**（旧口径不漂）——「为什么返回空」由码本身说明。

### 三 · 词表挂**顶层**，不抄三份

新增 [`judgement_causes.py`](../../judgement_causes.py)：`CAUSE_SCORED` /
`CAUSE_DATA` / `CAUSE_LLM` / `CAUSE_NO_CLIENT` + `llm_unanswered()`。
⚠️ **为什么挂顶层**：`ls_bridge` 的 import 契约**禁** import `evaluation.scorers`
⇒ 同 [`projection.py`](../../projection.py) 的先例（挂顶层，两边都够得着）。
⚠️ **不许抄第二份**：归因词表抄两份必然漂（漂了的代价是「后端 500」与
「后端超时」在报告上长得一模一样）。

### 四 · 批次级熔断：停 **D-2**，不是停全部评分

连续 **N** 次 LLM 调用失败 ⇒ **停本批 D-2 调用** + 落 `scout_meta.json`
（`judgement_trustworthy=false`）+ stderr 横幅 + **退出码 1**。

⚠️ **D-4/D-5/D-6 是纯代码判据，照跑不误**——熔断的是裁判后端，不是全部评分。
⚠️ **客户端 4xx 熔断打开 ⇒ 直接开批次熔断**（不再发那 170 次 401）。
⚠️ **熔断后被跳过的单元不算「调用失败」**（压根没发请求）
⇒ `llm_failure_total` 回答的是「后端失败了几次」。
⚠️ **`--dry-run` 也熔断**——dry-run 发的是**真请求**。

### 五 · 汇总分栏（⚠️ **最要紧的一条**）

`quarantine` 拆成「**数据判不出**」/「**LLM 没答**」两栏
⇒ 报表上**一眼看出**是后端坏了还是素材缺件。
⚠️ **分栏计数不在「各桶相加 = 输入样本数」那个和里**（它是 `quarantine` 的**再分**，
不是第三档）⇒ `UNIT_COUNTER_KEYS` 单列一常量守住。

### 六 · 上传 / 刷新**闸门**：不可信的判分不许进人工队列

**不拿不可信的判分去盖 LS 上已有的好卡** ⇒
