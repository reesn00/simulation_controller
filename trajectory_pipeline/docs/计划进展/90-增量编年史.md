## 增量四十六（2026-10-15）· rationale「动作前动机」口径改造

### 起因

### 单档真跑（E005__e35b7455）与连带修掉的闸门缺陷

真跑 **7 单元 / 13 步 + 7 reflection = 20 次调用，written=13 / unavailable=0**。
因果链验证通过：site-4 step0（goto）从「当前页是…越剧特别版…虽列出 8 期链接」
变成「需要打开一个候选链接进行验证…**预期**进入后能判断…」——时序倒置消除。
7 条 reflection 全部 written，P3 收尾消息读 reflection 正常。

真跑暴露一个**旧口径下被掩盖的闸门缺陷**：site-4 step1 被判
`unsupported_entity`。查证是**误判**——模型把观察里各自出现的
「越剧特别版」「越剧特别季」合并写成「…越剧特别版/越剧特别季」，
而 quoted 实体是整串子串匹配，合成串必然落空。旧口径下本步观察为空、
实体核查早退，所以从没暴露过；新口径历史观察完整，核查真跑起来才撞上。

修法：`lexicon.split_composite` 按**并列分隔符**（`/ ／ | ｜ 、`）拆开，
`gates._in_haystack` 要求**每段都命中**才算有据；**不收逗号**——
「发生了错误，请稍后再试」是一句话不是两个并列实体。收紧方向不变：
少一段命中仍判幻觉。3 组测试 + 2 条变异（`all`→`any`、逗号进表）钉住。

**这条是全量重生成前必须先修的**：合成写法在中文 rationale 里是常态，
不修会让全量批次的 failed 率被系统性抬高、scout 分流整体偏移。


### D-9 侧连带修掉的两处（真跑探针撞出来的）

**（a）``_rationales`` / ``_actions`` 只认 ``Mapping`` → Sample 对象静默变空。**
``score_d9`` 签名写 ``Sample | Any``，但 ``Sample.rationales`` 是 ``Rationale``
dataclass 元组、``Sample.actions`` 是 ``ActionView`` 元组，都不是 Mapping，
于是被**静默过滤成空**：不抛异常、不出 ``undetermined``，judge 在没有原文
的情况下照常出分。实测探针出 ``vague``，evidence 写着「未提供 rationale
原文」——那句话是 judge 在如实说它没东西可判。
生产路径（``evaluation/cli.py`` 喂 P2 dict）绕开了这个坑，所以此前没暴露。
修法：新增 ``_as_mappings``，dataclass 走它的 ``to_json()``。

**（b）``_render_observation`` 不渲染 ``page_title`` → 可见性口径与闸门不一致。**
闸门 haystack（``lexicon.resettable_text``）是 url / title / body / 元素 label /
链接**五项**全并，judge 侧只有 url + body 两项。同一个「当时能看到什么」
的问题两边拿着两个答案：judge 会把**标题里明写**的东西判成「当时看不到」，
系统性高估后见之明，把好 rationale 判进负样本池。实测那一条：judge 说
step0 里没有「…第一期：」，而它就在 ``obs[0]['page_title']`` 里。
修法：渲染补 title（空则不渲染该字段）。

修完重跑同一条探针：判据从「未提供 rationale 原文 → vague/4」变成
**引用具体文本的 hindsight/3**——judge 抓到 step2 把本步动作的 ``target``
label 说成「正文里出现」，而纯代码闸门漏了它（没加引号，lexicon 抽不出）。
这正是 gate + judge 分层的价值。

## 增量五十 · LLM 多轮入口 chat_messages（A2a-1，INC50，2026-10-17）

方案 13 §3.5（A2a-1）落地：agent 循环要「按步喂对话历史 + 拿 token 账本」，
而 `llm/client.py` 的 `chat` 是**单轮两消息**形态（system+user 固定）、
且 `_content_of` 把 `usage` 整体丢弃。新增 `chat_messages` 多轮入口，
**`chat` 的外部契约一字不动**（十一道判断题 + FakeLLM + 全部感知层测试
零改动）。

### 一个请求循环，两个入口

`chat` 的请求段抽到私有 `_exchange(messages, max_tokens) -> (content, usage, error)`，
`chat` 与 `chat_messages` 共用它。抽的理由不是省几行，而是**重试与失败
分类必须只有一个副本**：分叉的后果是「某一类失败只在其中一条路径上被
正确处理」，那要等真实后端出状况才暴露，代价是一次批次。

`chat` 因此成了薄壳（组装两条消息 + 取 `content`），且保留原语义——
`last_error` **只在失败时写**，成功后不清除（diag 路径依赖「上一次失败的
原因」这个语义），并由测试 `test_成功后last_error不清空` 钉住。

### 三个刻意的设计

| 设计 | 理由 |
|---|---|
| `messages` **原样透传**（OpenAI 形态 `{role, content}`），客户端不合并 system、不裁剪历史 | 加工了就会让「模型实际看到什么」有**两份真相**；裁剪是 agent_loop 的事（步数预算的下游） |
| **不加 `tools` / `tool_choice`** | D-B1 拍板 JSON 动作指令走文本通道；加上去等于把半个原生 tool_calls 协议引进来，而 P3 视图是从 Action 渲染的，两套形状会打架 |
| `usage` **只认 `int`**（显式排除 `bool`），取不到返回 `None` 而**不补 0** | 账本上「0」与「后端没给」是两个事实——补零后「这批没记到 token」会看起来像「这批一个 token 没花」，成本对比先错在**分母**上且不报任何警 |

`total_tokens` 刻意不取（可由两者相加得到，记下来就多一份要同步的东西）。

`ChatResult` 是 frozen dataclass：`content` / `usage` / `latency_ms` / `error`，
`error` 与 `last_error` 同格式（`transport:` / `http:` / `shape:` / `budget:`），
**空串 = 成功**。⚠️ 契约要点写进 docstring：`content is None` 在 agent 循环里
不能被当成「模型说放弃」——「没作答」（要重试引导）与「答了放弃」（收口
unresolved）是两种事实。

### FakeLLM 侧

`chat` 的题号 dispatch + 坏行为开关抽到 `_respond(user) -> (原文, 错误码)`，
`chat_messages` 与 `chat` 共用——**开关表是 fake 的价值所在，它必须两个
入口都生效**（分叉的后果是「某个开关只在单轮形态下生效」）。
`chat_messages` 取**首条 system + 末条 user** 记账，`usage` 默认给固定值
（真后端会回 token 计数），`no_usage=True` 模拟「后端没给」。
（`FakeAgentLLM` 是 A2a-5 的活，A2a-1 只补同签名方法。）

### 「没作答」与「答错了」分两条路（A2a-1 留下的契约提醒）

| 事实 | 处置 | 理由 |
|---|---|---|
| 后端没作答（`content is None`） | **直接收口，不重试、不升配** | 那是运维问题——client 内部已重试过；升配更是南辕北辙（更强的模型也连不上同一个挂掉的端点） |
| 模型答了但不合契约 | 注入契约原文 → **重试一次** | 这是**能教**的 |
| 说「找不到」 | `gave_up` → `unresolved` | 三支「没判出来」分立的纪律 |

第三轮重试的准入条件只有一个：**刚升配过**（`_MAX_ATTEMPTS=3`，
`_maybe_escalate` 返回 True 才 continue）。升配每个候选只发生一次
（`_escalated`），且 `escalate=None` 时只落事件——**升配是能力不是依赖**。

### 拦截的两条次序纪律

1. **拦截只在新观察到达时触发**，不在每轮循环开始时触发——同一份观察被拦
   两次会让「格式纠正重试」意外吃满 `_GUIDANCE_LIMIT`，模型还没来得及换路
   就被判成二次拦截收口；
2. **BLOCKED_CF / CAPTCHA 一次性收口，不给引导机会**——agent 没有登录态也
   没有指纹可换，引导只会烧一次 llm_call 然后得到一句「我换不了」。
   LOGIN_WALL / PAYWALL / DEAD_LOOP 才是「换路有机会」的那三类。

### 刻意不做的两件事

- **循环内不拦 goto URL**（纪律写进 prompt，A3-2 批次级溯源断言负责）——
  与 D-2 的样本级口径分开放，两个信号不混；
- **失败的两条路径都不消耗步数**（步数记的是「走到的页面数」）——给 agent
  换路的机会，但那机会由 llm_calls 预算兜底，不让「点了三次都点不动」吃光
  整个步数预算。

### 四个刻意的设计

1. **PLAYER_OK 判在「agent 看到的那一份观察」上**（`AgentOutcome.final_obs`）。
   循环外再取一次快照，判的就是另一份快照了——播放器会自转、广告会轮换，
   而 D-2/D-5 判的正是观察正文。**判据与决策依据分叉**是最难查的一类不一致。
   附带收益：省掉一次浏览器往返。
2. **落地即在播放页的保守降级**。深层链接候选中 agent 一步没走就报「到了」，
   于是 `pre_obs == player_obs`，守卫会把 PLAYER_OK=False 的记账从
   `component_unverified` 降级为 `unresolved`。这是**刻意的**——agent 说「到了」
   是自报，未经跨页证实；拿自报的前提贴负标签等于把「模型没找到」写成
   「这里看不了」。丢一个负样本，好过产一条假负样本。
3. **`executor_mode` 在构造期定下，分派只有一处**（`_visit_guarded`）。模式是
   批次级属性，逐候选判断会让「这条轨迹是谁产的」变成逐条才能回答的问题。
   有用例数着源码里 `self._mode ==` 的出现次数（=1）。
4. **要 agent 而没后端 → 当场报错，不静默退回 scripted**。退回的那一批在
   存档上写的是 `executor_mode="scripted"`，于是「agent 批失败了 40%」会被
   读成「scripted 跑得好好的」——**配置错误伪装成一次成功的灰度**：不报错、
   不空转，报表还挺好看。与 `--perceptor llm` 未配后端报错同款口径。

### 三条已知口径（留给 A3）

- **共用 `per_site_timeout_s`**：一个候选最多 12 次 llm_call，90s 默认值会被
  走得满的候选撞到。超时即 `unresolved`，与 scripted 同形；要单列改一处。
- **agent 模式不跑 `IS_REACHABLE`**：页面级「能不能看」由 gatekeeper 逐步
  拦截（LOGIN_WALL → `login_required` 等），比那道题更早也更硬。
- **A2a-3 不接 `llm_calls` 账本**（§3.6）：`RunRecord.llm_calls` 属 A2a-4，
  现在传 `None` = 丢弃。先接一半的账本会在报表上假装这批成本可查。

## INC54 · A2a-4：llm_calls[] 账本 + ESCALATE 升配后端（方案 13 §3.5 G2 / §3.6）

**日期**：2026-10-17

+ orchestrator 两处接线 + 候选收口统一盖 `ts`。
**依赖**：INC50（`chat_messages` 的 usage/latency 回传）、INC52（两处
`llm_calls=None` 预留接口）、INC53（中间页链接线点）。

### 一句话

A2a 的「最小账本」闭环：agent 循环每次问模型落一行进 P1
（`{ts, caller, candidate, model, latency_ms, prompt_tokens,
completion_tokens, error}`），升配后端从「文档里的三个环境变量」变成
真实可配的第二条 client。

### 三个落地决定（两处有文档依据，一处是新的）

| 决定 | 理由 |
|---|---|
| `ts` 盖在**候选访问收口时**（orchestrator `_stamp_llm_calls`），粒度候选级——同候选各条共享一戳 | 循环体不引入时间源是 INC51 已记的纪律；候选内次序由 list 顺序保证、单条耗时由 `latency_ms` 给出，ts 要回答的只是「这批成本是哪段时间烧的」。超时/异常收口的候选带没盖戳的残条落盘是**诚实残账**，不补假戳 |
| 升配**半配 = 报错**（有 BASE_URL 没 MODEL 或反之，光给 KEY 也算），全没配 = `None` | 主后端「缺件即报错，不猜」纪律的降档版：升配是能力不是依赖，全没配不 fail；但半配说明**想配没配齐**，静默当无升配处理，那一半配置就成了没人读的尸体——想升配的人看到「升配没生效」时不会去查「是不是只配了一半」 |
| 升配 config **继承主后端的 `timeout_s` / `max_tokens`** | 升配接的是同一类请求（agent 指令 + 推理模型的思考预算），主后端上校准过的输出预算原样带过去。继承的是「已校准值」而非类默认值——升配通常是远端大模型，预算被默认值悄悄放大/缩小的代价都是真金白银 |

## INC58 · A3-3：D-2/5/6 守卫 + D-9 判据修订落地（INC58）

**日期**：2026-10-17
**范围**：agent 批 D-9 断链修复（think → P1 rationale 槽位）、D-2/D-5 守卫、

**依赖**：INC51-53（agent_loop / 真链 fixture）、INC57（守卫复用其端到端姿势）、

### 一句话

「D-9 纳入 A3 验收」从拍板变成可执行：复核发现 agent_loop 此前**不落任何
rationale**——think 只活在对话历史与 `AgentOutcome.transcript`（都不进 P1），
agent 样本切出来 `rationales=()` → 闸门 `not_run` → D-9 永不触发，拍板会
落空成永远缺分的维度。本刀把 think 装进 P1 `steps[i].rationale` 槽位，
全链（P1 → P2 → 闸门 → D-9 触发）用守卫钉死。

### 断链修复的三个落地决定

| 决定 | 理由 |
|---|---|
| 挂接点在 `_execute` 的 `act()` 后、**成败两条路都挂** | think 是动作前动机，与执行结果无关——「点了但点不动」那一步的动机恰是 D-9 最该看的原文；挂在执行成功路径上会丢掉失败步的判据 |
| 空 think 不挂（rationale 保持 `None`） | 「没说话」与「说了但没落」不混——`align_rationales` 的缺件语义就是稀疏序列 |
| payload `reason="native-think"` | writer 成功时 `reason=""`，两值不冲突；「这条 rationale 是原生 think 还是 writer 产物」在 P1 里有了机器可读标记——同分不同质核对的刻痕，也是 A/B 报表按来源分桶的数据源 |

### 判据层零改动的复核结论（守卫即证据）

- **gates 不需要动**：时序/实体/因果三查吃的是 P2 形状，A2a 的同形纪律让
  agent 形状天然兼容。实测：引用后续步才出现的实体的 think 被
  `temporal_leak` 抓出（hard → failed → D-9 强制走 LLM，judge prompt 里
  带 think 原文）；干净 think 走成本控制口径与 scripted 完全一致
  （passed + 无可判短板 → not_evaluated，不烧 LLM）。
- **首步早退不误伤**：agent 链首条 rationale 步的可见窗口里有进站观察
  （site 链 index 2 窗口=[site_obs, 缺件占位]；中间页链 index 1 窗口=
  [agg obs]——`probe_and_observe`/`enter_site` 都落 goto+观察步）。窗口
  真空的 step 0 早退照走（防御钉）。
- **`check_boilerplate` 的 ≤20 字规则对 think 不对称**（think 是设计出来的
  短句）：只产生 soft finding，不进 GateMark、不改状态，下游零影响——
  **记录不修改**；rubric 若未来把 think 长度纳入锚点再修订。

fixture 两链都钉 `outcome.url == play_url` 且 `outcome_missing` 消失。

"outcome_missing" in ...` 那行），测试红在第一格——**读测试文件要看全
再改**，这次是 grep -C 比 Read 截断更可靠。
