### 1.2 为什么三条捷径都不行（省得白跑）

| 捷径 | 为什么不成立 |
|---|---|
| `agreement --version 7` 重跑 | 读的就是 v7 那批旧分数，结果一模一样；而且会**静默覆盖** `output/pipeline/calibration/v7/snapshot.json`（`write_snapshot` 无覆盖守卫），把历史那份盖成今天的 `evaluator_version` |
| `freeze --version 8 --from-version 7` | 继承式冻结的设计就是「**行内容不动**」——旧分数一起带过来，v8 的 d5 仍然全是 5 |
| 不带 `--from-version` 的 `freeze --version 8` | 重新洗牌切分（`_stratified_split`），回归集/持有集全变，「v7 与 v8 逐行可比」当场没了，C-17 的门禁自证为空 |

⇒ 必须补一个能力：**继承切分、但把 pred 侧按当前代码重算**。

### 1.3 要做的事

#### S1 · `overlay-scout`：弃权的维度写 `null`，不要删键

`trajectory_pipeline/evaluation/golden/builder.py` `cmd_overlay_scout`（约 1710–1732 行）。

现在：`score is None` 的维度**不进 dict**（原注释的理由是「避免下游读成 0 分」）。后果是
快照里「评分器弃权」与「压根没测」**都表现为条目消失**——v8 的 d5 会只剩 185 条，
104 行（弃权 26 + 无样本 78）**无声消失**，而那正是这次要审计的东西。

改成：**只要有样本，四维键齐全，值可为 `null`**；没有样本（`status=missing_sample`）才留 `{}`。
`status` 语义不动（`scored` = 有样本、`missing_sample` = 没样本、`negative_pool_no_sample`）。
`_report_overlay` 的分布打印要能显示 `{None: 31, 5: 218, 2: 8}`。

- 测试：**`overlay-scout` 现在零测试**（`grep -rn overlay trajectory_pipeline/tests` 为空）。
  新建 `tests/unit/test_golden_overlay.py`：①弃权写 null、②无样本写 `{}`、
  ③`code.branch`/`golden`/`retest` 一格不动、④`status` 三态各就各位。
- 下游已核对：`dim_agreement(None, p)` 返回 `None`（不计入分母）、
  `_compute_soft_dim_agreement` 里 `p is None → skipped_no_pred`——**都吃 null，不用改**。

#### S2 · `freeze --refresh-scores`：继承切分，重挂 pred

`cmd_freeze` 的 `carrying` 分支（约 866–960 行）+ parser（约 1869–1905 行）。

语义：`--from-version N --refresh-scores` 时，切分与行内容仍原样继承，但每行按 `golden_id`
从 `candidates.jsonl` 取回 `dimension_scores` / `scores_detail` / `status` 三个字段覆盖上去。
**`golden` 与 `code` 一个字不动**（金标与分支结论不归这条路管）。

- **缺 id 就退 2**（`GoldenError` 列出所有缺失的 `golden_id`），绝不「找不到就留着旧分数」。
- manifest 新增 `score_refresh`：`{"enabled": true, "source": "candidates.jsonl",
  "rows_matched": N, "rows_missing": 0, "per_dim": {"d5": {"before": {...}, "after": {...}},
  "tally": {"d5": {"scored": 185, "abstain": 26, "no_sample": 78}}}}`。
  `before/after` 是逐维分布（`Counter` 排序后落盘），`tally` 是三态计数——**审计要看的就是这两个**。
- `--from-version` 的 help 现在写「给了它就**不读** candidates/annotations」，加 `--refresh-scores`
  后是半真：**改 help 写成「切分不读；给了 `--refresh-scores` 时只读 candidates 的评分字段」**。
- 回归集指纹：`_rows_fingerprint(reg)` 在 v8 上按**新内容**重算（刷新后与 v7 不同是预期的；
  守卫是「同一版 manifest 与同一版行一致」，不自相矛盾）。
- 测试（`tests/unit/test_golden_three_split.py` 已有「行原样带过来」一组，加两条）：
  ①给了 `--refresh-scores` 后分数变了、切分与 `golden`/`code` 不变、`regression_fingerprint` 变了
  且与文件内容一致；②候选里少一个 id ⇒ 退 2 且**没写出任何文件**。

### 2.2 谁做哪一半

| | 机器（agent 可做） | 人（agent 不可代劳） |
|---|---|---|
| 做什么 | 把**事实**摆齐：每个 URL 上的金标分布/档位/`reviewed_by`+`reviewed_at`/`golden.note`、每行的 `code.source`、`reached_play_page`、`fallback_used`、样本在不在盘上；以及跨档泄漏的条数 | 19 个 URL 逐个**定性**：站点漂移可解释 / 同一页面不可能共存 / 待查；以及"该改成哪个标签" |
| 判据 | 只做计数、只搬事实 | 「同一页面不可能同时成立」是**语义判断**，不做投票、不做多数表决（纪律：分歧必须暴露给人看） |

⚠️ 一个容易走偏的地方：**「URL 级冲突」不等于「金标错」**。同一个 URL 两次访问一次
`success` 一次 `unresolved` 是**真事实**（站点漂移、地区、登录态）。所以连
`not_play_site` vs `unreachable_hard` 这种看着"不可能"的组合，也可能是「t1 打不开、t2 打开
且判定不是播放站」——**要么有证据，要么写「待查」，不许用排除法断言**。
