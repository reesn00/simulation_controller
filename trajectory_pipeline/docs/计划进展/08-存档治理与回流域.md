# 08 · 存档治理与回流域

**职责：** 存档自己分不出、靠门禁或人工裁定的那一类问题——负样本池并池、
跨存档矛盾、三档严重度门禁、`quarantine.jsonl` 冻结、复核队列、L7 LS 双向桥。
落点是 [`executor/integrity.py`](../../executor/integrity.py)、
[`executor/review_queue.py`](../../executor/review_queue.py)、
[`evaluation/ls_bridge/`](../../evaluation/ls_bridge/)。

**核心纪律：** **`check-archives` 挡住「池记负样本、存档判成功」这种分叉
的机制必须一直在**。守卫只能加豁免（fail-open 跳过），不能删。

### 2026-10-26 · 「出池」这条路：三个口径被写反了，顺带查出一个漏扫 bug（H-17）

台账 H-17 从 2026-10-21 起写的是「这 7 条要**转正**回正样本池，而**那条路不存在**」。
逐条核过之后，三句都不成立——**每个错法都会把人引到不同的错动作上**：

| 原写法 | 核出来的事实 | 会把人导去哪儿 |
|---|---|---|
| 「**池里** 7 条」 | 那 7 条在 `output/pipeline/dualrun{,2}/camoufox/negative.jsonl`（`DR01`–`DR03` 双跑批的**批内池**；⚠️ 那是 **2026-10-21 camoufox 执行层**留下的历史目录名，**现行批次的批内池在 `dualrun{,2}/camofox/`**），**生产池 `negative.jsonl` 一条都没有** | 去生产池里找，找不到 |
| 「要**转正**」 | 这 7 份存档**没有任何成功证据**（`reached_play_page=False` · `visits[].success=False` · evidence 写「点击失败 / 同一页面」）⇒ 改 `branch=None` 得到**假正样本** | 手改 `branch`：改一半被 `success_branch_mismatch` 抓住，全改就是**伪造采集事实**（`downgrade` 坑 4） |
| 「**无路**」 | 路是两个动作：`downgrade`（存档落 `unresolved`）+ `pool-drop`（撤池行）。**07 手册 §6.1 的分工表里本来就写着这一对**，而同一份文档 §2.7 说「无路」 | 两份矛盾的说法之间随便挑一个，或者干脆不动 |

**要一条真正的正样本，只能重跑那条 URL**（现场重采到播放页）——存档里没有的东西，改标签变不出来。

★**顺带查出的漏扫 bug**：`executor/downgrade.py::apply_to_root` 的遍历原先写的是
`root.glob("T*__*.json")`——**只认 `T` 前缀**。实测生产根目录 78 份存档里
**28 份是 `E`/`P` 前缀**（`E005__e35b7455.json` 这类），双跑那批判全是 `DR01__`
⇒ **这 7 条根本没有命令能碰**，而 CLI 那层打印的是
「没有匹配的 outcome —— 归档可能已被降过（幂等），或判据不匹配」：
**判据被冤枉**，读的人会去改判据，改不好的。
现改为走 `archive.select_archives`（「什么算一份存档」全仓库只有一处），
只额外把它折回**原档**（降级不动 `.reviewed.json`，坑 1）。
真数据 dry-run 实证 `E005__e35b7455.json` 已可见。

门禁：`tests/unit/test_downgrade.py::Test目录遍历` 加 2 条（非 `T` 前缀 / 同目录探针取证不算存档）；
`tests/contract/test_pool_exit_sequence.py` 5 条（出池两步走完门禁零发现 · 顺序颠倒在门口被抓 ·
撤行留痕 · 「转正≠改 branch」两个方向）。

## INC37 · 199 条验证器自动裁决（2026-10-14）

**背景**：仓库根 xlsx 工作单有 199 行 `review_label` 空。增量三十六初判
「真待人工产能，**不可脚本化**」——**该判断需要修正**。

> 项目自增量二十八起逐步增加 L0–L5 七层验证器 + L3 规则仲裁 + L4
> `HeuristicVLMReviewer`，**目的之一**就是「人工标注数据过百后，效率极低
> 耗时长」时切换到验证器自动裁决。
> **不是「人海战术扛 199 条」，而是「验证器扛大头，人只看低可信子集」**。

### 验证器四路裁决

| 裁决 | 触发条件 | 含义 |
|---|---|---|
| `confirmed` | L4 输出 branch 且 conf ≥ 0.85 **且** branch 与现 label 一致 | 强一致，无需人工 |
| `weak_confirmed` | L4 conf ≥ 0.65 与 label 一致 **或** L3 规则 conf ≥ 0.85 与 label 一致 | 中度一致，AI 占大头 |
| `flagged_mismatch` | L4 或 L3 输出 branch **与** label 不一致 | 验证器对现 label 有异议，**留人工** |
| `no_text_signal` | L4 与 L3 都没产出可仲裁的 branch | 验证器沉默，label 保留为「无信号」基线 |

裁决优先级按表中顺序短路。裁决函数落在
[`executor/arbitration.py`](../../executor/arbitration.py)（`L4_LABEL_TO_BRANCH` /
`L3_ACCESS_KIND_TO_BRANCH` / `L3_PAYWALL_TYPE_TO_BRANCH` 等），
规则感知器 [`perception/rule_perceptor.py`](../../perception/rule_perceptor.py)，
L4 启发式 VLM 评审 [`executor/review/vlm_reviewer.py`](../../executor/review/vlm_reviewer.py)。

**分布**：2 / 9 / 30 / 153（详见
[07-评估与黄金集域 §黄金集标注来源分层](07-评估与黄金集域.md#黄金集标注来源分层29412-行)）。

### note 形态

每条被处理行的 `note` 形如：

```text
INC37_NOTE: flagged_mismatch; L4[paywall(0.85) -> subscription_wall]; L3[partial_free(0.85)]
```

flagged 行一定带 `INC37_NOTE: flagged_mismatch` 关键词（用于后续人工
复核触发器识别）；其他 verdict 也带，便于 grep 审计整批 199。
