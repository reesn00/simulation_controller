⚠ **LS 上传的桶分布标签**（风险 1，Phase 6 加注）：
trajectory 主路径下的「positive / negative / quarantine」是 **per-Run 任务数**

### 评估（**另一个入口，不挂 `executor.cli`**）

```powershell
uv run python -m trajectory_pipeline.evaluation.cli                       # D-2/D-4/D-5/D-6 汇总
uv run python -m trajectory_pipeline.evaluation.cli --only-undetermined   # 只列不可判定/扣分的样本
uv run python -m trajectory_pipeline.evaluation.cli --json out.json       # 落全量 JSON
uv run python -m trajectory_pipeline.evaluation.goto_trace                # 批次级 goto 溯源（A3-2）
```

`goto_trace`（方案 13 §6.2）：核每个 `origin=model` 的 goto 的 `params.url`
是否可溯源（候选池 ∪ 已观察链接，锚点随轨迹递推），产出**批次级**幻觉
goto 计数/明细并按 `executor_mode` 分桶——agent 批的幻觉计数从
`[agent]` 行读。不进 D-2 样本级（幻觉记账决策 A），有违规**不非零退出**：
这是 A/B 对比要收集的质量信号，不是闸门。

| 参数 | 作用 |
|---|---|
| `--out` | P1 存档目录（默认 `output/pipeline`，**优先取 `.reviewed.json`**） |
| `--dimension` | 逗号分隔，默认 `d2,d4,d5,d6`。**D-3 未建**（判据依赖黄金集） |
| `--per-sample` / `--only-undetermined` | 逐条明细 / 只列有问题的 |
| `--json` | 落全量结果 |

⚠️ **看汇总先看「缺件分布」，分档只当线索**。各档都进总分母，
分档不改变任何数字，它只用来定位差异来源。

报表因此分两段读：

| 段 | 是什么 | 能怎么用 |
|---|---|---|
| **分档** | **推断**（缺件代理切出来的） | 指向差异可能在哪，不能当结论 |
| **缺件分布** | **事实**（P1 里压根没这个键） | 直接回答「哪些不可判定是采集缺件造成的」 |

⚠️ **代理警告在混合档下照样会打**。判据是「只要有任一条 `schema_version`
为空」，**不是**「整批都没版本号」——新存档落盘那一刻会变成混合档，
恰恰是最该警告的状态；按 basis 字符串判断会让警告自动消失。

分档判据本身是**两级**：优先按 P1 的 `schema_version`（写入时记的格式
版本），没这个键的存档退回 `run_config` 缺件**代理**。**不回填历史
存档**——没有依据断定一份没版本号的存档是哪一批。档名按判据起
（`未标版本·缺 run_config` / `未标版本`），**不写「旧批次 / 当前批次」**：
那是在替没有版本号的存档断言新旧。

> 实测数字不进本手册——数据一批一换，写死在这里的数必然作废。要数字
> 就跑 `evaluation.cli` 当场取。

### scripted / agent A/B 双跑（五指标验收，2026-10-18 A3-4）

两批用**同一份执行计划**（输入一致是 A/B 的前提），落盘分开目录：

```powershell
# 0) 采样一份计划（与模式无关，两批共用）
#    当批真用的那份已归档在 trajectory_pipeline/research/ab_baseline/plan-ab.json
uv run python -m trajectory_pipeline.executor.cli gen -n 40 --seed 42 --out plan-ab.json

# 1) scripted 批（默认模式，参数可省）
uv run python -m trajectory_pipeline.executor.cli run --plan plan-ab.json --task-id AB-S --out output/ab/scripted

# 2) agent 批（需配齐 TRAJECTORY_LLM_*；升配可选，见环境变量表）
uv run python -m trajectory_pipeline.executor.cli run --plan plan-ab.json --task-id AB-A --out output/ab/agent --executor-mode agent
```

五指标读法（**分别跑、分别算，两批目录就是两个 `--out`**）：

| # | 指标 | 命令 / 数据源 | 通过线 |
|---|---|---|---|
| ① | D10 等价类一致率（主口径） | `uv run python -m trajectory_pipeline.evaluation.golden.builder agreement --version N`（黄金集冻结版对照，两批各算一次）。**头条分母 = 调参池**（v7 起 128 条；回归集与持有集旁置），同一条命令还会打印「旧口径（三档合计）」，跨版本对比看那一行。加 `--emit-disagreements` 可同时派生全量快照 + 分歧卡（方案 16 C-15 / C-02，见[下方](#emit-disagreements-派生校准产物)） | agent 批不降（上岗线 0.90 不变） |
| ② | D-2/D-5/D-6/D-9 得分不降 | `uv run python -m trajectory_pipeline.evaluation.cli --out output/ab/<批> --include-llm-judge --json <批>.json` | 四个维度分别不降；D-9 随 2026-10-17 拍板纳入（§6.4 决策记录） |
| ③ | agent 步数预算内完成率 | 存档 `outcomes[].reached_play_page` 命中比例；未完成候选由 agent_loop 预算（max_steps=8）截断，表现为 unresolved/预算类分支 | 与 ④ 合读——「没到播放页」要分得清是站点失败还是预算烧完 |
| ④ | unresolved 簇占比 | 存档顶层 `outcomes[].branch == "unresolved"` 占比，按模式分桶（对照方案 12 §3 的两类主张：body 反爬降级、JS-heavy 失败） | agent 批不升（核心主张恰是它该降） |
| ⑤ | 幻觉 goto 计数 | `uv run python -m trajectory_pipeline.evaluation.goto_trace --out output/ab/agent`，读 `[agent]` 行 | 批次级信号，**不进 D-2 样本级**（幻觉记账决策 A），有计数不非零退出 |

三条必须随批记录的口径：

- **D-9 走 CLI 是快路径**（`gate_result=None → sample.gate.status`）；要 d9/gates 的 detailed 判据（temporal_leak 之类）得显式调 `gates.gate()`——那是给 A3-3 判据修订验收用的，成本约 +200% 跑时代码，不进常规批次报表；
- **站点时变**：两批尽量同时段跑；间隔超过一天以上时，④ 的对比结论要带时差保留——「agent 修好了 unresolved」与「站点刚好能爬了」在单次对比里分不开；
- **单元全绿 ≠ 批次达标**（方案 13 §6.6）：门禁记账与批次验收分开记，prompt 调优 × 站点时变是两端最大的不可控项，A/B 重跑取分布不取单点。

同一次双跑还顺手收口 **A1 遗留**两项（方案 13 §6.6）：①判断准确率 A/B 对比、golden alignment ROUTED 口径复核。

### ★ `run` 的执行层与时限参数（2026-10-26 切 camofox 后）

```powershell
uv run python -m trajectory_pipeline.executor.cli run --task-id T001 --title 功夫
uv run python -m trajectory_pipeline.executor.cli run --task-id T001 --title 功夫 --driver obscura   # 回溯路径
uv run python -m trajectory_pipeline.executor.cli run --plan plan.json --per-site-timeout 240
```

| 参数 | 作用 | 缺省 |
|---|---|---|
| `--driver {obscura,camofox}` | 执行层实现。obscura = **整批一条 MCP 连接**（行为不变，回溯路径）；camofox = **一个 Run 一次 MCP 会话**（身份/指纹随 Run 重建） | `camofox`（`driver_factory.DEFAULT_KIND`） |
| `--headful` | **已作废**（2026-10-26）——camofox 的浏览器由**上游 REST 服务**持有，有头/无头**不由本仓库决定**。传了会**当场报错退出 2**（不是静默忽略） | — |
| `--element-basis` | 采**跨面可比的元素账目**，落进存档的 `element_basis` 列 | 关 |
| `--per-site-timeout <秒>` | 单站超时。**它落进 `run_config`**——B-4（异常处置）唯一的时限判据 | `180` |

⚠️ **单站超时从 90 抬到 180 的理由**（**不做这件事的后果比做它更贵**）：
90 是 **obscura 时代**的数。camoufox 单次点击实测上界 **13.3s**（真人鼠标
轨迹回放），8 步 ≈ **122s** ⇒ 90s **必然触顶**。而触顶**不是「超时」这么轻**：
它会被记成 `unreachable_hard`——**一条理由通顺的假负样本**。假负样本进了池，
模型学到的就是「这类站点了不得」，而真相是「我们没等够」。
⚠️ **这是 camoufox 那支的实测结论，camofox 的延迟特性还没量过** ⇒
**180 是保守值，不是标定值**；等 camofox 那批真跑完，**要按实测重标**
（[设计方案 21 §R3](设计方案/21-camofox-browser执行层接入方案.md#r3-面与声明)）。

⚠️ **非正数即报错**（`--per-site-timeout 0` 会被 argparse 挡下）：0 的业务含义
是「立刻超时」，那会产出一批**看起来正常的空批**——有产出、有存档、只是产出
全是空的。

⚠️ **两种执行层的产出物**结构一样但**口径不同**（元素键名与词表都随面变），
**不能混池**。存档的 `driver` 字段是工具面的唯一来源（`{tag,label}` vs
`{role,name}`）——训练侧的声明按它折算。

### scout 工作流（rubric 评分门禁）

主流程的轨迹在进黄金集之前要先过一次 rubric 评分门禁 —— 不然黄金集里
混进一批没跑过评分的「裸轨迹」，后面那些百分比根本靠不住。完整链路：

    scout run → scout aggregate → from-scout → annotate → freeze → agreement

`scout run` 跑四维评分（D-2/D-4/D-5/D-6），输出三件套（positive / negative
/ quarantine）；`aggregate` 把三件套聚成 per-Run 的
`trajectory_candidates.jsonl`（D14.5 主路径，给 LS 上传用）；`from-scout`
把三件套投影成黄金集候选；剩下的 annotate / freeze / agreement 是已有命令。
详细设计见 [09-rubric-gate改造方案v04-实施细节.md](设计方案/09-rubric-gate改造方案v04-实施细节.md)，
本节只给命令。

```powershell
# 1) 跑 scout：四维评分，落三件套 + scout.jsonl + --stats
uv run python -m trajectory_pipeline.evaluation.scout.cli run `
    --p2-root output/pipeline `
    --out output/scout/v1 `
    --mediabrowse-dir output/pipeline/mediabrowse `
    --stats

# 2) per-Run 聚合（D14.5 主路径；**默认不覆盖**）
uv run python -m trajectory_pipeline.evaluation.scout.cli aggregate `
    --scout-dir output/scout/v1

# 3) 产物体检（只读：jsonl / stats / T 视图 三者一致性；error 返 1，warning 返 0）
uv run python -m trajectory_pipeline.evaluation.scout.cli verify `
    --scout-dir output/scout/v1

# 4) 把 scout 产物投影成黄金集候选（quarantine 不进）
uv run python -m trajectory_pipeline.evaluation.golden.builder from-scout `
    --scout-dir output/scout/v1
```

`freeze` 的三档切分参数：

| 参数 | 作用 |
|---|---|
| `--from-version N` | **继承式重冻结**：把 vN 的三档**原样**搬过来（行内容一个字节不动），不再读 `candidates.jsonl` / `annotations.jsonl`。这是"只改切分口径、不动数据"的唯一姿势——回头重切会重新洗牌，拿旧版本做对照就没意义了。⚠️ 带了它**不带** `--refresh-scores` 时，pred 侧仍是 vN 冻结时的分数（不是当前评分器的输出），stderr 会喊一声 |
| `--refresh-scores` | 继承式冻结时把每行的 **pred 侧评分按 `golden_id` 从 `candidates.jsonl` 重挂**（只换 `dimension_scores` / `scores_detail` / `status`；**`golden` 与 `code` 一个字不动**）。**为什么需要**：继承式冻结「行内容不动」⇒ 上一版冻结时写进去的分数原样带过来，而评分器换了之后那批分数就过期了（v7 的 d5 清一色 5，因为那时 D-5 还「恒真」）——快照与评分器不再是同一个东西，且一个字都不报。**fail-closed**：候选里找不到 `golden_id` ⇒ 退 2 并列出全部缺失 id，**绝不「找不到就留着旧分数」**。只能配 `--from-version` 用 |
| `--regression K` | 从调参池切 K 条**站点级**行作回归集（D-C8 定 60）。按 `golden.label` 分层、种子固定（`--regression-seed`，默认 20261022），同一输入两次切出同一批 |
| `--regression-seed` | 回归集抽样种子，**与切校准/持有的 `--seed` 分开**（改一个不该动另一个） |

`--refresh-scores` 刷新时，manifest 多落一段 `score_refresh`：
`{enabled, source, rows_matched, rows_missing, per_dim: {d5: {before, after}}, tally: {d5: {scored, abstain, no_sample}}}`。
`before`/`after` 是逐维取值分布（键是字符串，`"null"` = 弃权），
`tally` 是三态计数（`no_sample` = 这行压根没样本）。**这两个字段就是审计要看的东西**。

⚠️ **回归集一经冻结不得重切**：源版本已有 `regression.jsonl` 时再给 `--regression` 直接报错。重切等于把"原本判对的"换成"这次判对的"，回归门会永远显示 0 回归。`manifest.json` 里记的是**整行内容指纹**（`split.regression_fingerprint`），`agreement` 每次读都会重算比对——`regression.jsonl` 被人改过就当场退出码 2。

| 参数（`scout run`） | 作用 |
|---|---|
| `--p2-root` | P1 存档 + P2 samples 的共同根，默认 `output/pipeline` |
| `--out` | 三件套落盘目录（**必填**，自动创建） |
| `--mediabrowse-dir` | 可选，指向 `output/pipeline/mediabrowse`；开启后挂 L5 证据到 `evidence_supplement` |
| `--dry-run` | 不落盘，只打印三态统计 |
| `--stats` | 落盘后打印三态统计 |

`aggregate` 另有 `--buckets`（默认 `positive,negative,quarantine`）与
`--expected-unit-count`（少于此数记 `missing_unit` 留痕）；`verify` 另有
`--task-views-root`（默认 `output/pipeline/task_views`）。

输出三件套：

| 文件 | 是什么 | 是否进黄金集 |
|---|---|---|
| `positive_candidates.jsonl` | 四维都高分，可作校准集 | ✅ |
| `negative_candidates.jsonl` | 任一维 ≤ 2 或 veto，**带 tags 字段** | ✅ |
| `quarantine.jsonl` | 任一维 `score=None`（采集/门禁问题），**不是差评** | ❌ |
| `scout.jsonl` | 三者汇总（不含 skip） | — |

⚠️ **score=0 ≠ score=None**：前者走 negative（判了零分），后者走
quarantine（没判）。quarantine 永不入黄金集 —— 它是上游缺陷信号，
不是负例。`from-scout` 只读 positive + negative。

⚠️ **fail-closed 不算差**。当样本采集/仲裁层主动 fail-closed（凭
`L5_FAIL_CLOSED_NOTES` / `AUTO_REVIEW_NOTES`）时，scout 标 `not_run` →
不参与四维评分、也不落盘 —— 它是「主动放弃」不是「结果差」，与
quarantine 语义不同。

### `--emit-disagreements` 派生校准产物

`agreement` 多一个**只读**开关：口径不变（D-10 等价类一致率照旧打印），
额外把这一轮**每一行的每一维**预测落成快照，再从快照里筛出分歧卡。
方案 16 的校准回路（C-15 / C-02）读它，不改任何评分。

```powershell
# 缺省落 output/pipeline/calibration/vN/（派生数据，可重建，不入库）
uv run python -m trajectory_pipeline.evaluation.golden.builder agreement --version 6 --emit-disagreements
# 也可显式给目录
uv run python -m trajectory_pipeline.evaluation.golden.builder agreement --version 6 --emit-disagreements D:\tmp\cal
```

| 文件 | 是什么 | 口径 |
|---|---|---|
| `v{N}/snapshot.json` | **全量**逐行逐维预测（**三档都收**）：`{golden_id, split, dimension, verdict, rubric_ref, gold_*, pred_*}`，附 `rubric_version` / `evaluator_version`；**每条还带采集面三栏**（`gold_access_surface` / `pred_access_surface` / `surface_comparable`，方案 20 §R3，schema **`"2"`**） | 五态封闭集 `agree / detail_mismatch / disagree / tier_gap / ungraded`；`ungraded` **不进分母**（`None ≠ 0`）。`summarize_snapshot()` 出 `d10`（头条档）/ `d10_by_split` / `d10_all_splits` 三个数；`summarize_surfaces()` 出两面分布与 `comparable` 三态计数 |
| `v{N}/disagreements.jsonl` | 分歧卡，**只从调参池出**（`calibration`） | 一张卡 = 一次分歧 = 一个 `disagreement_id`；人工分诊/处置槽位**全空**，`status="open"` |
| `v{N}/collection_accounts.jsonl` | **采集侧账**（方案 20 §R3）：跨面 **且** pred 落在 `COLLECTION_SIDE_BRANCHES`（`blocked`）的行 | 一笔 = 一次访问（按 `golden_id` 聚合）；`loop=collection` / 桶 `evidence_missing` / `owner=collector`。它**不是分歧**——说的是「我们这张采集面被拦」，处置是**换面重采**。与卡**分两个文件**：拦截笔数要能直接数 |

四条读法：

- **`--emit-disagreements` 必须同时给 `--version`**（缺了直接抛 `GoldenError`）：
  快照要和冻结版对齐，否则「上一轮这一行判了什么」无从比较；
- **快照已存在 ⇒ 退 2，不静默覆盖**（M-29 S3′）：那份文件是「上一轮判了什么」
  的唯一凭据，重跑一次 `agreement --version N` 就把它重新盖成今天的
  `evaluator_version`，等于改历史。要重算得显式加 `--force-snapshot`
  （`calibration.gate` 自己那条重算路径**自带**这个许可——闸门的活儿就是每次
  从冻结档重算，复用盘上那份就等于拿旧答案判新版本）；
- **快照是回归判定的唯一来源，分歧卡不是**——上一轮判对、这一轮判错的行
  **不会出现在卡里**，只有全量快照才看得见「原本对现在错」；
- **卡只从调参池出，旁置档（回归集 / 持有集）不出卡**：分诊的下一步就是改
  rubric 或改评估器 = 调参。回归集归 `verify`（C-08）判 `regressed`，持有集归
  最终验收。真数据上这个差别是量级：v6 三档全出 74 张 → 只出调参池 49 张，
  v7 是 33 张；**v9 是 44 张**（33 张 d10 + **11 张 d5 `tier_gap`**——
  软维度金标第一次有值才长出来的，见 [07 手册 §1.2](07-人工复核与判读手册.md)）；
- 快照**不含时间戳**，同样的输入重算逐字节相同，可直接 diff 两轮；
- **采集侧账与分歧卡是两个文件，读报表时也分两块**：`agreement` 的
  「反爬拦截率（采集侧账）」块排在 D10 头条与下钻口径 D **之前**（02 避坑 §3.7）。
  ⚠️ **`拦截笔数 0` 有两种来源**——真没被拦 / 这一版**判不出跨面**（旧冻结档
  两侧都没记面）——所以同一块里必须一起看 `comparable` 三态：`none` 大就是
  后者。`cards_from_snapshot()` 的返回值**不含账**（老签名不变），要账走
  `cards_and_accounts_from_snapshot()`。

四类分布分别在 `summarize_snapshot()` / `summarize_cards()` 里出：
按 verdict、按 `split`、按维度、`d10` 的 `{n, agreed}`；卡片侧按
`delta_kind`（`label_mismatch` / `eq_class_mismatch` / `tier_gap`）。

```powershell
# 登记全部已冻结版本（缺省）
```

| 项 | 口径 |
|---|---|
| **写什么** | **只写** `evaluation/golden/data/scorer_provenance.jsonl`（**旁路账**，与 `v{N}/` 平级、**不进 `v{N}/`**——那一层是冻结档，一字不许改）|
| **不写什么** | 冻结档、`candidates.jsonl`、P1 存档 —— **一个字节都不动**。它**不是** `overlay-scout`（那条路会重挂分数并改变读数）|
| **怎么算** | 三个**面**逐面登记：`code`（D-2/D-4/D-5/D-6）· `llm`（D-3/D-9）· `collection`（D-10 的 `code.branch`）。行里记了 `scorer_version` ⇒ 直接读；没记 ⇒ **重算当前代码面、逐行比对存档里的读数** |
| **三个状态** | `reproduced`（逐行复现 ⇒ **可比**）· `diverged`（复现不出 ⇒ **已知不可比**）· `unrecorded`（没得比 ⇒ **不可判定**）。⚠️ **`diverged` 与 `unrecorded` 不是一回事**：前者是「确定不可比」，后者是「答不出来」 |
| **退 2** | 版本不存在 / 同一版里混着**两版**评分器（出处登记不出来，停下）/ 没有冻结版本目录 |
| **联网** | **不联网**（重算走本地存档 + 本地评分器）|
| **答完在哪读** | 派生的**分歧卡**与**工作表**上多了三栏：`pred_face`（哪一面）/ `pred_comparability`（三态：同一版 / 不是同一版 / 判不出来）/ `pred_comparability_reason`（人话理由）——**答案写在人看的那张表里**，不必自己算 |

⚠️ **效力边界，不夸大**：「当前代码面逐行复现了本版读数」证明的是**读数层面的
一致**，**不是**「当时跑的就是这份源码」——源码当时长什么样没记，谁也证不了。
可比性要的正是前者。

### URL 级金标读数（M-30）

`agreement` 每次都会多印一段「URL 级金标读数」，并可另落一份**人填清单**。
它回答的是「按 URL 读」与「按行读」差在哪——两件事都已裁定：

- **金标粒度 = 按访问**（Q-11，2026-10-23）：同一 URL 的不同访问可以拿到不同
  标签，那是**真事实**（站点漂移 / 地区 / 登录态），**只标注不判缺陷**；
- **切档 = 按行**（Q-12，2026-10-23）：切档按行不按 URL ⇒ 持有集里可能有行与
  调参池/回归集**同 URL** ⇒ **持有集不是 N 条独立证据**，所有持有集读数必须
  带附注（`agreement` 与 `verify` 都会带）。

```powershell
# 只打印读数（不落盘）
uv run python -m trajectory_pipeline.evaluation.golden.builder agreement --version 7
# 另落「URL 级金标冲突清单」：事实块机器刷，两列结论人填
uv run python -m trajectory_pipeline.evaluation.golden.builder agreement --version 7 --emit-url-conflicts
```

| 读数 | v7 实测 | 是什么 |
|---|---|---|
| 同 URL 多头金标 | **19/131** 个 URL | 一个 URL 上有两种 d10 金标（按访问 ⇒ 正常事实，不判缺陷） |
| 跨档 URL | **25** 个 | 同一 URL 的行落在不止一档 |
| 分歧卡落其上 | **11/33** 张 | 落在冲突 URL 上的分歧卡（**不能单独**用来判 H-02 方向） |
| 持有集泄漏 | **65/101** 行 | 持有集行与调参池/回归集同 URL ⇒ 持有集不独立 |

清单落 `evaluation/golden/data/url_gold_conflicts.md`（**入版本控制**，与
`golden/data/triage/` 同性质：机器填事实，人填结论）：每 URL 一节，事实块
（标签分布 / 档位 / 审核人 / 审核时间 / `code.source` / `reached_play_page` /
`fallback_used` / 样本是否在盘上 / 金标备注）由机器填，**「定性」「裁定依据」
两列由人填**——三选一：`漂移可解释` / `不可能共存` / `待查`。

**机器重跑只刷新事实块，已填结论原样保留**（回读旧文件按 **URL** 匹配，
不按行号——行号会随 URL 增删而漂）。

#### 人怎么填这两列

| 要看的 | 在哪看 |
|---|---|
| 事实块（**别动**） | 清单每节开头的「行数 / 金标分布 / 档位」+ 下面那张 11 列表格 |

| ⚠️ 词表缺口（判据认不出 ≠ 金标错） | 现场正文里明明有门禁/拦截，但仓库判据返回空串，**是词表的缺口不是金标的错**，共 5 处：①`paywall_evidence` **只看 body 不看 title**（iqiyi 的「完整版」在 title 里）；②句单元按**换行**切 ⇒ CTA 与语境词被换行拆开（ixigua「打开App看完整内容」）；③`ACCESS_HINTS` 认不出**中文之间夹空格**的短语（youku「请 登录 后继续观看」）；④ixigua 的 App 墙文案已改（词表里旧形态「以下内容需下载西瓜视频查看」**过期**）；⑤**DRM 形态**（v.qq「当前浏览器不支持加密播放」/70013080.14）**不在任何词表里**。⇒ **别拿「机器没判出来」当「金标错了」的证据** |
| 判断口径 | 「同一页面不可能同时成立」＝ 两个标签在**同一份正文**上互相排斥；「无证据不判」≠「页面不是这样」 |

|---|---|

### `calibration.verify` 两轮对比（方案 16 C-08）

**改完 rubric 或评估器，凭什么说「变好了」？** 光看 D-10 涨不够：总数涨着、
某一类塌了，或者回归集悄悄掉了一行，头条都照涨。`verify` 拿两轮**全量快照**
做差，四条判据全过才算过关。

```powershell
# 按冻结版号（快照缺省在 output/pipeline/calibration/vN/snapshot.json）
uv run python -m trajectory_pipeline.evaluation.calibration.verify --baseline-version 7 --current-version 8
# 快照在别处就直接给路径；落报告
uv run python -m trajectory_pipeline.evaluation.calibration.verify --baseline a.json --current b.json --json-out report.json
# 同桶清零（分诊表来自 C-05；给了 --triage 就必须给 --bucket）
uv run python -m trajectory_pipeline.evaluation.calibration.verify --baseline-version 7 --current-version 8 --triage triage.jsonl --bucket eq_class_mismatch
```

| 判据 | 数什么 | 不过的条件 |
|---|---|---|
| **净改善** | 调参池里 `fixed - regressed`（同一条判定从坏变好算修，从好变坏算伤） | `≤ 0`；`--class-tolerance` 可放宽到「数量持平但分布更好」，缺省 `0.0` |
| **无类回归** | D-10 等价类 F1 逐类对比（同一份 `builder.classification_report`，不抄第二份） | 任一类 F1 掉超过容差 |
| **回归集** | 旁置的 60 行 | 任一行 `regressed`，或键集/金标本身变了（后者直接退 2，不是驳回） |
| **同桶清零** | 本轮分歧是否还残留 `--bucket` 那一桶 | 有残留 = 不过；分诊表没给 ⇒ 打印 **n/a 不算通过**（不拦人，但绝不显示 ✅） |

退出码是结论，**别混报**：`0` 通过 / `1` 驳回（判据没过）/ `2` **输入不可比**
（切分变了、schema 版本不同、键对不上、缺文件）。1 是「这次改动不行」，
2 是「这次根本测不成」——把 2 写成 1，工具故障就被读成回退了。

⚠️ 三条口径：

- **快照里 `pred` 是冻结行上的旧判定，不是当轮重算**。所以「改评估器 → 重采集」
  这类变化**现在还判不了**（配对键只有 `(golden_id, dimension)`，重采集换了
  run id 就配不上）——见方案 16 §9.4「已知未做」；
- 两轮必须是**同一份切分**。拿重冻结前的版本当基线，`verify` 会退 2 并报
  「N 行（M 条判定）在两轮之间换了档」，不会假装有数；
- 同一版本对同一版本跑，结果必然是**全 0**（`still_wrong` 该多少还是多少）——
  它是回归的对照，不是「重跑一遍会不会更好」。

### `calibration.gate` 冻结时闸门（方案 16 C-09）

`verify` 能判，但它不会自己跑。闸门把「冻结下一版」和「判这一版好不好」焊在一起：
**freeze 完就跑它**，退出码就是这一版能不能采纳。

```powershell
# 本轮 = 最新冻结版，基线 = 它之前最近的一版（缺省行为）
uv run python -m trajectory_pipeline.evaluation.calibration.gate
# 显式点名（快照由闸门自己重算，不用先手工跑 agreement）
uv run python -m trajectory_pipeline.evaluation.calibration.gate --current-version 8 --baseline-version 7
# 只读盘上已有快照（不重算）；缺了退 2
uv run python -m trajectory_pipeline.evaluation.calibration.gate --no-emit
```

⚠️ **为什么挂在 freeze 上而不是每次 push**：快照的 pred 侧取自**冻结行**
（`snapshot.PROVIDER_FROZEN_BRANCH`），不由当前代码重算。同一版对同一版恒等于
「净改善 0」⇒ 按 push 跑的门永远红 ⇒ 会被绕过。**能被判的只有「这一版比上一版好」**。

| 闸门自己的预检 | 结论 |
|---|---|
| 黄金集里一个冻结版都没有 | 退 2（先 `freeze`） |
| 本轮是**首版**（没有更早的版本） | 退 2 **测不成**——不拿"首版"当通过，要放行走 owner 裁定 |
| 基线与本轮**同一版** | 退 2（同一版对同一版不是比，是没比） |
| 基线**晚于**本轮 | 退 2（反着比正负号会反） |
| 冻结档出不了快照（头条分母空 / 回归集被改过） | 退 2（输入不可信） |
| 两版之间**恰好跨了一次切档**（C-17） | 退 2，并提示「第一对可比的是本轮与它的后继」 |
| 本轮**重挂过金标**（manifest `gold_refresh.baseline_reset=true`，由 `freeze --refresh-gold` 写入） | 退 2，并提示「下一对可比是 vN → vN+1」——**尺子换了，前后不可比**（§「软维度金标」一节） |

闸门**每次都重算**两版快照（同输入逐字节相同，重算不引入噪声；复用盘上旧文件
会把上一轮的结论当这一轮的）。报告里的 `gate_meta` 记着这一对是哪两版。

> 现状读数（2026-10-23）：黄金集最新两版是 v6 → v7，正好跨 C-17 切档 ⇒ 闸门退 2。
> **这是对的**：切档之后第一对可比的是 v7 与它的后继（v8）。别为此去放宽切档守卫。

### `calibration.triage` 分诊档（方案 16 C-05）

分歧卡是**派生产物**（`output/` 下，可重建）；分诊是**人的判断**，进版本控制
（[`evaluation/golden/data/triage/`](../evaluation/golden/data/triage/README.md)）。
一张卡归哪一桶，决定了**谁去改**——所以桶名不能随手贴。

```powershell
# 校验（六桶封闭集 / 签名 / 证据 / 状态）
uv run python -m trajectory_pipeline.evaluation.calibration.triage check
# 贴一桶：默认 dry-run，看清标准化后的行再加 --apply
uv run python -m trajectory_pipeline.evaluation.calibration.triage add --golden-id P000__r1__h --dimension d4 --bucket evaluator_prompt --by zhang --evidence "评分器把可播当不可播，prompt 里没写这一条"
uv run python -m trajectory_pipeline.evaluation.calibration.triage add … --apply
# 已有行改桶/改判据：必须 --replace（否则跳过并报冲突）
uv run python -m trajectory_pipeline.evaluation.calibration.triage add … --replace --apply
```

| 桶 | 归谁改 | 前置事实（写不清就不是这一桶） |
|---|---|---|
| `evaluator_logic` | 代码 | 同一输入按代码走一遍能复现，是**判断规则**错了（不是 prompt 没说清） |
| `evaluator_prompt` | prompt | prompt 里没写这条判据、或写反了 |
| `rubric_ambiguous` | rubric（**只能人填**） | rubric 两头都说得通，缺的是边界定义 |
| `rubric_missing` | rubric（**只能人填**） | rubric 根本没写这一类，判不了 |
| `gold_defect` | 黄金集（**只能人填**） | 金标本身错了 |
| `evidence_missing` | 采集 | 两侧证据都不够，判不了谁对 |

**没有 `other` 桶，封顶六项**（`buckets.py` 里撞上封顶在 import 期就抛）。贴不进去
说明**是新的失败模式**：该做的是扩这套表并写清前置事实，不是临时造个筐。
`accepted_exception` 是**状态**不是桶——桶说「该谁改」，状态说「这轮先放过」。

⚠️ 三条硬规矩：

- **签名必填**（`--by`）。机器身份（`agent` / `llm` / `agent:xxx` / `bot` …）写
  `rubric_*` 或 `gold_defect` 一律拒：这两类金标侧的判断**只有人能下**（D-C3），
  agent 只能往卡上写**建议值**（`suggested_*`）。反方向也拦——人冒充不了机器，
  因为签名是**原文照抄**进档的，谁填的一眼可查；
- **证据必填**，而且要求写清「为什么是这个桶、为什么不是别的桶」。桶名是结论，
  没有判据的结论不可复核；
- **覆盖走 `--replace`，审计走 git**。分诊是人在判断，改了就是改了——不静默覆盖，
  也不做复杂版本号，历史的对照看 `git log -p`。

`verify --triage … --bucket …` 与 `gate` 读的是同一份档：它们在热路径上**再校验
一遍**（`analyze` 是公开 API，不假设调用方已经过 CLI）。

> 现状读数（2026-10-23）：分诊档还是空的——C-06 的工作表已经能出（见下一节），
> 但**填表这一步是人做的**，工具只保证「填完能校验、能落盘、能算覆盖率」。

### `calibration.worklist` 首轮分诊工作表（方案 16 C-06）

三份东西别混：**卡**（派生，只说两侧不一致）→ **worklist**（派生，卡 + 机器事实
+ 至多一条建议）→ **工作表**（人填的表单）→ **分诊档**（裁定，入库）。

```powershell
# 1. 先有卡（缺卡 = 退 2，不拿"这批全都一致"顶替）
uv run python -m trajectory_pipeline.evaluation.golden.builder agreement --version 7 --emit-disagreements
# 2. 出 worklist + 工作表（工作表**已存在不覆盖**；要重来加 --overwrite）
uv run python -m trajectory_pipeline.evaluation.calibration.worklist build --version 7
# 3. 人填 worksheet.jsonl 的三栏：bucket / triage_by / triage_evidence
# 4. 导入（默认 dry-run；半填整批拒，逐条列缺什么）
uv run python -m trajectory_pipeline.evaluation.calibration.triage import trajectory_pipeline/output/pipeline/calibration/v7/worksheet.jsonl
uv run python -m trajectory_pipeline.evaluation.calibration.triage import … --apply
# 5. 看进度：exit 0 全覆盖 / 1 还有未分诊 / 2 测不成
uv run python -m trajectory_pipeline.evaluation.calibration.worklist status --version 7
```

`worklist.jsonl` 每条带三类东西：

| 组 | 字段 | 谁给的 |
|---|---|---|
| 卡 | `gold_value` / `pred_value` / `delta_kind` / `rubric_ref` / `pred_evidence` | 派生（C-02） |
| **事实** | `facts.pred_origin`（`rule` / `llm`）/ `reached_play_page` / `fallback_used` / `gold_reviewed_by` / `collection_refusals` | 冻结行，机器可确认 |
| **建议** | `suggested_bucket` / `suggested_by` / `suggested_rules` / `suggested_reason` / `needs_human_reason` | 规则（当前只有采集层那条） |

**`worksheet.jsonl`（人填的那份）每行多一栏 `scene`——现场读数**：

| 键 | 内容 |
|---|---|
| `found` / `status` | `located`（读到了）/ `located_no_steps`（读到了存档但那步没观察）/ `not_found`（找了没找到）/ `not_read`（压根没读） |
| `unit` / `note` | 匹配到哪个决策单元、**怎么定位到的**（或为什么定位不到；`located_no_steps` 时会说明**为什么那一步没有观察**） |
| `degraded` | 存档自报的降级标记（`steps` / `outcome_missing` …）——`located_no_steps` 的原因多半在这儿 |
| `title` / `steps` | 页面标题；每步一行（`3. click → video=6 iframe=10 元素=80/200 正文=6000字`） |
| `body` / `body_from` | 正文预览 + **它来自第几步**（正文常来自更早的一步，不标出来会读成最后一步） |
| `candidates` | 定位不到时，存档里现有的单元与 url（人好判断是「没访问过」还是「url 对不上」） |

⚠️ 五条口径：

- **行里没有 `bucket` 这个键**（不是留空）——建议只落 `suggested_*`，裁定那一栏
  只在分诊档里存在，且唯一写入口是 `triage.validate_rows`；
- **能预填的桶只有 `evaluator_logic` / `evidence_missing`**（§11.2）。注册表里
  出现 `rubric_*` / `gold_*` 时**导入即炸**，不是靠约定；
- **`evaluator_logic` 当前没有规则**：能机械确认的只有「pred 不是 LLM 判的 ⇒
  `evaluator_prompt` 不成立」，而"所以是代码判据"那一步要读条款才站得住。
  **这不是漏做**——硬填就等于把机器的不确定伪装成建议；
- **两条规则指向不同桶时不给建议**（fail-closed）。机器看到两件事就该由人判，
  别指望它"平均一下"；
- **`scene` 是只读上下文，不进分诊档**（`triage.strip_row` 只留裁定字段）。
  它是「判这一条的依据」，重算会变；抄进裁定档就等于让今天的裁定引用着下一版
  的观察。

**为什么现场要进表**：D-10 的判据原文是「对照黄金集**预存档**的站点核验结论」，
而预存档不在表里。人打开表看到的是「这个页面是不是播放站」这句话、**却没有页面
可看**，「该归哪个桶」就答不了——那不是「人不肯判」，是**表里没有可判的东西**。

**尺子另外落一份** `v{N}/clauses.md`（D-10 / D-4 / D-5 的条款原文，**现读**生成）。
尺子是**同一把**，每行各带一份会让同一个文件长 N 倍。

> 现状读数（2026-10-23，v7 的 33 张卡）：有建议 **12** 条（全是 `evidence_missing`：
> 采集降级 6 / 未选中站点 4 / 遍历超时 1 / 哨兵无法区分 1）；现场读数 **28/33 条定位到存档**，
> 其余 5 条在表里明说「存档里没有匹配该 url 的站点样本」——**不是「页面是空的」**。
> **这 33 张卡已全部由人判完并导入**（`worklist status` 退 0，建议接受 6 / 改判 6）：
> 分布 = `evaluator_logic` 11 · `evaluator_prompt` 1 · `gold_defect` 14 · `evidence_missing` 7
> · `rubric_*` 0。⚠️ 其中 5 张「定位不到现场」的卡里 **2 张仍判成 `evaluator_logic`**——
> **读不到现场 ≠ 采集的错**，别把 `scene.status=not_found` 直接翻成 `evidence_missing`。

### `calibration.worklist show` 读现场（方案 16 C-06 配套）

**不联网，只读**（不写分诊档，不写工作表）。工作表给的是「结论 + 一句话证据」，
**不是现场**；D-10 的判据原文是「对照黄金集**预存档**的站点核验结论」——
预存档不在表里。这条命令把冻结行反查回存档（**复用 builder 的同一条查找路径**，
不自己猜文件路径——两份查找逻辑必然漂，而漂了不报错）并附上 rubric 条款原文。

> 现场现在**也**在 `worksheet.jsonl` 的 `scene` 栏里（`build` 一并写）。
> `show` 仍然是查单条现场的手段：一卡一屏，带条款原文，比在 JSONL 里翻行舒服。

```powershell
# 一张卡：两侧 + 现场 + 尺子
uv run python -m trajectory_pipeline.evaluation.calibration.worklist show --version 7 --golden-id E006__2729220b__e9b9542b
# 全部卡：紧凑读数（一卡四行，人扫）
uv run python -m trajectory_pipeline.evaluation.calibration.worklist show --version 7 --all
# 另存结构化读数（派生，不入库）
uv run python -m trajectory_pipeline.evaluation.calibration.worklist show --version 7 --all --json trajectory_pipeline/output/pipeline/calibration/v7/evidence.jsonl
```

⚠️ 三条口径：

- **它只给事实，不给结论**——桶仍然由人填（`triage.validate_rows` 仍是唯一写入口）；
- **定位不到现场就说定位不到**（并列出存档里现有的单元与 url 作候选），
  **不返回空读数**——空读数会被读成「页面里没有 video 标签」，那是把「没找到」
  当成「看到了没有」；
- **尺子与现场分两处写着**：D-10 说「结论与 ground truth 一致」（比**什么**），
  「该给哪个分支标签」在 **D-5 决策树**、「什么算播放组件」在 **D-4**——
  条款原文从 rubric 文档**现读**（**不抄第二份到代码里**）。

`--golden-id` 与 `--all` **都不给 = 退 2**（一条都不指 ⇒ 不知道要看哪张卡）；
给的 ID 不在本轮卡里也退 2，并说清是「不是分歧卡」还是「版本对不上」。

### `calibration.goldwork` 软维度金标填表盘（方案 16 · C-11 收尾）

**不联网，只读**（只写自己那张表，**不写** `annotations.jsonl`）。
补的是回路里最大的一块空洞：黄金集的 `dimension_scores` **一条都没填**，
于是 v8 快照 1133 条里 **844 条 `ungraded`**、条款级读数只覆盖 D-10、
T-2 / T-3 恒测不成、抽样盘 S2 / S3 两层总体为 0。

```powershell
# 1. 出表（D-2 / D-4 / D-5 / D-6 各一行；已存在不覆盖，重出加 --force）
uv run python -m trajectory_pipeline.evaluation.calibration.goldwork worksheet --version 8
# 2. 人填三格：gold_score（1–5，判不了写 null，没看就留空）/ gold_note / reviewed_by
# 3. 导入（只写分数，不动 label；默认不覆盖已填的分，改判要 --force）
uv run python -m trajectory_pipeline.evaluation.golden.builder annotate --dimensions-only \
  --input trajectory_pipeline/output/pipeline/calibration/v8/gold_worksheet.jsonl
# 4. 带进新版本（只换 golden.dimension_scores）
uv run python -m trajectory_pipeline.evaluation.golden.builder freeze --version 9 --from-version 8 --refresh-gold
# 5. 进度（待填 / 已填 / 人判判不了 / 无样本）
uv run python -m trajectory_pipeline.evaluation.calibration.goldwork status --version 8
```

**表里每格带六样只读上下文**（少一样人就判不了，C-06 踩过同一坑）：

| 键 | 内容 | 为什么要它 |
|---|---|---|
| `anchors` | 该维 1–5 档的 rubric **原文**（`rubric_tier_text` 现读文档） | 手抄一份帽标必然漂 |
| `scene` | P1 存档现场（标题 / 每步动作与观察 / 正文预览），与分诊工作表的 `scene` 同源。⚠️ `scene.title` 是**页面标题**，不是目标片名 | D-4 / D-5 判的是**页面**，不给页面就只剩 pred 可抄 |
| `record` | 这条**记了什么** + **存档在哪**：`unit_url` / `site_url` / `play_page_url` / `reached_play_page` / `archive`（P1 存档路径，与 `evidence.locate_sample` 同一条 `{task_id}__{run_id}.json` 口径）/ `archive_exists` | D-6 核的就是「记录字段完整性」，被核的字段自己得在表里；片名与 `outcome.evidence` 原文只在存档里（P2 不复制），没有 `archive` 人就得自己拼路径 |
| `pred_value` / `pred_reasons` / `pred_branch` | 当前评分器的输出与理由原话 | 这是**要判的对象**，不是答案——照抄 pred 等于把尺子交给被量的人。⚠️ 可能是**旧判据**（见下面「底料以存档为准」） |
| `gold_label` | 这条样本**归哪个分支**（D-1 硬维度的结论，如 `trailer_only`） | ⚠️ **它不是这四维的分数**——长得像答案但是另一道题，别照抄 |
| `existing` | 这张卡这一维**已有**的金标（内容键预填，L-19；v8 首版全空） | 换一版重出表不能让人把同一格再填一遍 |

⚠️ 七条口径：

- **只出「有样本」的行**：`status != scored` 的行没有观察，人无从判分 ⇒ 不进表，
  但**按维度单列计数**（`no_sample`）。把它混成「没人填」会让覆盖率永远上不去，
  而真相是那一条压根没有可看的东西；
- **`null` 是结论、空串是没填**：两者进快照都是 `ungraded`，但覆盖率分得开
  （「91 条里 40 条人判过」≠「91 条都没看」）；
- **表是派生物**：写入只有一个入口（`annotate --dimensions-only`），重出表不会
  顺手改金标；整张表空格导入 → 退 2，不写一堆 `null`；
- **没人签不写**：`reviewed_by` 空着，分数与机器猜的分不开；
- **金标变动 = 新基线**：`freeze --refresh-gold` 落
  `gold_refresh.baseline_reset=true`，`gate` 读到就退 2。填完金标就顺手跑
  `gate` 比一版，读到的会是「净改善 +N」——那 N 是**尺子换了**，不是评估器变好；
- **底料以存档为准**：P1 存档被人工 relabel 过而快照没跟上时，`pred_branch` 会与
  存档 `branch` 对不上（v8 实测 **7/91 条 D-5**，其中 3 条机器给了 5 分）⇒
  **以存档为准**，并在 `gold_note` 写明「底料已 relabel」；
- **判读口径只认 `anchors` 原文**：D-4 的档位差在「**处数**」不在「方向」、

### `rubric_changelog` 变更记录与「未列条款逐位不变」（方案 16 C-12 / C-18）

两件事、两条命令、两个不同的问题：

| 命令 | 问的问题 | 什么时候跑 |
|---|---|---|
| `check` | 表**填得对不对**（九列齐全 / 变更类型在封闭集 / 每条改动指回分歧卡 / 现行版本有行） | 改完 rubric 立刻跑；门禁里也有（契约测试） |
| `audit --before N --after N` | 改动**有没有偷偷动别处**（逐条款比两版快照，未列条款必须逐位不变） | 出新快照、升版本时 |

```powershell

uv run python -m trajectory_pipeline.evaluation.scorers.rubric_changelog check
uv run python -m trajectory_pipeline.evaluation.scorers.rubric_changelog check --verify-cards --version 1.3
# 2. 未列条款逐位不变
uv run python -m trajectory_pipeline.evaluation.scorers.rubric_changelog audit --before 7 --after 8
# 3. 落报告（JSON）+ 快照不在 pipeline/output 下时直接给路径
uv run python -m trajectory_pipeline.evaluation.scorers.rubric_changelog audit --before 7 --after 8 --json-out out.json --calibration-root <目录>
```

**唯一真源是 rubric 文档里的那张 markdown 表**——解析它，不另存一份 JSONL
（抄两份必然漂，见 CLAUDE.md 纪律 6）。九列：版本 / 日期 / 条款 / 变更类型 /
变更内容 / 预期效果 / 分歧卡 / 责任区分声明 / 修订人。`—` 只表示「该版本当时
不存在这一项」，不是「没想到」。列契约逐条判据见
[rubric 文档 · 变更记录列契约](设计方案/在线视频场景rubric.md)。

⚠️ 五条口径：

- **`audit` 的退出码是结论**：`0` 过 / `1` 有条款动了 / `2` **测不成**（缺快照、
  schema 不合、两版 `rubric_version` 相同、区间里没有变更记录行、**或受检条款
  一条都没配上**）。`2` 不是「驳回」，是「这条判据没跑到」；
- **`0 条样本 ≠ 一切正常`**：`freeze --from-version` 把行原样带过来，两版分数
  完全一样，这个守卫会**空跑**并印 `✓`——所以它单列 `measurable`，
  判据是「受检条款上真配上了条目」，不是「没发现差异」。**`check --verify-cards`
  同一条道理**：表里一条卡号都没有时（追溯线 1.3 之前全是 `—`）它印
  「没有任何卡号可核」，**不印 ✓**——核了 0 条不等于全对得上；
- **刚好触及条款是允许的**：改 `D-3` 时 `D-3.5` 一并算「已列」（派生根）；
  通配 `*` 表示整版重写，此时守卫退化成「什么都不断言」——**如实印出来**；
- **金标被重判只报不驳**：快的 `gold` 侧变了（`gold_defect` 窗口内的正常动作）
  单独列 `gold_moved`，不混进「pred 动了」；
- **追溯线是前向的**：`TRACEABLE_SINCE = "1.3"` 之前的老行允许 `分歧卡` 填 `—`
  （那时还没有分歧卡这套机制），从 1.3 起**必须能指回卡**。不伪造历史。

### `calibration.sampling` 分层抽样 S0–S3（方案 16 C-19）


| 层 | 判据（机械可算） | 抽它干什么 |
|---|---|---|
| **S1** 两评分者打架 | `verdict ∈ {disagree, detail_mismatch, tier_gap}` | 主菜：分歧面 |
| **S3** 中间段 | 软维度金标 = 3 分，或硬分类 = `ambiguous` | 最容易含混、最该抽查的那段 |
| **S2** 理由含糊 | 有 judge 理由、且理由引不到 `--quote-marker` 给的片段 | 判分有没有落到观察上 |
| **S0** 一致且两端（**对照层**） | `verdict = agree` 且等价类 ∈ `SUCCESS` / `REACH_FAIL` / `BROKEN_CONTENT` | 估「**一致但都错**」的假阴性——只抽分歧会把它估成 0 |

⚠️ 五条口径：

- **配额缺口如实报，不补**（`short_by`）。层候选不足就少给，**不跨层借人**——
  借完 40 条看着齐了，实际 20 条同质，「分层样本」这个词就废了；
- **抽样可复现靠「固定种子 + 稳定排序 + SHA-256 定序」，不用 RNG**：
  `random.sample` 跨 Python 版本可能换结果，而冻结档要的是换台机器跑出同一份；
  **同一输入两次抽样逐行相同**（有测试封着）；
- **一条只入一层**，优先级 S1 → S3 → S2 → S0（信息量最大、最稀缺的先挑，
  S0 兜底）。层间重叠**写进报告** `overlap`——重叠是事实，藏起来就成了
  「四层互斥」这个假前提；
- **层内读数不外推总体**（D-C10）：每行带 `sample_weight` = N_h / n_h，它说的是
  「**这条有多重**」，**不是**总体估计量。要外推得单独设计权重推导；
- **抽不满不是 bug、也不许凑**：缺口说明判读盘里少两类样本，人工判读只看得见
  S0/S1——**回路这半边看不见 S2/S3 的质量**。这是「软维度金标未填」的另一个后果。

> 现状读数（2026-10-23，v7 头条档）：S1 总体 **33** / S0 总体 **32**（各取满 10），

## 取证后处置（`cli downgrade`）

判据成立时把 outcome 降为 `unresolved`（人工复核分支，**不入负样本池**，§5.1）。

```powershell
# 默认 dry-run：只报清单
uv run python -m trajectory_pipeline.executor.cli downgrade --url v-wb.youku.com --reason "现场实测无渲染"
uv run python -m trajectory_pipeline.executor.cli downgrade --evidence '\(?<!\d\)0 个交互元素' --reason "采集缺件，非业务结论"
# 看完清单再落盘
uv run python -m trajectory_pipeline.executor.cli downgrade --evidence '…' --reason "…" --apply
```

| 参数 | 作用 |
|---|---|
| `--out` | P1 存档目录（默认 `output/pipeline`）。**只动原档，不动 `.reviewed.json`** |
| `--url` / `--evidence` | 两个选择器，**互斥**——同用会让人猜是 AND 还是 OR |
| `--branch` | 限定分支。**不受理 `unresolved`**（它已是降级后的状态） |
| `--reason` | **必填**，原样进 `evidence`。它是半年后唯一能说清「这条当初凭什么被降」的依据 |
| `--apply` | 落盘。**默认只报清单** |

`--evidence` 走 Python `re`，且**只看原始判定正文的第一段**——
每次降级追加的中文理由里也含判据关键词，全文匹配会把自己刚降的再降一次
（真发生过，见[避坑指南 §1.5](02-避坑指南.md)）。

处置动作只有一份（证据戳、`branch_before_downgrade`、ledger 记账、
`visits[].success` 同步），**判据由 `--url` / `--evidence` 传进来**：
判据是那批数据的结论，不是通用参数。

⚠️ **存量存档里指向已删脚本的落款不回改**（如 `success_downgraded_by` 里
的 `scripts/probe_disputes.py`）——那是在**那批取证当时的落款**，改它等于
改写证据来让记录好看，比留着指向已删文件更坏。看不懂就去读
`review_note` 全文，取证结论写在正文里，落款只是落款。`cli downgrade`
新写的落款是 `人工降级（cli downgrade）`。

⚠️ **扫的是「存档」而不是「`T` 开头的文件」**（2026-10-26 修）：原先遍历写的是
`glob("T*__*.json")`，只认 `T` 前缀。生产根目录 78 份存档里 **28 份是 `E`/`P`
前缀**（`E005__e35b7455.json` 这类），双跑那批判全是 `DR01__` ⇒ 那些存档
**结构性地降不掉**，而命令打印的是「没有匹配的 outcome —— 归档可能已被降过
（幂等），或判据不匹配」：**判据被冤枉**。现在口子与 `check-archives` 同一处
（`archive.select_archives`：文件名里必须有 `__`，探针取证不算），只额外
折回**原档**（不动 `.reviewed.json`，见上）。`--out` 仍**不递归子目录**——
子目录里的存档（`dualrun/camoufox/`〔2026-10-21 那批的历史路径〕、
`dualrun/camofox/`〔现行批〕、`proberun/`）要点名给 `--out`。

## 改分支（`cli relabel`）

**判定成立、但分支贴错了**——这一类改动前**没有处置路径**：
`downgrade` 的目标分支硬编码 `unresolved`（那说的是「判定不成立」），
而 `review --apply` 只对 `REVIEW_BRANCHES`（反思档）生效，**真负样本不在其列**。
`relabel` 补的就是这条路：**换一个真负样本分支，仍留在池里**。

```powershell
# 默认 dry-run：只报清单
uv run python -m trajectory_pipeline.executor.cli relabel --to blocked --branch subscription_wall --reason "主证据是地区限制（70017001.1），不是付费墙"
# 看完清单再落盘
uv run python -m trajectory_pipeline.executor.cli relabel --to blocked --branch subscription_wall --reason "…" --apply
```

| 参数 | 作用 |
|---|---|
| `--to` | **目标分支**。必须是**活跃且是真负样本**的分支——`unresolved` / `trailer_suspect` / `player_unverified` / `site_search_routed` 走 `review --apply`，已弃用分支（如 `login_wall_or_blocked`）不受理 |
| `--out` | P1 存档目录（默认 `output/pipeline`） |
| `--url` | 按 URL 片段挑（**多片段 OR**） |
| `--branch` | 按**当前**分支挑（**多名 OR**） |
| `--evidence` | 按**原始判定正文**是否命中正则来挑（只看第一段） |
| `--reason` | **必填**，原样进 `evidence` |
| `--apply` | 落盘。**默认只报清单** |

**判据组合**：同类 OR、异类 AND（`--url` 与 `--branch` 同时给 = 两个都命中）。

**落盘时存档与负样本池一起改**——训练侧吃的是**池行**的 `branch`，
不是存档；只改一边会让门禁报 `negative_not_pooled`。三条派生行为：

| 落点 | 改什么 |
|---|---|
| 存档 outcome | `branch` / `branch_before_relabel`（记**原判**，链式不覆盖）/ `source=human` / `evidence` **追加**一段（原正文不覆盖） |
| 存档 ledger | `by_branch` 逐 outcome 增减、`missing_branches` 同步；**`negative_samples` 不动**（改判前后都是真负样本，池的规模没变） |
| 负样本池 | 改写那一行的 `branch` / `branch_label` / `source` / `evidence`；**坏行原样保留** |

⚠️ **复核档（`.reviewed.json`）也一起改**——读侧
（`archive.select_archives`）**优先取复核档**，只改原档 ⇒ 复核档里还是旧键
⇒ 门禁当场报 `negative_not_pooled`。原档也改了，所以下一次
`review --apply` 从原档重新合并时**不会把改判覆盖回去**。

⚠️ **撞键并入，不新建行**：同一个 `(task_id, url)` 在池里已有新标签那一行时
（实测有两次跑出互相矛盾的标签），改判后会同键 ⇒ 违反池的去重约定。
处置是「**并入**」：保留已有的那条、**删掉**贴错标签的那一条，**不新建**。

⚠️ **不向池补行**：存档里有、池里没有的负样本（**人工改判改出来的那些**），
本命令**不补**——补行是**并池**动作（`cli pool-add`，见下），越界。

⚠️ **凭据闸门**：理由是人手输的 ⇒ 闸门挂在入口，命中凭据特征**直接拒绝**，
dry-run 也拒。

## 撤池行（`cli pool-drop`）

**「这一行的结论不成立」**——`check-archives` 的
`negative_contradicted_by_success`（Severity.FATAL）会指出来：**池里那一行的
URL 在某份存档里同时是一次「成功」**。

处置分**两侧**：`downgrade` 改**存档**（结论 → `unresolved`，离开池），
`pool-drop` 撤**池里那一行**。**顺序永远是先改存档、后撤池行**——
反过来的话，撤池时存档还写着旧结论 ⇒ 撤掉的那行在存档里还有支撑，
看着像撤错了。

```powershell
# 默认 dry-run：只报清单
uv run python -m trajectory_pipeline.executor.cli pool-drop --url "555k27.com/vodplay/572215-1-1.html" --branch component_unverified --reason "存档侧已降为 unresolved ⇒ 池里这一行没有存档支撑，是孤儿行"
# 看完清单再落盘
uv run python -m trajectory_pipeline.executor.cli pool-drop --url "…" --reason "…" --apply
```

| 参数 | 作用 |
|---|---|
| `--url` | 按 URL 片段挑（**多片段 OR**） |
| `--task-id` | 按 task 挑（**AND**——同一个 URL 可能挂着不同 task 的行） |
| `--branch` | 按分支挑（**AND**） |
| `--reason` | **必填**，进 `pool_dropped.jsonl` 审计日志（原行 + 理由 + 判据 + 时间） |
| `--apply` | 落盘。**默认只报清单** |
| `--out` | P1 存档目录（默认 `output/pipeline`） |

**判据必须显式给**（`--url` / `--task-id` / `--branch` 至少一个）——
**不给就是全选**，而池是**跨 run 累积的 append-only 资产**，**全选等于清空训练集**。

⚠️ **它不碰存档**：存档侧的结论由 `downgrade` / `relabel` 改。
⚠️ **撤掉的行连同理由进 `pool_dropped.jsonl`**——池里没有反向操作，
删掉的东西不留痕，半年后只剩「这行没了」，没人知道为什么。
⚠️ **坏行原样保留**（坏行可能是被人手工截断、正等人查的，不该被一次撤行动手清掉）。
⚠️ **不要写「池与存档对账」的工具**：实测有 10 行池找不到对应的顶层存档——
那些存档在**子目录**里（`proberun/`），顶层 `glob` 看不见 ⇒
对账工具会误删完全正确的行 ⇒ 撤行只能**显式逐条定**。

## 并池（`cli pool-add`）

**「这一条该进池，却没进池」**——最常见的一种是**人工改判**出来的：
`review --apply` 把 `unresolved` 改成 `partial_free` / `subscription_wall` /
`component_unverified` 等**真负样本**，存档里有了，**池里没有**。

⚠️ **训练侧吃的是池**（`evaluation/golden/builder.py` 读 `negative.jsonl`），
**不是存档** ⇒ 没并池 ⇒ 这条负样本**压根没进训练集**
（2026-10-26 实测：门禁 `check-archives` 报 `negative_not_pooled` ×30 =
29 条人工补判 + 1 条历史欠账）。

```powershell
# 默认 dry-run：只报清单
uv run python -m trajectory_pipeline.executor.cli pool-add --out trajectory_pipeline/output/pipeline
# 看完清单再落盘
uv run python -m trajectory_pipeline.executor.cli pool-add --out trajectory_pipeline/output/pipeline --apply
```

| 参数 | 作用 |
|---|---|
| `--out` | P1 存档目录（默认 `output/pipeline`）——**只扫顶层**（子目录要点名） |
| `--apply` | 落盘。**默认只报清单** |

**口径与门禁一致**（顶层存档 · 复核档优先 · 排除 `NON_SAMPLE_BRANCHES` 与
`COLLECTION_SIDE_BRANCHES` · 键 `(task_id, url, branch)`）⇒
**跑完 `check-archives` 就不再报 `negative_not_pooled`**。

⚠️ **幂等**：已在池里的键**不出现**在清单里 ⇒ 跑第二次是空清单。
⚠️ **三条拒并条件**（命中就**跳过并打印**冲突的那份存档与它的 evidence）：

| 拒并 | 什么情况 | 人该怎么办 |
|---|---|---|
| `quarantined` | 整条 URL 已人工判为**拒收**（`quarantine.jsonl`） | 不并池；确认该判是不是过期 |
| `contradicted` | **同一 URL 在别的存档里被判成功** | 矛盾**不替人投票** ⇒ 查那份成功存档 |
| `stale_branch` | 池里同 `(task_id, url)` 已有**别的分支**（人工改判的旧行） | 先走 `cli relabel`（两边一起改） |

⚠️ **人工的理由会折进池行的 `evidence`**（训练侧只读 `evidence`）——
不折进去就会出现「evidence 说『无证据不记负样本』」配一个负样本标签，
**理由与标签互相打脸**。
⚠️ **并池是「写入时的动作」⇒ 不回填历史** ⇒ `review --apply` 接线**之前**
改判的那些**不会自动补上**，补欠账走本命令。

```powershell

# Anthropic 通道（次选；只 ANTHROPIC_API_KEY 设了才走）

# 模型与超时（默认值已够用，按需覆盖）：

# INC34_OPENAI_TIMEOUT_S = 12.0
# INC34_ANTHROPIC_MODEL = claude-3-5-haiku-latest
```

**三处纪律**：

1. **降级显式**——无 key / API 错 / label 非法都走 `HeuristicVLMReviewer` 兜底，`source="multim_fallback" + note="multim_fallback:<reason>"`。**不冲掉 L4 标签**。
2. **OpenAI 优先**——双 key 同时设时 OpenAI 优先；`elif` 改相等权重是**合同变更**，不要悄悄改。
3. **空字符串 key 与 unset 同语义**——`OPENAI_API_KEY=""` 是 falsy 走 fallback，不是调通网络收 401。


**代码不猜模型名**——按「缺件即报错，不猜」这条纪律，清单里挑一个是**人的决定**。

感知实现由 `TRAJECTORY_PERCEPTOR=rule|llm|auto` 选（默认 `auto`）。

### 排查：判断题空回传 / 「模型没答」

症状都是「判断题未取得结论（LLM 不可用（…））」。**先读括号里的错误前缀再动手**——前缀不同，处置完全不同：

| 存档 `warnings` / 终端错误前缀 | 根因 | 处置 |
|---|---|---|
| `budget:max_tokens 用尽（finish_reason=length，content 为空）` | 推理模型**思考吃光了输出预算**（思考与正文共用 `max_tokens`），不是后端坏了 | 调大 `TRAJECTORY_LLM_MAX_TOKENS`（**16384**，TPIN02 实测；默认 8192 对真实采集不够）→ 重跑 |
| `transport:ReadTimeout` | **请求超时**（搜索页分类的输入大，默认 90s 不够） | 调大 `TRAJECTORY_LLM_TIMEOUT_S`（默认 90）→ 重跑；仍超时查后端负载（[§5.6](02-避坑指南.md#56-推理模型的思考与正文共用-max_tokens-一个预算) 副产物教训） |
| `shape:...` / 解析失败 | 模型回复格式坏了（未转义引号等） | `schema_parse` 已容错；仍失败看日志 `last_error`（[§5.19](02-避坑指南.md#519-解析失败不是判不出来而-403-不是-503)） |
| `http:403` | 模型名大小写不匹配/未注册 | `/models` 清单逐字核对（见上表） |
| `http:503` | 服务过载 | 等，或换可用模型 |

**步骤**：

1. 重跑一条已知样例（`run --task-id TPIN02 --title 功夫`）复现，先排除偶发；
2. 从存档 `warnings` 读出错误前缀，按上表定位根因；
3. **只调对应参数，且改完必须重跑同一条验证**——判断题真出了结论（`heuristic_candidates=0`、四分类里 `video_site` 非空）才算修好，不能凭推理宣布修好（[§5.6 副产物](02-避坑指南.md#56-推理模型的思考与正文共用-max_tokens-一个预算)）；
4. 换机器/换模型后第一件事：用 `LLMConfig.from_env()` 打印实际生效的 `max_tokens` / `timeout_s`（`setx` 只对新终端生效，防「配了没生效」被当「模型坏了」）。

> 这一节只对 **scripted 链**成立：搜索页一级判断 `①.5 CLASSIFY_SEARCH_LINKS`
> 两条链都问（搜索页不归 agent 管），而站内那一段 agent 链根本不问
> ② / ③ ——它的 LLM 调用走 [`agent_loop`](../executor/agent_loop.py)，
> 排查口径不同。两条链的分界见[架构总览 · 控制流与四个判断点](01-架构总览.md)。

```powershell
uv run python -m pytest -q
```

> 历史教训仍然有效：gdr/tests 曾漏在门禁外，360+ 条不跑，掩盖了 2 处生产代码从未执行——
> **门禁必须显式枚举每一棵在开发的树，漏一棵 = 静默失效不可见**。

**另一道门是校准闸门**（`python -m trajectory_pipeline.evaluation.calibration.gate`，[C-09](#calibrationgate-冻结时闸门方案-16-c-09)）：
它不进 `pytest`，因为它判的是**冻结版本之间**的关系，不是代码是否自洽——触发点是
`freeze`，不是 commit。CI 若要接，接的是它，且**退出码 1 与 2 必须分开报**。

**变异测试（`uv run python -m trajectory_pipeline.tests.mutation_check`）只对 scripted 批次承担守卫职责**（2026-10-18 A3-5 收口）：它的前提「结论可从 task_id 纯函数重算」在 agent 批次不成立（决策侧多了 LLM，同 task 重跑不保证同轨迹）。agent 批的重跑可比性由 `executor_mode` 分批记账 + 归因锚点存档全保真承担，A/B 口径改为「同 task N 次重跑取分布」——见 [A/B 双跑节](#scripted--agent-ab-双跑五指标验收2026-10-18-a3-4)。变异本身仍指向 agent 链**两侧的护栏**（ref 白名单〔obscura 面〕、预算、死循环、分支映射），那些恰是 agent 模式最该守住的东西。

## 两条固定动作

**每次真实运行后都要逐条打开存档读 evidence 核对**——这是固定动作不是可选项。设计上五类缺陷全部是离线测试测不出来的（fixture 是我们自己造的，规则和 fixture 一起错，测试照样绿），只有把真实站点喂进去、逐条读存档，才会看见「结论」和「证据」在打架。踩坑全记录在 [避坑指南](02-避坑指南.md)。

**这条现在是命令了**：`cli check-archives`（[`executor/integrity.py`](../executor/integrity.py)）是它的机械版——查证据链完整性、结论与观察是否自相矛盾、真负样本有没有并池。**纯手工的固定动作等于没有**：它靠人记得做，而它恰恰是最容易在赶批次时跳过的一步。选档案走 `archive.select_archives`，与 `report` 同一口径，否则会出现「门禁说全过、报表说有 5 个档有问题」。三档严重度：

| 档 | 含义 |
|---|---|
| `FATAL` | 不可信，只能重跑 |
| `DEGRADED` | 缺件，不能直接当训练数据 |
| `INFO` | 看一眼 |

**判断「结论对不对」仍然不在门禁里**——那要人读证据，它只保证「值得人读的东西没悄悄烂掉」。

## 感知层回放（`cli replay`）

[`perception/replay.py`](../perception/replay.py) 把 P1 存档里的**真实观察原样**喂给感知实现，**不开浏览器**。P1 存的是 `_obs_json` 落下来的结构化观察——`video_tag_count` / `iframe_count` / `interactive_elements` / 正文 / `degraded` 全在，那正是 `Observation` 的字段。

- **验**：感知层在真实数据上的判得出来率、两版答案差在哪。
- **不验**：ref 点击、播放器探测、跳转、反爬、加载时序——**所以它不能替代真实批次**。

`--perceptor rule` **不需要任何 LLM 后端**，于是「各判断题在真实数据上答得出来几道」完全离线可测。

⚠️ **只报分歧，不报准确率**：拿 rule 的答案当真值会得到一个漂亮的假数字（rule 判成功的那几条里有相当比例是假阳性）。真要算准得先有人工标注集——那也是 `CONFIDENCE_JUDGED` 校准的前置条件，两件事一起做。

> 感知层在热路径上已退位成三块静态资产（[设计方案 15](设计方案/15-执行器与agent-runtime重新定义.md)），
> `replay` 因此是**回归与校准工具**而不是主链的一环：它验的是「两版实现
> 在真实存档上的口径是否一致」，不验控制流。
