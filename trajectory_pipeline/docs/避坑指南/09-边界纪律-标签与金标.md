### 8.14 改了标签却没改**池**：训练侧吃的是**池行**，不是存档

**症状**：`cli check-archives` 报
`negative_not_pooled`（DEGRADED）——「存档里这条真负样本的
`(task_id, url, branch)` 不在负样本池里」；而报告上**只多一行「没并池」**，
看不出是「改标签写了一半」。反过来（只改了池没改存档）也一样报，
**两个方向的症状完全一样**。

**根因**：负样本池（`negative.jsonl`）是**派生资产**，而**训练侧读的是它**——
`evaluation/golden.builder._scan_negative_pool` 读的是**池行**的 `branch` /
`branch_label`，**不是存档**。⇒ **只改存档等于没改**：训练数据一个字没变，
而存档看起来已经改好了。

**纪律**：任何**改分支**的处置动作，必须**存档 + 池**一起改，
且**两边都按同一个键** `(task_id, url, branch)` 落：

- 同一个键在**几份存档**里各有一条时（改一份不改另一份 ⇒ 另一份当场报
  `negative_not_pooled`），要**一起改**；
- **复核档（`.reviewed.json`）也要改**——读侧 `archive.select_archives`
  **优先取复核档**，只改原档 ⇒ 复核档里还是旧键 ⇒ 门禁照样红；
- **撞键要「并入」不是「新建」**：同一个 `(task_id, url)` 在池里已有新标签
  那一行时（两次跑出互相矛盾的标签），改判后会同键 ⇒ 违反池的去重约定 ⇒
  保留已有的那条、**删掉**贴错标签的那条。

→ `executor/relabel.py`（`cli relabel`，2026-10-21 增量七十八）

### 8.15 注释说「旁路生效」，代码早就把它退役了

**症状**：`executor/branches.py::_has_strong_paywall_signal` 的 docstring
写着「LLM 给出强付费墙信号时旁路同页守卫」，`_precondition_failed` 的注释
还写着「强信号旁路**始终命中**」——而这条旁路**在 2026-10-19 就随同页守卫
窄化（同守卫集合 5 条 → 1 条）失去了拦截对手**，那个函数**一个调用点都没有**。
**读代码的人会以为有一条保护在生效**——而它保护的东西早就不存在了。

**根因**：**退役的机制不会自己删自己**。守卫集合窄化时，改的是**调用处**，
那段说明与那个适配函数留在原地；注释随即变成**反向的误导**。

**纪律**：动一处口径时，把**引用它的地方一起搜一遍**——
`grep -rn "<函数名>"` 找到的**每一个**引用都要问「它现在还成立吗」；
退役的机制**连注释一起删**（或明确标注「已退役 + 为什么退役」）。
⚠️ 判据本身没死时要**写清它现在归谁**——本例里强弱信号仍是
`gatekeeper.is_paywall`（**拦截**口径）的判据，只是**不再用于贴分支**。

→ `executor/branches.py` · `perception/rule_perceptor.py`

### 8.16 「读到一半」：观察**跨了一次导航**，读出来的是半页

**症状**（2026-10-22，第一批 camoufox 生产批次读 evidence 读出来的）：

- **同一页、同一动作位置、两次独立运行，`iframe_count` 读出 3 与 0**
  ——那个 0 **不是页面事实**；
- 观察里 **URL 非空而 title 为空**（过渡态）：新文档 commit 了但还没解析完，
  这一份观察**不是**页面事实；
- **同 URL 的两次读数，媒体元素「变少」**（打架）——后一次读到了一半
  （变多 = 页面还在加载，是合法的）；
- 下游因此打出**理由通顺的假负样本**：修复前那批的 `E022` 把
  `ycsedu.cn/yc-vod-play/201830-1-1.html` 记成两条 `no_play_control`
  （「29 个交互元素中未找到播放控件」），**而修复后同一 URL 同一页面
  读出的是「页面包含一个播放器 iframe」⇒ 判 True**。
  同一批里 `nmxzytw.com` 记成 `unresolved`，理由写着
  「点击播放控件**前后是同一个页面**」——**点击其实导航了，只是没被看见**。

**根因**：`observe()` 是 **4 次以上独立往返**（url/title → body → links →
交互元素 → 计数），而**导航是异步 commit 的**——commit 落在两次往返之间，
这份观察就是**两页的拼接**（chimera）。
原先 `_settle` 等的 `domcontentloaded` **恒真**：它等的是**当前文档**的状态，
而旧文档早就 loaded 了 ⇒ 观察恰好落在「旧文档正在被替换」的那一瞬。

**★ 判据换了一代（换错会误伤好观察）**：

| 候选 | 实测 | 结论 |
|---|---|---|
| playwright `page.on("framenavigated")` | **同文档导航（pushState / 改 query）也触发** | ❌ SPA 页面（bilibili 等）播放时改 URL ⇒ 被误判成「换了文档」⇒ 观察白白重来、连续撞上还误记 `nav_unsettled` ⇒ **把好观察当半成品丢掉** |
| **`performance.timeOrigin`** | 同文档连读两次**恒定**；pushState 后**不变**；真导航后**变** | ✅ 每个文档一个常量，**pushState 免疫**，且在隔离世界（`main_world_eval=False`）里读得到 |

⚠️ **两种「读不到」必须分开**：`""` = **读失败**（执行上下文被销毁 ⇒ 正在换文档
⇒ ** instability 的证据**，要继续等）；`"none"` = **页面没有 `performance`**
（读得到且恒定 ⇒ **永不误伤**）。混成一个「读不到」⇒ 每个没有 `performance`
的页面都会把观察降级成半成品。

**纪律**（两条治法，都在驱动层）：

1. **动作之后先等新文档 commit 再观察**（有界 2s，`click`/`fill`/`press`
   一律等——owner 裁定「速度次要」）。`fill` 也要等：页面脚本可能因输入触发跳转，
   而 agent 链里 `fill` 之后**下一步就是观察**，不等的代价是拿旧页的名字去点新页
   ——**点错不可逆**。
2. **观察侧读数自检**：观察前后各取一次**文档代号**，跨了文档就重来（至多 2 次），
   仍不稳记 `degraded += "nav_unsettled"` ⇒ 下游**不判**（fail-closed：
   `unresolved` 不是负样本）。

⇒ **判据必须能分「换了文档」与「只改了 URL」**——前者要重来，后者不是。
拿「URL 变没变」当判据会在 SPA 上误判；拿「连续两次读数一致」当判据**在导航前恒真**
（§8.8）。

**量**（`research/probes/probe_settle_readings.py`）：修复前 **24 份存档 / 388 条带 URL
的观察 ⇒ 过渡态 59（15%）、读数打架 6**；**修复后（第二批）12 份 / 218 条 ⇒
过渡态 8（3%）、读数打架 1、`nav_unsettled` 0**；同 task 的直接对照
（`E022`：修复前 **7/17（41%）** ⇒ 修复后 **0/19**）。
★ **那 8 条过渡态全落在 ixigua 一个站上**（7× 同一 URL + 1× 另一个 ixigua URL）
⇒ **剩下的不是「读到一半」，是那个站的页面压根没有 title**（站点属性）；
而修复前的分布是**散在 10 份存档里**（`E022` 7/17 · `E028` 5/25 · `T025` 4/21
· `E014` 3/13 · `T004` 3/13 · `T018` 3/21）⇒ **从「散布」变成「集中到一站」
正是治法生效的样子**。

→ `executor/browser/camofox_driver.py`（`_doc_stamp` / `_await_commit` / `_settle` / `observe`
——**同一套判据在现行执行层上**）
· ⚠️ `probe_doc_stamp.py` / `probe_nav_commit.py` 两支探针**已退役**
（2026-10-26，见 [`research/README.md` §退役配方](../../research/README.md)）——

### 8.17 回归集被重切或改了标签：`regressed` 永远是 0

**症状**（方案 16 C-17）：`cli verify` 报 `regressed = 0`、门禁一片绿，
而上一轮明明修坏过东西。真相是**两轮比的不是同一批行**——
回归集被重新切了一次，或者里面某几行的金标被就地改了。
**绿色的门保护的是一个已经换掉的基线**。

**根因**：回归集是**唯一跨轮可比**的资产，它的可比性**不在行内容里，
在「还是那 60 行」这个事实上**。重切与改标签都不改变任何单行数据的外观，
只改变「这批样本还是不是上一次那批」——**这一点没有任何字段记得住**。

**纪律**：
- **整行内容指纹当守卫**：冻结时把 60 行的整行（12-hex sha256，
  剥掉 `__` 前缀的运行时注解如 `__split__`，否则冻结时与读时的哈希必然对不上）
  写进 `manifest.split.regression_fingerprint`；`agreement` **每次重算**，
  不一致就 `GoldenError` 退 2——「回归集不得改动（C-17）」
- **回归集一经冻结不得重切**：`--from-version N` 携带回归集，
  在已经有 `regression.jsonl` 的版本上再给 `--regression K` 直接拒绝，
  不猜、不静默重切
- **要改标签就新建版本**，不在原地改；历史版本的回归集永远保持冻结时的样子
- **回归集与 holdout 都不许当 triage 素材**：分歧卡只从调参池出
  （`cards_from_snapshot` 按 `SIDE_SPLITS` 过滤）。拿回归集调参 =
  回归门失效；拿 holdout 调参 = 封存作废（D-C5）

→ `evaluation/golden/builder.py`（`_rows_fingerprint` / `cmd_freeze` carry 路径）·
`evaluation/calibration/disagreement.py` · `tests/unit/test_golden_three_split.py`

### 8.18 `verify` 的绿是三种绿：`n/a 不算通过`、`测不成`不是`回退`

**症状**（方案 16 C-08）：CI 上 `cli verify` 一片绿，可这一轮其实**什么都没验**
——分诊表没给（同桶清零那一条打印 `n/a`），软维度全是 `ungraded`，
两轮快照还是同一个版本号；反过来，工具缺文件、切分变了，
脚本把它当「回退」报出来，人去查 rubric 查半天。

**根因**：`verify` 的结论是**三态**，而且退出码与结论**不是一对一的**。
`pass` / `fail` / `not_evaluable` 都可能被压成一个布尔，
`1`（判据没过）与 `2`（输入不可比）也都能被压成一个「非 0」——
两次压缩都发生在**调用方**，工具自己没做错。

**纪律**：
- **`not_evaluable` 不算通过**：判不了的判据必须显示 `n/a`，且要求判据的
  那几条上它是**驳回**不是通过。CSV/CI 摘要里看见 `n/a` 就当没测
- **退出码 1 与 2 分开报**：`1` = 这次改动不行；`2` = 这次根本比不了
  （schema 版本不同、两轮切分不一致、键对不上、缺文件）。**2 写成 1，
  工具故障就被读成回退；1 写成 2，「不行」就被读成「待重试」**
- **两轮必须是同一份切分**：拿重冻结之前的版本当基线必退 2（报「N 行
  （M 条判定）在两轮之间换了档」），不会假装有数
- **同一版本对同一版本必然全 0**：快照里的 `pred` 是**冻结行上的旧判定**，
  不是当轮重算。想测「改评估器 → 重采集」现在**判不了**（配对键只有
  `(golden_id, dimension)`，重采集换了 run id 就配不上）——
  看到全 0 别当「重跑一遍更好」，也别当「评估器没生效」
- **闸门（`calibration.gate`）的触发点是 freeze，不是 push**：同一条「pred 来自
  冻结行」的理由，按 push 跑的门永远红 ⇒ 会被绕过。它另外三条预检也是退 2：
  **首版没有基线**（不拿"首版"当通过）· **基线与本轮同版**（不是比，是没比）·
  **两版之间跨了一次切档**（提示"第一对可比的是本轮与它的后继"）

→ `evaluation/calibration/verify.py`（`_gate` / `_criterion_bucket` / `main` 退出码）·
`evaluation/calibration/gate.py`（`resolve_versions` 三条预检 · 每次重算出快照）·
`tests/unit/test_calibration_verify.py` · `tests/unit/test_calibration_gate.py` ·

### 8.19 分诊桶贴错，下一步就改错地方：`other` 筐把「新失败模式」藏起来

**症状**（方案 16 C-05）：某批分歧全被贴成「评分器逻辑错」，于是连着三轮改
评估器代码，分歧一个没少。真相是这些分歧属于**另一种失败模式**——rubric 里
根本没写这一类（`rubric_missing`），改代码永远改不到。或者反过来：所有贴不
进去的卡被顺手扔进一个 `other` 筐，三个月后没人说得清那 40 张卡是什么。

**根因**：桶名**不是分类标签，是派工单**——它决定**下一轮谁去改**
（代码 / prompt / rubric / 黄金集 / 采集）。两种错法的代价不对称但都很大：
**贴错桶** ⇒ 改错地方、白烧一轮，且下一轮分歧还在，看起来像「改不动」；
**加 `other` 筐** ⇒ 新失败模式被静默收纳，永远不会被当成「该扩表」的信号。

**纪律**：
- **六桶封闭集，没有 `other`**，封顶就在 `buckets.py` 的 import 期检查
  （加第七桶必须改 `MAX_BUCKETS` 并写清前置事实，改不动就是不该加）。
  **贴不进去 = 需要扩表**，不是需要临时筐
- **每桶都有前置事实**（`BUCKET_PRECONDITION`），写清「什么不算这一桶」。前置
  事实不成立就**换桶或降级为 `unresolved`**，不硬贴——桶名是结论，定义里带前提
- **`accepted_exception` 是状态不是桶**：桶说「该谁改」，状态说「这轮先放过」。
  混成一个字段，就会出现「因为先放过所以不归任何人」的死角
- **`rubric_*` / `gold_defect` 只能人填**（D-C3）：rubric 与金标是**判断的标准
  本身**，由 agent 来定等于让它自己出题自己判。agent 只能往卡上写建议值
  （`suggested_*`），**分诊表的路由按机器身份拒写**——不靠 prompt 里叮嘱
- **签名与证据都是必填**：`--by` 是谁下的判断，`--evidence` 要写清「为什么是
  这个桶、为什么不是别的桶」。匿名的桶和没贴一样不可追溯

### 8.20 机器建议被当成裁定：`suggested_bucket` 抄进 `bucket` 之后，归属比例就再也算不回来了

**症状**（方案 16 C-06）：工作表上机器已经预填了「建议 `evidence_missing`」，
人一眼扫过去全是同一个桶，于是整列照抄签名。三周后 C-07 出「rubric 缺陷 vs
评估器缺陷」比例——**这个比例其实是在描述这台机器的规则，不是这批数据**。或者
反过来：预填把 21 张「机器判不了」的卡也硬塞了一个桶，人的判断被这个桶锚住，
本来该贴 `rubric_ambiguous` 的贴成了 `evaluator_logic`，于是下一轮去改代码。

**根因**：`suggested_*` 与 `bucket` 是**两种东西**——前者是机器能确认的事实加上
至多一条建议，后者是人签名的裁定。混成一列，C-07 的分子分母就都变成了机器的话。

**纪律**：
- **worklist 行里没有 `bucket` 这个键**（不是留空）。建议只落 `suggested_*`，
  裁定那一栏只存在于分诊档，唯一写入口是 `triage.validate_rows`
  （`tests/contract/test_rubric_traceability.py` 用 `inspect.getsource` 钉住）
- **能预填的桶只有 `evaluator_logic` / `evidence_missing`**（§11.2）。注册表里
  出现 `rubric_*` / `gold_*` 时**导入即炸**——不是"记得别那么干"
- **预填要有证据原话**：规则命中时返回的是证据里那句话（"采集降级" / "未选中该
  站点"），人在确认时核的正是那句话。返回 `True` 的规则等于让签名变成橡皮章
- **机器判不了就写「判不了」**：没有规则命中 / 两条规则指向不同桶，一律
  `suggested_bucket = null` 并在 `needs_human_reason` 里说清原因。**不要为了
  覆盖率好看去凑一条建议**——「`evaluator_logic` 当前没有规则」是结论不是遗漏
  （能确认的只有"prompt 桶不成立"，够不着"一定是代码判据"）
- **建议与裁定分开记**：分诊档保留 `suggested_bucket`（人当时看到的那个值），
  事后重算会漂 ⇒ C-07 只能用当时那份算「接受 / 改判」
- **半填的工作表整批拒**，不做"填几行写几行"：那种行为让覆盖率看起来在涨，
  涨的只是填表耐心

### 8.21 改一条款顺手动了别处：「未列条款逐位不变」印了 ✓，其实一条都没比

**症状**（方案 16 C-12 / C-18）：改 `D-5` 的措辞，本意只改这一条，但锚点分档
一起动了（`D-5` 的三档边界挨着改）。两版快照一比，`audit` 报「未列条款逐位
不变 ✓」——**因为受检条款上一条配对条目都没有**，那个 ✓ 是空跑出来的。
另一种：变更记录表里写「只把动作空间文字对齐 `actions.TOOLS`」，读起来像
无副作用，但**没写清「哪些条款分数不变」**，事后没人能机械证明，
只能信这句话。第三种：以「评估器做不到」为由改 rubric——改了三次之后
rubric 变成迁就当前评分器的形状，而没人记得它原来是为什么那么写的。

**根因**：`rubric` 改动**同时改的是三样东西**——判断标准、评分器、黄金集分数。
不把「预期影响面」写成可机械校验的形态，就只剩「我记得我只改了一条」。
而「0 条样本 ≠ 一切正常」在这里最难看出来：守卫跑成功了、退出码 0、
还印了个 ✓。

**纪律**：
- **改条款时，变更记录表必须加一行**（九列）。`条款` 列写的就是**允许动的集合**
  ——`audit` 拿它当白名单，没列的条款分数一动就退 1；
- **`预期效果` 列要写成可证伪的**：要么带一个数字或比较方向（`→` / `<=` /
  `≥`），要么明写「逐位不变 / 零变化」。写成「让判断更准」这种 → `check` 退 2。
  **本条改动的预期效果必须能对上 `audit` 的输出**；
- **`分歧卡` 列必须能指回卡号**（`v7:P000__r1__h:d10`，`check --verify-cards`
  核存在性）。以「评估器做不到」为由的改动**直接驳回**——那是 `evaluator_*`
  桶的事，不是 rubric 的事；rubric 侧只允许因 `rubric_ambiguous` /
  `rubric_missing` 改；
- **`责任区分声明` 列要写「判不了的情形」**：说清这次改动在什么情况下仍判不了、
  那部分归谁。只写「已修复」的声明是不可复核的；
- **`0 条样本 ≠ 一切正常`**：`audit` 单列 `measurable`，判据是「受检条款上真配上
  了条目」。`freeze --from-version` 把行原样带过来时（两版分数完全一样），
  这个守卫退化成空跑 ⇒ **退出码 2，不许印 ✓**；`check --verify-cards` 同理——
  表里一条卡号都没有（1.3 之前的行全是 `—`）时印「没有任何卡号可核」，**不印 ✓**；
- **追溯是前向的**：`TRACEABLE_SINCE` 之前的老行允许 `分歧卡` 填 `—`，
  从那一版起必须指回卡。**不伪造历史**——补一列假卡号比留 `—` 更糟。

### 8.22 触发读数看着挺像结论：「分歧率 0%」其实是「一条都没判过」

**症状**（方案 16 C-16）：跑 `triggers` 想看「有没有问题条款」，屏幕上只有一行
`T-1 D-10 分歧率 3.4%`，读起来像「分歧很小，还行」。其实那 **128 条里 121 条
是 `ungraded`**——黄金集软维度金标一条没填，评分器对它们根本没判过，`n` 被算成
了 7。另一个方向：`T-2` / `T-3` 打了「测不成」，人顺手把 T-1 的数当「整体分歧率」
往外推，于是结论是「分歧不大，评估器基本跟人对齐」。

**根因**：`0 条样本 ≠ 一切正常` 在**分母**上的形态。分母为 0 时，最自然的写法是
`rate = 0`，而 `0` 和「真的没有分歧」在报表上长得一模一样。第三种形态：T-1/T-4
按 `rubric_ref` 读，而覆盖不到的条款**根本不出现在表里**——只报测到的条款，
报表就会读成「五条条款都测过了」。

**纪律**：
- **`ungraded` 不进分母**，条款的 n 是**可判**条目数；`n = 0` 的条款**不出读数**
  （出 `rate = 0` 就是把「没数据」写成「零分歧」，而那正是 T-1 该抓的东西）；
- **`coverage` 单列**：报告顶上把「一条都判不了」的条款连 `ungraded` 条数一起喊
  出来。v7 真实读数是 **4 个条款一条都判不了**（D-2 18 条 / D-4 89 / D-5 90 /
  D-6 45），只有 D-10 有数；
- **阈值列为空就不许判合格**：D-C9 是「读数先行」——报告里 `judged` **恒为
  `None`**，命令行第一行就印「本命令不判合格/不合格」。T-1 里那个
  `over_candidate_line` 写的是「**按候选线**会不会越」，不是「越了」；
  唯一 `line_set=True` 的 T-2 也只标「低于已有上岗线」，**不标合格**；
- **一条都测不到就退 2**（不是 0）。退出码里**没有 1**——本命令没有「合格」这个
  结论可给，退出码 1 会被读成「驳回」；
- **测不成要说清缺的是哪一种**：「软维度金标 0 条」与「judge 逐行 pred 不落盘」
  是两个工程，补错那个等于白干。`--judge-report` 的行**缺 `golden_id` /
  `dimension` 直接退 2**——按 `sample_id` / url 猜键会让 kappa 建在配不上的
  分母上，而 kappa 对配对样本量极敏感。

### 8.23 分层抽样凑够 40 条：「缺口」拿别的层补齐，看着齐了其实同质

**症状**（方案 16 C-19）：跑 `sampling` 想要 40 条人工判读清单，S2、S3 两层抽不
到（总体都是 0），于是从 S1 多抽 20 条补齐，报表上「40 / 40 ✓」。判读的人打开
清单：40 条全是 D-10 分歧，`sample_weight` 一列全是同一个数，看着像随机抽的 40 个
样本——其实 33 条来自同一个 33 条的分歧池，只抽了 30 条。「分层抽样」这个词已经
废了，而报表上看不出异常。

**根因**：配额是**设计**（D-C10 拍板 10×4），缺口是**事实**（判读盘里就没有那两类
样本）。补齐把事实改成了设计，于是缺口这条读数被抹掉了。同一族的第二个形态：
`random.sample` 抽出来的「固定种子样本」换台机器/换个 Python 版本就变，而冻结档
要的是复算得出来。

**纪律**：
- **缺口如实报，不补**：`_draw` 只在**本层**候选里抽，不足就少给并写进
  `short_by`。`render` 顶上印「实抽 N 条（缺口 M）」。⚠️ **抽不满不是 bug、
  也不许凑**——v7 的真实读数就是 **S1/S0 各 10 条、S2/S3 各缺 10**；
- **可复现靠「固定种子 + 稳定排序 + SHA-256 定序」，不用 RNG**：`random.sample`
  的实现细节跨 Python 版本可能变。**同一输入两次抽样逐行相同**（有测试封着）；
- **一条只入一层**（优先级 S1 → S3 → S2 → S0），层间重叠**写进报告** `overlap`
  ——重叠是事实，藏起来就成了「四层互斥」这个假前提；
- **层内读数不外推总体**（D-C10）：`sample_weight` = N_h / n_h，说的是「**这条
  有多重**」，**不是**总体估计量。拿它当权重把 40 条推成「分歧率 25.8%」就是
  外推；
- **`0 条样本 ≠ 一切正常`**：一条都抽不到（档位选错、或该档无可判条目）→ **退 2**；
- **`sample.jsonl` 不覆盖 `worksheet.jsonl`**：前者是判读**谁**的清单，后者是
  分歧卡的判读表，是两样东西。

### 8.24 工作表上那句「证据」不是现场：照着它判桶，判的是解读不是页面

**症状**（方案 16 C-06 补读现场）：打开 `worksheet.jsonl`，`pred_evidence` 那一栏
写着「存在 `<video>/<audio>` 标签 ×6（iframe=10）——代码层事实，不问 LLM」。
判读的人据此贴桶：站点上有 6 个 video ⇒ **代码判得没错** ⇒ 贴
`gold_defect`（金标错了）。全批 21 张卡里有 4 张这样贴过去——**全贴到了同一个
桶，而那个桶是错的**。真正的原因在存档里：那个页面是**网易号美食图文**，
6 个 `<video>` 是**点击广告链接之后**被注入的广告（正文里多出「烈焰觉醒…立即体验
广告 ✕」），代码短路把广告视频当成了播放器。

**根因**：`pred_evidence` 是**存档被解读后的产物**，不是存档本身。D-10 的判据
原文是「对照黄金集**预存档**的站点核验结论」——**预存档不在表里**。拿一句被解读
过的话当现场，等于判「解读对不对」而不是判「结论对不对」；而解读这一步恰恰就是
被审的那一步。

> ⚠️ **2026-10-23 · M-26 补记**：那句 evidence 的**成因**（媒体计数短路）
> **已修**——④ 现在一律问 LLM，媒体计数不再许诺成功。但**历史存档里的旧
> evidence 不会变**（存档冻结，不回填历史）⇒ 表上**仍可能读到**「代码层事实，
> 不问 LLM」那句话。**看到它要记住的是「这批存档跑在旧代码上」**，不是
> 「现在的代码还这样」。⚠️ 另外：计数经**提示词**仍进模型（见台账 §Q-13），
> 所以**同一页面的新判定未必与旧 evidence 一致**。

**纪律**：
- **现场要进表**：`worklist build` 把现场读数写进工作表**每一行的 `scene` 栏**
  （页面标题 / 每步观察 / 正文预览 / 定位说明）。**人填的那张表里没有现场，
  「该归哪个桶」就答不了**——那不是「人不肯判」，是表里没有可判的东西。
  想一屏看完一条卡（现场 + 尺子 + 两侧）再用 `worklist show --golden-id <ID>`；
- **`scene` 的 `status` 分四态**（`located` / `located_no_steps` / `not_found` /
  `not_read`）：**「没找到」与「没去读」归成一个布尔**，就分不清是「存档里没有」
  还是「压根没查」，而这两种的修法完全不同；
- **正文要标出来自第几步**（`body_from`）：正文常来自**更早**的一步（最后一步
  常常是没读到正文的那步），不标出来，人会默认是最后一步——于是读到一个不对的
  页面的正文；
- **`scene` 是只读上下文，不进分诊档**（`triage.strip_row` 只留裁定字段）——它
  是「判这一条的依据」，重算会变；抄进裁定档就等于让今天的裁定引用着下一版的
  观察；
- **尺子分两处写着**：D-10 说「结论与 ground truth 一致」（比**什么**），「该给哪个
  分支标签」在 **D-5 决策树**、「什么算播放组件」在 **D-4**。只给 D-10，人就
  拿不到尺子。尺子**另外落一份** `v{N}/clauses.md`——**同一把尺子**每行各带一份
  会让同一个文件长 N 倍；
- **条款原文从 rubric 文档现读**（不抄第二份到代码里）——抄一份必然漂；
- **定位不到现场要说定位不到**（并存下存档里现有的单元与 url 作候选），
  **不许返回空读数**：空读数会被读成「页面里没有 video 标签」，那是把「没找到」
  当成「看到了没有」；
- **两种字段形状都要读**：P1 存档用 `body_len` / `elements_total`，P2 样本用
  `body_chars` / `interactive_elements`。只认一种 ⇒ 另一种读成空值，而空值会被
  读成「页面是空的」。

### 8.25 答案算出来了，却没落到产物上：**定义了没人调用 = 等于没答**

**症状**（方案 16 C-11 补齐，2026-10-24）：「存量 pred 是哪版评分器打的」这条
问句有了完整答案——`pred_comparability()` 给三态、`pred_comparability_reason()`

可**没有一处产物把它带出来**，于是「答不出来」这件事在报表上**一个字都没消失**。

**根因**：**「算」与「给出去」是两件事**。函数是**能力**，产物是**答案**——
中间那根线（谁把结果写进谁）没人画，就断在那儿。而且它**不报错**：函数存在、
测试绿、变异红，**每一项检查都通过**，只有「人打开产物读答案」那一步是空的。

> ⚠️ **同一族**：本仓库已经记过两个同形的坑——「变异压根没生效而全绿被读成
> 守卫无效」（§7.5）与「注释说『旁路生效』，代码早就把它退役了」（§8.15）。

- **答案要落在人看的那张表里**：分歧卡（`disagreements.jsonl`）上写 `pred_comparability`

- **「没人调用」要当 bug 看**：新函数若**零调用方**，要么接上，要么别留（留着的
  代价是**下一个人会以为答案已经给出去了**）；
- **接线本身要有守卫**：光有「函数算得对」的测试不够，再加一条「**产物里必须有

  `可比性结论不写进卡` · `可比性理由不写进卡` · `可比性没走到工作表`；
- **「多出来的那一栏」也是口径**：字段名要跟值对得上——本轮顺手抓到

  `distinct_fingerprints` 同值），**行数 ≠ 指纹数**：v9 起行里真会记版本，

### 8.26 用 `.get()` 判断「这一格填过没有」：人判的「判不了」写不进去，也拦不住覆盖

**症状**（软维度金标写入链，2026-10-24）：`merge_dimension_scores` 第一版这样判
「这一格之前判过没有」——`old = previous.get(dim)`，然后 `if old is not None` 才算
「已填」。`{"d5": None}`（人判**判不了**）于是被当成 `{}`（**没填**）。两个后果，
**都不报错**：

1. **写不进去**：变化检测是 `all(previous.get(d) == v for d, v in patch.items())`，
   而 `{}.get("d5") == None` **恰好等于**新值 `None` ⇒ 判定为「没变化」⇒ 幂等跳过。
   人填了 `null`，`annotations.jsonl` **一个字没变**，而命令打印「无变化（幂等跳过）」；
2. **拦不住覆盖**：`old is not None` 不成立 ⇒ 改判检查整段跳过 ⇒ 别人拿 `4` 覆盖
   人判的 `null` **不需要 `--force`**，也就**不留痕**。

**为什么测试才会发现它**：这两条路径**纸面上都对**——「判不了也算判过」和
「`.get()` 拿值」各自都读得通。写完第一轮测试时**四条同时红**，红的全是
「人判的 `null` 不见了」，才看出是**同一行**的锅。

**纪律**：
- **「有没有判过」看键在不在，不看值**：`dim in previous`，不是
  `previous.get(dim) is not None`。三态（没填 / 判不了 / 分数）**永远是三个**，
  用两个值表示它必然塌成一态；
- **`dict.get` 的缺省值不是「空」**：缺省 `None` 会让「键不在」与「键在值是 null」
  **无法区分**——凡是**值域里含 `None`** 的字段，`.get()` 就是**错的判据**（同族：
  `None` = 「判过，判不了」 vs 缺席 = 「没看过」，本仓库的两套 API 都按这个口径写）；
- **同一份语义要在三个地方一致**：写工作表（`state`: `to_fill`/`filled`/`judged_na`）、
  导入（`merge`）、算覆盖率（`coverage` 的 `filled`/`judged_na`/`empty`）——
  三处若有一处用两态，那处就会和别人对不上，而且对不上的表现是**数字偏小**；
- **顺手把「省掉整栏」也判成错误**：`{"golden_id": ..., "dimension": ...}` 缺
  `gold_score` 键，会被 `.get()` 读成 `None` ⇒ 半张表被**静默写成一堆 `null`**。
  直接抛，并说清「没填的格子写空串，别整栏省掉」。

### 8.27 填完金标顺手比一版：读到「净改善 +N」，而那 N 是**尺子换了**

**症状**（软维度金标写入链，2026-10-24）：`dimension_scores` 一直空着，填完、
`freeze --refresh-gold` 出 v9、跑 `gate` 比 v8 → **净改善 +N**，报告结构完整、

——它长得跟一次真的改善一模一样。

**根因**：**金标是尺子，不是被测对象**。跨版本比较的前提是「同一把尺子」，
而填金标恰好**换了尺子**。同族的老坑：切档（C-17）、换 rubric 版本、改阈值
——凡是**量具**变了的，前后都不可比。

**纪律**：
- **金标变动 = 新基线**：`freeze --refresh-gold` 在 manifest 落
  `gold_refresh.baseline_reset=true`，`gate.assert_gold_comparable` 读到就**退 2**
  并明说「下一对可比是 vN → vN+1」——**不靠人记得别比**；
- **退 2 不是退 1**：这不是「驳回」（判据没过），是「**没比**」（输入不可比）。
  混成 1，「尺子换了」就被读成「回退了」；
- **新基线是可比对的**另一半：`v7` 重挂过金标、`v8` 没重挂 ⇒ `v7 → v8` 正是那一对。
  判定只看**本轮**的 manifest，不看基线——否则新基线永远比不了任何东西；
- **顺带一条 CLI 常识**：`builder` 的 `--golden-root` 是**顶层参数**，要写在子命令
  **前面**（`builder --golden-root X freeze …`），写在后面 argparse 直接
  `unrecognized arguments` 退 2——但那时**已经晚了**：看起来像「冻结失败」，而原因
  是参数位置。

`evaluation/golden/builder.py`（`_refresh_gold` 落 `baseline_reset`）·
`tests/unit/test_calibration_gate.py`（`test_金标重挂过就是新基线_与前版不可比` ·

### 8.28 填金标时按「看起来像」分档，而不是按锚点原文分档

**症状**（软维度金标填表，2026-10-24）：交付的判读口径写「懒加载页直接判『有』按
4 档、直接判『无』并排除按 3 档」，人照着填 91 行 D-4；而锚点原文写的是
「[3] **2 处**该给未验证却给了确定结论／[4] **1 处**应判未验证却直接给确定结论」
——判「有」与判「无」**都是 1 处** ⇒ **两处都该按 4 档**。
**报告上完全看不出异常**：分数仍是 1–5 的合法值、导入照样过，差别只在**档位分布整体偏一档**。

**根因**：档位不是「按现象归类」，是**按锚点原文的计数条件**。
「3 档」不等于「判『无』的那档」、「4 档」不等于「判『有』的那档」——
两者差的是**处数**（2 处 vs 1 处），**不是方向**。
**方向换了、处数没变 ⇒ 档位不变**。交付口径是**转述**，转述会掉承重信息（本次就掉了「处数」）。

同族的两条（一起在这次对账里查出来的）：

- **覆盖面被口径窄化**（D-5 写成「六节点」）：实测 **12 种分支**、**62 条落在负样本
  分支上** ⇒ 按「六节点」表填，这 62 行会因「找不到对应节点」被写成 `null`（判不了），
  **覆盖率永远上不去，而表看上去是填满了**；
- **底料比 pred 新**（P1 存档被人工 relabel 过、快照没更新）：**7/91 条 D-5** 的
  `pred_branch` ≠ 存档 `branch`，其中 **3 条机器给了 5 分** ⇒
  **「机器打了 5 分」≠「底料没变」**。

**纪律**：

- **档位只从 `anchors` 读，不从「现象描述」读**——`anchors` 是 rubric 原文**现读**
  （`rubric_tier_text`），交付的判读表是**转述**，转述必掉信息；
- **「不适用」不是档位**：落在负样本分支上的样本**同样按 1–5 判**
  （核「该不该落这条分支 + 前置事实成不成立」），不是「不适用」、不是「判不了」；
- **以存档为准**：底料与快照对不上时核存档，并在 `gold_note` 写明「底料已 relabel」；
- **填表前对一遍口径**：四处口径更正 + 七条必核清单见
  [07 手册 §7.2/§7.5](../07-人工复核与判读手册.md)。
