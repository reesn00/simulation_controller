## 0. 速览

### 0.1 一句话

**把「训练轨迹数据 / LS 上传的合成数据 / 黄金集数据」三处的交付粒度，从
「一个决策单元一条」改成「一个任务一条」，同时**一个字都不动**测量口径
（D-10 的分母、档位、rubric 全部逐字可比**。**

### 0.2 为什么要拆成**两条轴**（本方案最关键的一步）

改造前，**一个概念**同时承担了三件事：**交付粒度**（给训练/上传的形状）、
**测量单元**（D-10 在哪个粒度上算）、**标注单元**（人在 LS 上判什么）。
per-Run 改掉第一件（交付粒度）；**第二件（测量）一个字都不动**；第三件要**分开
说**——

- **已有的 306 条人核标注不能改写**：它们判的是「这个站点是不是播放站」，
  那是**站点级的事实**，重写成轨迹级就是**改写人核数据**；
- 但**以后**的人核单元**可以是轨迹**（裁定 ④）⇒ **站点级与轨迹级并存**，
  **两种粒度两个 LS 项目**。

⇒ 本方案的核心主张：**交付粒度与测量口径分开记账。**

| | 改造前 | 改造后 | 谁在读 |
|---|---|---|---|
| **交付粒度**（数据集的形状） | 决策单元（`__search` / `__site-N`） | **一条轨迹** | 训练侧 · LS 上传 · `trajectories.jsonl` |
| **测量单元**（D-10 的分母） | 站点 | **站点**（不变） | `cmd_agreement` · `snapshot` · `calibration` |
| **标注单元**（人判什么） | 站点 | **站点（历史口径）** + **轨迹（新口径）** | LS 项目 · `annotations.jsonl` |

**为什么不能顺手把测量单元也改成轨迹**：D-10 的头条分母是 **106/128 = 82.8%**，
那是**绑定口径**（门禁只读调参池，分母薄不是改口径的理由）。按轨迹重切档，
分母整个换掉 ⇒ 历史读数全部作废 ⇒ 门禁自证为空。

⇒ 落地形态：**两层黄金集**。测量层 = **一个字不动的**站点级冻结档（三档切分文件）；
数据集层 = **新增**的轨迹级 `trajectories.jsonl`（一条轨迹一行，站点明细收在
`site_outcomes[]` 里，每条带自己的 `split`）。

### 0.3 三条不做（越界即架构回退）

1. **不重写人核标注。** 站点级 306 条标注的**键一个不改**（口径 C 的 url 键集合与
   历史**逐字相同**）⇒ 人核数据只**换挂载位置**（挂到轨迹行的 `site_outcomes[]` 里），
   **不换判断内容**。
2. **不动测量层。** 三档切分文件（`calibration.jsonl` / `regression.jsonl` /
   `holdout.jsonl`）**一个字都不改**⇒ D-10 的读数与历史逐字可比。
3. **不 import 存量。** 新代码全在 `trajectory_pipeline/` 内；跨层共享走**顶层纯包**
   （`outcomerules/` / `toolcatalog/`），不靠 Python 导入边。

| 量 | 读数 |
|---|---|

| 人核标注 | **306** 条（站点级 294 + 历史 per-unit 占位 6 + 负样本 6） |

### 2.2 访问点与 outcome 的配对口径会分歧（**为什么要口径 C**）

P2 的访问点用**逐档配对**取自己的 outcome（候选 → 落地 → 播放页，每档匹
`site_url` 或 `url`，同档取末条）；候选集原来用「同 url 一律取末条」。

> 实测：**79/1386 个访问**上两套口径给出**不同的 outcome** ⇒ 候选行的 `code` 与
> P2 访问点的 outcome **对不上** ⇒ 「这个站点是轨迹里哪一段」没法答，
> 而 D-5/D-6 打分打的就是那一段的观察。

**三套口径的 url 键集合（`per_run_site_key`）**：

| 口径 | 键集合大小 | 与 A 的差 | 306 条标注挂得上 |
|---|---|---|---|
| **A**（同 url 取末条，历史现行） | 1512 | — | 283/294 |
| **B**（只取被访问点配到过的） | 1307 | A−B = **205**（B 会丢 205 个键） | **211/294**（丢 83） |
| **C**（访问阶段优先 + 孤儿兜底） | 1512 | **A−C = 0，C−A = 0** | **283/294**（与 A 逐字相同） |

⇒ **取口径 C**：键集合与历史**逐字相同** ⇒ **306 条人核标注一条不丢**；
而 B 会丢 205 个键 ⇒ **83 条标注挂不上**。

⚠️ **键不变、内容变**：同一个 url 的 pred 侧可能从「同 url 末条」换到
「访问点配到的那条」。**已冻结的版本不受影响**（冻结档存的是冻结当时的行），
只有**新建**的版本会带上新口径。

|---|---|

| 只有 calibration | 7 |
| 只有 holdout | 5 |
| 只有 regression | 5 |
| calibration + holdout | 3 |
| calibration + regression | 1 |
| holdout + regression | 1 |

⇒ **一条轨迹没有单一档位**。档位决定的是「**能不能进金标**」（裁定③：holdout 的
裁定不进金标；C-17：回归集不得改动）⇒ 必须有一个确定的口径。

**⭐ owner 2026-11-01 裁了：按「头部站点」定档**（裁定② 的末条结论所在站）⇒
**档闸用 `rows.headline_split`**（取严口径 `strict_split` 保留作**对照**）。
**两条口径的读数**：

| 口径 | calibration（唯一可进金标的） | regression | holdout | 定不出档 |
|---|---|---|---|---|
| **② 头部站点（现行档闸）** | **13** | 13 | 15 | **9** |

  ⇒ 定不出档）⇒ 「补数据」补的就是这 5 条。

⇒ **头部站点认不出 ⇒ fail-closed 不放行**（`split_unresolved`）——「定不出档」
当成「没有限制」恰恰是**最不该放**的那种情况（解不出来的那条往往**沾着封存面**）。

### 2.4 同轨标签互相冲突（**为什么轨迹级标签必须人填**）

> `per_run_golden_shape`：50 条轨迹里 **28 条**的站点级标签**互相冲突**
> （例：`TPIN02__1cf5deca` 16 条站点标注出现 9 个不同标签：
> `broken` / `login_wall_or_blocked` / `no_play_control` / `not_play_site` /
> `subscription_wall` / `success` / `trailer_only` / `unreachable_hard` / `player_unverified`）。

⇒ **轨迹级标签不能由站点级标签推导**（那是投票，CLAUDE.md 明令禁止）⇒
**必须由人在 LS 上逐条判**（裁定④）。

### 2.5 迁移的落点分布

| 情形 | 落点 | 依据 |
|---|---|---|
| 旧 per-unit 标注，`label == unresolved`（**判不出来**） | **轨迹级** `{task}__{run}` | 单元级没给出任何判决 ⇒ 收成「这条轨迹也没判出来」，人核的这句话**一个字不动** |
| 旧 per-unit 标注，label 是实打实的分支 | **站点级** `{task}__{run}__{url_hash}` | 这个判决说的是**那个站点**（实测 `E001__57bbf995__site-2` 的 round 2 = `subscription_wall`，说的是 vip.1905.com，而那条轨迹的末条结论是 `unresolved`）⇒ 落回它自己的站点行，**不许冒充整条轨迹的结论** |

⚠️ **round-2 是 retest（D9 的一致性复测），不是金标** ⇒ 迁移只动 round=1。
round 2 的 `subscription_wall` 那条**被挪了位置**（站点级），**不是被合并掉**。

## 3. 架构：两层黄金集

```
output/pipeline/                       ← P1 存档（一份 Run 一个 json）
   T001__67a05faa.json
        │
        ▼  assembler/schema.py::split_archive  （0 或 1 条）
trajectory_pipeline/output/pipeline/samples/
   T001__67a05faa.json                 ← P2 样本（**一条 = 一条轨迹**）
        │  sample_id = <task>__<run>   （与 P1 存档名逐字相同）
        │  outcome     = 任务级结论（裁定②：末条）
        │  site_outcomes[] = 逐个访问点的结论（带 step 区间）
        ▼
   ┌────────────────────────────────────────────────────────┐
   │ 训练侧 P3（views.py）· T 视图（task_view.py）           │
   └────────────────────────────────────────────────────────┘
        │
        ▼  evaluation/golden/builder.py::cmd_candidates
golden/data/candidates.jsonl           ← **轨迹级**（一条轨迹一行）
   {golden_id: "<task>__<run>", source_kind: "trajectory",
    site_outcomes: [ {golden_id: "<task>__<run>__<hash>", split: "calibration", ...} ],
    splits: {calibration: 2, holdout: 1}}
        │
        ├─► golden/data/v{N}/{calibration,regression,holdout}.jsonl
        │      ↑ **站点级**（D-10 的测量底座）——**一个字不动**
        │
        └─► golden/data/v{N}/trajectories.jsonl
               ↑ **轨迹级**（一条轨迹一行）——交付层
```

### 3.1 行形状的唯一真源：`evaluation/golden/rows.py`

两层并存 ⇒ 每一行都得能回答「我是哪种形状」。**判据是结构，不是 `source_kind`**：

```python
is_trajectory_row(row)  ==  ("site_outcomes" in row)
```

结构判据对手写/迁移过来的行同样成立，而 `source_kind` 可能被改过。

| 函数 | 作用 |
|---|---|
| `trajectory_id(task, run)` | `{task}__{run}`——与 P2 的 `sample_id` **逐字相同** |
| `is_trajectory_row(row)` | 结构判据（上面那行） |
| `site_rows(row)` / `expand_site_rows(rows)` | 摊平成**站点视图**（测量层读的就是这个；键与旧的站点级行逐字一致） |
| `site_ids_of(row)` | 这一行涉及的站点级 id 集合（**孤儿门禁**用） |
| `index_site_entries(rows)` | 站点级 id → 明细条目（`_refresh_scores` 重挂 pred 侧用） |
| `headline_site(row)` | 给出轨迹级结论的那一个站点（按 `outcome_index` 对齐 `code_index`，**不按分支值猜**） |
| `headline_split(row)` | **这一行的档**（头部站点口径 · 档闸的**第一步**；认不出 ⇒ `""` ⇒ fail-closed 不放行） |
| `non_reflow_splits(row)` | **这一行沾着哪些「不许回流」的档**（封存面 / 回归面）⇒ 档闸的**兜底第二步**（owner 2026-11-01「泄露做兜底」） |
| `row_splits(row)` / `strict_split(row)`（**对照**）/ `splits_within(row, allowed)` | 档位（见 §4） |

⚠️ **`source_kind` 的新取值**：轨迹级候选行是 **`"trajectory"`**，**不是 `"p2_sample"`**。
旧的 `p2_sample` 行是「per-unit 轨迹占位」（没有 url、没有现场、label 恒为
`unresolved`）；per-Run 之后那种行**不存在了**，轨迹级行是**有站点明细的轨迹**。
继续叫 `p2_sample` 会让「D-10 只算 `source_kind != "p2_sample"`」这条判据
把带金标的轨迹级行**一起排除掉**。

## 4. 档位策略：分档仍是站点级，跨档按**头部站点**定档（owner 2026-11-01 裁的 ②）

### 4.1 分档**留在站点级**（不动测量层）

每个站点自带 `split`；轨迹行顶层是 `splits`（各档计数）。**任何问「这一行属于哪一档」
的代码都必须先过 `rows.headline_split`**（头部站点口径），不许拿顶层 `__split__`
硬读（轨迹行压根没有这个键）。

### 4.2 头部站点口径（**现行档闸**）vs 取严（**对照**）

⭐ **owner 2026-11-01 裁了「按头部站点定档」**（裁定② 的末条结论所在站）⇒
**档闸用 `rows.headline_split`**；取严口径 `rows.strict_split`
（`STRICT_ORDER = ("holdout", "regression", "calibration")`）**保留作对照**。

**头部站点怎么认出来**（不猜）：`rows.headline_site` 按**记账下标**对齐——
`site_outcomes[].outcome_index == code_index`（`code_index` = 末条 outcome 的
下标 ⇒ 两者**同一坐标系**）⇒ 认不出就返回 `None` ⇒ `headline_split` 返回 **`""`**
⇒ 调用方**必须**当「定不出档 ⇒ 不放行」处理（fail-closed）。

⚠️ **取严那条为什么曾经更严**：它按「这条轨迹**沾没沾封存面**」判——
holdout > regression > calibration ⇒ **沾上就是不许回流**。⚠️ **封存面连「人看过」
都不该发生**（D-C5：只在最终验收跑一次）⇒ 「宁可少回流，不许错回流」。

⚠️⚠️ **裁 ② 的代价照实记**（2026-11-01 逐条核对 v16 实测，走产品代码路径）：

| | 取严（对照） | **② 头部站点（无兜底）** | **② + 兜底（现行档闸）** |
|---|---|---|---|
| 够格进金标 | **7** | **13** | **2** |
| 与取严的**交集** | — | **只有 2 条** ⇒ **换了一批数据**，不是「放宽」 | **2** ⇒ **⊂ 取严** |
| 放行批次里**含 holdout 站点**的 | 0（按定义） | **11/13** ⇒ **封存面泄漏面 11/13** | **0**（兜底挡掉了） |
| 放行批次里**含 regression 站点**的 | 0 | 9/13 | **0** |
| **判死**的「纯 calibration」轨迹 | — | **5 条**（头部站点的访问点没进冻结集 ⇒ 定不出档） | 同样 5 条（**被 fail-closed 挡，不是被兜底挡**） |

⇒ **要改口径就改档闸那两处**（`evaluation/golden_ls/reflow.py` 的
`build_worksheet` 与 `validate`），**别散着改**。

⭐⭐ **兜底（owner 2026-11-01「泄露做兜底」）**
-------------------------------------------------
**两道闸，顺序固定**：

1. **定档**：`headline_split(row)` ⇒ 头部站点那一档；**认不出 ⇒ fail-closed
   不放行**（`split_unresolved`）；
2. **兜底**：`non_reflow_splits(row)` ⇒ **整条**沾着 holdout / regression ⇒
   **不放行**（`holdout_not_reflowed` / `regression_not_reflowed`）。

**为什么第 2 道不能省**：「头部站点在调参池」**不够**——其余站点里的封存事实
会跟着**轨迹级标签**一起进调参池 ⇒ **封存面作废**（裁定③：holdout 只上传、
只被人看，**不回流**）⇒ **宁可少回流，不许错回流**。

⚠️ **兜底的边界**：它量的是「**冻结集里那些站点**」的档 ⇒ 挡得住「已冻结的
封存站点」，**挡不住**「没冻结过的访问点里藏着封存事实」——那是**冻结集覆盖
不到**的问题（另一件事）。

⚠️ **头部站点口径的已知缺口（9 条定不出档）**——owner 2026-11-01 **接受这个前置
条件**：「那 9 条得先补数据」。拆开看（§2.3 的表）：**6 条是负样本池行**
（**从来就不是轨迹** ⇒ 要么补采一条真轨迹、要么排除出轨迹级数据集），
**3 条是头部站点配不到**（⇒ **给人核补标注 + 重冻**）。
⚠️ **补数据的收益照实算**：补齐这 5 条纯 calibration 的 ⇒ 放行数 **2 → 7**
（与取严齐平）；补不齐 ⇒ 现行档闸就只放行 **2/50**。

### 4.3 上传筛选：**整条推**（不是「有交集就行」）

LS 的页面摆的是**整条轨迹** ⇒ **没法只推一半** ⇒ 一条轨迹的**所有**档位都得在
本次范围内才推（`rows.splits_within`）。

## 5. Label Studio：两种粒度两个项目

### 5.1 scope 模型

| | 值 | 含义 |
|---|---|---|
| `SCOPE_SITE` | `"site"` | 一个标注单元 = 一次访问（**历史口径**，v1–v16 推上去的那些） |
| `SCOPE_TRAJECTORY` | `"trajectory"` | 一个标注单元 = 一条轨迹（**裁定④**，新口径） |

字面量的唯一真源：`evaluation/golden_ls/scope.py`（项目台账的键、label_config 的
文案、CLI 的 `--scope` 三处都从它取）。

⚠️ **两种粒度两个 LS 项目**（标题 `golden-v{N}` / `golden-v{N}-traj`）——标题相同
会让两个粒度**共用一个项目** ⇒ 两种粒度的行混在一页 ⇒ **标注员分不清自己在判
一条轨迹还是判一个站点**。

⚠️ **台账按 `(version, scope)` 建键**——只按版本查会把轨迹级的任务推进站点级的
项目里。

### 5.2 站点级的 label_config **一个字节都不动**

已推上 LS 的 v14/v15 的 `label_config_sha` 记在台账里 ⇒ 改一个字 ⇒ 事后核对会说
「配置漂了」⇒ 白推一遍。

| 粒度 | 留底文件 | sha（实测） |
|---|---|---|
| site | `label_config.xml` | `376f822addb1`（与台账里 v14/v15 记的一致，**冻结**） |
| trajectory | `label_config.traj.xml` | `c4dcb125b052`（v17–v19 项目）→ **`2a3d3c1fe49b`**（2026-11-10 起：多 ⑩ SFT 训练数据） |

两份的差别：**5 行页眉文案**（②③④ 的标题写「轨迹」而不是「站点」）+
**轨迹级多一个 ⑩ 块**。站点级九块的键一个不少、一个不改（`BLOCK_CONTROLS`
是冻结契约）；轨迹级十块（`TRAJECTORY_BLOCK_CONTROLS`）。

⚠️ **项目存的是建项目那一刻的快照** ⇒ 已有 v17–v19 项目**不会**长出 ⑩；
要用新版本号建新项目。`upload` 会核对台账 sha，对不上时**不覆盖留底**、
**不把新 sha 记到旧项目头上**（见 `golden_ls.cli._label_config_for_plan`）。

### 5.3 回流（LS 裁定 → 金标）：两个新口径

1. **档闸按头部站点**（owner 2026-11-01 裁的 ②）：轨迹跨档 ⇒ 按 `headline_split`
   取**头部站点**那一档。头部站点落在 holdout / regression 的轨迹**裁定不进金标**
   ——**显式跳过并记原因**（`SKIP_HOLDOUT` / `SKIP_REGRESSION`）；**头部站点认不出**
   ⇒ **也不进**（`SKIP_NO_SPLIT`，fail-closed），不是静默丢弃。
2. **可以「新建」**：轨迹级标注**大部分还不存在**（人核的单元刚从站点级换成
   轨迹级）⇒ 人判的第一条**没有原标注可改** ⇒ 这一行是**新建**
   （`creates_gold: true`），且**必须由人署名**（「谁定了这个标签」是人的事实）。

## 6. 迁移（`builder migrate-trajectory`）

⚠️ **动的是人核数据的键 ⇒ 需 owner 签字**（同 `cmd_rekey` 的规矩）。
⚠️ **默认 dry-run**；`--apply` 才写盘。

### 6.1 三条硬规矩

1. **禁止投票**：同一个 `(新 id, round)` 上出现**两个不同的 label** ⇒ 直接报错退出，
   把分歧摆给人看。
2. **人话不许丢**：被合并的每一行都进 `merged_notes`（原 id / 原 label / 原 note /
   原署名 / 原时刻）。
3. **只改键不改内容**：label / note / 署名 / 时刻 / 软维度分**一个字不动**。

### 6.2 落点规则（§2.5）

- `label == unresolved` ⇒ **轨迹级** `{task}__{run}`；
- 实打实的分支 ⇒ **站点级** `{task}__{run}__{url_hash}`（靠 `outcomerules.site_conclusions`
  逐档配对拿 outcome 下标 ⇒ 取 url ⇒ 算 hash）。

⚠️ **配不出来就报错退出**（不猜、不把判决挂到猜出来的站点上）。

### 6.3 配套

- **id 迁移映射表**照写 ⇒ 历史冻结档不改写，表就是两个口径之间的桥。
  ⚠️⚠️ **但迁移表与 `id_alias.json` 不是同一张表**（2026-11-01 实测踩过）：

  | 表 | 映射 | 谁在用 |
  |---|---|---|
  | `id_alias.json` | **1:1**（旧池行 id → 新池行 id） | 代码拿它给**冻结行换键**（`builder._rekey_rows`） |
  | `id_alias_trajectory.json` | **多对一**（几个旧 per-unit id → 一条新轨迹 id） | **只**给**标注**换键；**代码不拿它换行键** |

  ⇒ **合成一张 ⇒ 冻结行被按合并语义换键 ⇒ 同一个 `golden_id` 出现两次**
  （实测：holdout 里出现 2 次，且同一个 id 同时落在 calibration 与 holdout
  ⇒ 一行进两个分母）⇒ **报表上完全看不出异常**。
  ⇒ **判据**：表里的映射是 **1:1** 还是**多对一** ⇒ 决定它能不能给**行**换键。
  ⇒ 配套地加一道**主键门禁**（`builder._assert_unique_golden_ids`）：
  冻结前核「一个 `golden_id` 在整个冻结档里只出现一次」⇒ 撞了**不冻结**。
  ⇒ 详见[避坑指南 §8.46](../02-避坑指南.md)。
- **`candidates --force` 重建候选集**（轨迹级）→ **`freeze --from-version`** 冻结新版本。
- **新的冻结档与 v16 **不是**逐行可比**（键变了、粒度变了）——这是**已知代价**，
  不是回归。
  ⚠️ **2026-11-01 实测**：修掉上面那个撞 id 之后，**三份切分档与 v16 逐行一致**
  （键一个字都没变）⇒ 站点级读数（D-10 128/106/22 = 82.8%）**不变**。
  ⇒ 「不是逐行可比」说的是**轨迹级档**，**不是**说站点级测量层变了。

## 9. 一句话验收

**每条轨迹 = 一次执行 = 一把键**（`<task>__<run>`）；
**每个站点的判法 = 原来那个判法**（键集合逐字不变）；
**每个档 = 原来那个档**（分档留在站点级）；
**每次回流 = 原来的那笔账**（只多了一条：**按头部站点定档** · owner 2026-11-01 裁的 ②）。
