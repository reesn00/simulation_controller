## 0. 判定标准：什么算「对齐了」

对齐不是「功能都写了」，而是三条**可机械核**的判据。方案落地时逐条核，核不过就是没对齐。

| 编号 | 判据 | 怎么核 |
|---|---|---|
| **A1 条款齐** | rubric 每条条款在评估侧有**一个**明确产出口（评分器 / 断言 / 读数） | `rubric_version.DIM_CLAUSES` 覆盖全部条款（含 B-1 / B-3）；无「条款有、实现无」，也无「实现有、条款无」 |
| **A2 读数非空** | 每条样本级条款在**调参池**上有读数，且**弃权/不可判定单列** | 报表出「可评率」一栏（当前没有）；每维可评率 ≥ 60%（调参池口径） |
| **A3 门禁有牙** | rubric G-7「批次级断言不过 → 暂停该批发放」有执行面 | 闸门第五条判据 `batch_asserts_clear` 存在且能退 1 |

> ⚠️ **A2 的分母只算调参池**：持有集是封存面（D-C5/D-C8），软维度不进它的分母是**设计**，不是缺陷 —— 但报表必须显式写清，否则会被读成「持有集也空」。

## 2. 落点设计

### 2.1 批次级断言 B-1~B-4（P0-1）

**「批」的定义要先定死**：rubric 只说「每批一份」，没说批是什么（这是 P0-1 里的准则缺口）。本方案取：**批次 = 一个 run**（`run_id`），理由是 `run_config` 是 per-run 落的、且 rubric B-2 提到「任务标准 / 裸任务按全量处置计」都落在 run 这一层。**这行定义要写进 rubric v1.3**（P0-3 的一半）。

**新模块**：`evaluation/batch/asserts.py`（新目录，与 `scorers/`、`calibration/` 平级）
**新命令**：`python -m trajectory_pipeline.evaluation.batch --version N`（或挂在现有 `agreement` 下作子命令 —— 倾向后者，少一个入口）
**读数落盘**：`output/pipeline/calibration/v{N}/batch_asserts.json` —— 按 run 一行 + 批次汇总一段（与 `snapshot.json` 同目录、同版本号绑定）

| 断言 | 口径（可机械核） | 数据源 | 现状 |
|---|---|---|---|
| **B-1 动作 schema 合规** | 全批 `steps[].action.tool` ∈ `executor.actions.TOOLS`（**六值**：goto/click/new_tab/fill/press/close_tab，与 rubric 2026-10-17 补记一致）且 `params` 齐 | P1 `steps[].action` + `actions.TOOLS` | **数据源齐，可直接做** |
| **B-2 检索覆盖完整性** | 覆盖率 = 有明确处置的候选数 / `run_config.max_candidates`；结构性剔除的候选**不计入分母** | P1 `run_config` + `outcomes` | P1 侧齐；**黄金集候选里没有 `run_config`**（2495 行全缺）⇒ 读数从 P1 存档取，不从黄金集取；「结果页覆盖率」算不到（采集缺口 P2-3，报表必须写明） |
| **B-3 语义判断一致率** | 一致率 = judge 站点类别与**人工类别标注**一致数 / 本批进入站点类型判定的样本数；阈值 ≥85%（LLM 裁判资质领证线） | 黄金集**人工类别标注**（新增字段）+ D-3 judge 输出 | **人工类别标注不存在**（黄金集 `label` 是分支名，不是 `playable/nav_aggregator/review/irrelevant/ambiguous`）⇒ 依赖 P0-2 的 d3 金标先落地 |
| **B-4 异常处置合规率** | 合规 = 三条同时成立：① 该异常被记成分支 ② 异常后**立即转向下一站**（未在同一 URL 上重复无效动作）③ 止损理由锚定观察（引用存档里的具体依据） | P1 `outcomes[].branch` + `steps[]` + 止损理由原文 | **数据源齐，可直接做** |

**接闸门**：新增第五条判据 `batch_asserts_clear`，**默认 `status="只出读数"`**（对齐 `thresholds.py` 的 status 机制）—— 第一批只报不判，等 owner 看一批读数再定线。**这正是 rubric G-7「不过 → 暂停该批发放」的落点**：定线后该判据不过即闸门退 1（驳回）。

> ⚠️ **口径纪律**：B 断言**不出 1–5 分**（rubric 明写），所以它们**不进软维度一致率、不进样本级分母、不与样本级分数相加**（G-7）。

### 2.2 D-3 / D-9 的读数（P0-2）—— 工程只补两个口子，其余全是数据活

**关键事实**：这条路**早就修好了**，缺的数据。

1. 机器件全在：
   - `d3_scorer.score_d3` / `d9_scorer.score_d9` 已实现，prompt 与锚点表冻结（`rubric_version.evaluator_version()`）；
   - `goldwork worksheet --dimensions d3,d9` 能出金标表（`goldwork.py:84` 的 `FILLABLE_DIMS` 派生自 `SOFT_DIM_NAMES`，**含 d3/d9**）；
   - `dim_scores` 写入路径接受 d3/d9（`alignment.py:509` 白名单 = `TIERED_DIMS - {d10}`）；
   - `judge_pairs convert --dimensions d3,d9` 能把 judge 逐行读数摊平成带 `golden_id` 的配对行（`judge_pairs.py:400`）；
   - `triggers --version N --judge-report <pairs>` 的 T-2 / T-3 就是「judge ↔ 人工 kappa」，**正是 d3/d9 的条款级读数口径**。
2. 数据缺口只有两处：
   - **金标侧 182 格没人填**（`output/pipeline/calibration/v16/gold_worksheet_d3d9.jsonl`）；
   - **judge 逐行 pred 没跑**（需 LLM 凭据 + 一轮真实批次）。
3. 跑通顺序：`goldwork worksheet --dimensions d3,d9` → 人填 → `annotate --dimensions-only` → `freeze --refresh-gold` → `evaluation.cli --include-llm-judge --json` → `judge_pairs convert` → `triggers --judge-report` ⇒ **T-2 / T-3 从「测不成」变成有读数**。

**工程要补的一处（P1 级）**：**pred 侧的 d3/d9 不进快照**。原因：`freeze --refresh-scores` 用 `candidates.jsonl` 重挂 pred，而 `cmd_overlay_scout`（`builder.py:5186`）只回填 `OVERLAY_DIMS = ("d2","d4","d5","d6")` 四维；judge 的 pred 在 version 目录的 pairs 文件里，**没有回填通路** ⇒ 快照里 d3/d9 只有 gold 一侧 ⇒ `verdict` 恒 `ungraded` ⇒ **分歧卡与闸门看不见这两维**。
⇒ 新增 `overlay-judge`：把 pairs 写进冻结行顶层 `dimension_scores`（**键齐全、弃权写 `null`**，与 `overlay-scout` 同纪律：弃权与没测在快照里长得一样正是 M-29 的病）。

> ⚠️ **judge 面与代码面不可混比**：`provenance.DIM_FACES` 已把 d3/d9 标为 `llm` 面、d2/d4/d5/d6 为 `code` 面 ⇒ 快照的 pred_provider 会自动带面与版本，**不混算进代码面的类回归**。

### 2.3 读数口径：把「可评率」与「弃权率」摆到明处（P1-1、P1-2、P2-1）

**三条并列读数**（缺一条就读不出真相）：

| 读数 | 定义 | 为什么必须有 |
|---|---|---|
| **可评率** | 可评条数 / 该维条目数（分母 = 该维在快照里的条目总数，**不是** 294） | 现在只报 ungraded 条数 ⇒ 「三分之二是空的」看不出来 |
| **弃权率** | 三态口径下「任一侧没结论」的条数 / 该维条目数 | D-10 分母 18 的成因是 51.4% 弃权；**弃权 ≠ 错** |
| **金标来源分层** | 按 `reviewed_by` 桶拆开报（人署名 / 自动验证器 / 无信号基线） | 194/294 行不是人判；把它们算进一致率等于「拿代码给自己打分」 |

**口径纪律（三条）**：
- 持有集（封存面）的软维度读数**照常出，但显式标注「不参与判定」** —— 不出它会让人以为没跑，出它而不标会让人以为它进了分母；
- **分母跟着绑定对象走**：`thresholds.py` 的 `scope` 机制（`headline_split+human_signed+three_state`）照搬到软维度 ⇒ 「可评率」的分子分母必须与上岗线读数**同一个绑定对象**，否则两个数会被拿来比；
- **弃权单列，不折进 agree 也不折进 disagree**（三态口径已定）。

## 4. 红线与不做的事

- **不投票 / 不集成**：judge 只出读数，不进生产链（`--include-llm-judge` 默认关，本方案不改这一点）。
- **封存面只读**：持有集不参与调参、不进软维度分母；D-C5「每个 rubric 版本只跑一次，平时只报条数」不变。
- **fail-closed**：**测不成 ≠ 驳回**（退出码 2 vs 1）；**弃权 ≠ 错**（不进分母、单列报出）；**没结论就不猜**。
- **不回填历史存档**：第 3 批的尺子改造**只影响新冻结档**；批次边界前后的分布跳变必须记批次元数据。
- **不改采集层**：P1-2 的根因（H-01 `unresolved` 桶）与 P2-3（候选剔除不留 URL）**本方案只显式化、不修**；越权修采集会把「评估口径」和「采集能力」两件事搅在一起。
- **不改已定线的阈值**：`d10_min_agreement = 0.80` 与它的绑定对象（2026-10-30 owner 裁定）**不动**；新增读数走 `thresholds.py` 的 `status="只出读数"` 机制，不借机调线。
- **分歧一律暴露**：不做投票、不做集成、不把分歧平均掉（轨迹级 28/50 条站点标签互相冲突的事实在案）。

### 7.2 裁 ② · D-10 的五档由 LLM 判 —— 已落地（**分判，不是投票**）

```
因子 A 一致性（代码断言 · 语义等价类三态） × 因子 B 依据陈述（LLM 裁判）
        ↓ 查表（唯一映射）
      1..5 档
```

- **两张因子表不交叉**：一致时问「依据说得准不准」，不一致时改问「成因判得对不对」
  ——**同一个提示词问两件事，裁判会挑好答的答** ⇒ 契约测试钉死不许交叉；
- **fail-closed**：裁判没判出来 / 观察不足 / 依据文本缺失 / 取值不在契约内 ⇒
  一律 `undetermined`（**不落 1 档**）——**1 档是 ★ 一票否决面**；
- **依赖方向**：`golden → scorers`（本模块**不 import golden 包**）⇒ 因子 A 由
  **调用方**传进来（`D10Case.state`），本模块**不自己算一致性**。
