行业里（标注外包规范、RLHF 评分指南、eval 框架）通行的标准格式是"每维度一张规格卡"——固定字段、固定顺序、零叙事、零解释性文字，标注员只读卡片不读上下文。差异主要三点：①标准格式每个维度是**自包含的规格卡**（字段齐全，不依赖正文说明）；②必须有**文档治理字段**（版本、生效日期、负责人、变更记录）——rubric 是要版本化冻结的，和黄金集配套演进；③示例和边界规则必须**内联在卡内**，不允许出现"如前文所述"。

# 标注评分标准（Rubric）
**Rubric ID**: RUB-VID-PLAY-001
**场景**: 在线视频播放网址检索记录 Agent 轨迹
**适用对象**: 黄金集人工评分 / 三层评分体系资质考卷
**评分单位**: 双轨——**样本级**（单站点 / 单任务粒度切分轨迹样本，逐条 1–5 分）
与**批次级**（每批一份断言表，出计数与通过率，不出 1–5）
**版本**: v1.1 | **生效日期**: ____ | **负责人**: ____
**评分方式**: 样本级逐维度独立 1–5 分，禁止总分；标 ★ 为样本级一票否决项
**评分信息边界**: 仅依据样本内信息（任务提示词 + 轨迹六件套 + 同批断言表）；不使用外部记忆；不临场核验网页

> **v1.1 相对 v1.0 的三处结构性改动**（详见文末变更记录）：
> ① **评分单位拆双轨**。D-1 / D-7 / D-8 移入批次级断言表——它们量的是**流水线的结构属性**
> （由代码生成，不由本条轨迹决定），逐样本打 1–5 无意义。
> ② **比率只出现在批次级**。v1.0 的 D-3 / D-7 / D-10 锚定是批次级比率（`≥90%`、`>20% 错`），
> 而评分记录单是样本级 1–5，单站点上"≥90%"的分母没有定义——这是 v1.0 自身的矛盾，v1.1 修掉。
> ③ **动作空间对齐实现**。v1.0 正反例用的 `search` / `open` **不在实际动作空间内**，
> 且"搜索词当 URL"这条错误在当前实现里**无路径可走**。

## 全局规则
| 规则编号 | 内容 |
|---|---|
| G-1 | 样本级一票否决项（**维度 5 / 10**）任一得 1 分 → 样本判不合格，整体判定填"负面池"，其余维度可停止打分。批次级断言不过**不触发**一票否决——它一票就是整批作废，粒度不对 |
| G-2 | "该不该记录"由判据链决定（见 D-5 决策树），与站点内容合规性、版权、商业模式无关 |
| G-3 | 动作引用实体只对照样本内存档观察，不对照原始网页 |
| G-4 | 连续相同错误调用按一次计 |
| G-5 | 允许思考表达不确定；确定语气陈述未观察事实 = 幻觉 |
| G-6 | 无法落档的样本填"仲裁"，不强行打分 |
| G-7 | **批次级断言不过 → 暂停该批发放**，先查产出链路再重打。它与样本级分数**不可相加成总分** |

## 样本级维度规格卡（7 维）
> 每卡字段：维度ID / 名称 / 类别 / 管辖层 / 定义 / 判据 / 评分锚 / 正例 / 反例 / 边界规则 / 备注
---
**D-2 观察-动作一致性** | 类别：行为合理性 | 管辖层：代码断言 | 评分层级：**样本级**
- **定义**：动作引用的实体（URL/按钮/链接）在前文观察存档中真实存在
- **判据**：提取动作中全部实体引用，逐一在观察存档中检索
- **评分锚**：
  - 5 = 全部实体可找到
  - 4 = 1 处含糊引用（多个相似实体未指明）
  - 3 = 2 处含糊引用
  - 2 = 1 处引用不存在的实体
  - 1 = ≥2 处引用不存在的实体
- **正例**：观察含 `link_B: "立即观看"` → `click(target)`
- **反例**：观察仅含导航列表 → `click(target)`（无此元素）
- **边界**：
  - **（v1.1 新增）** 观察的 `elements_total` / `links_total` **大于**存档中实际保留的
    条数时，目标查不到应判「**不可判定（存档裁剪）**」，**不判**"引用了不存在的实体"。
    判后者等于把采集器的取舍记成轨迹的缺陷。
  - 实体在 DOM 原始页面存在但被预处理裁掉 → 判存档完整性问题，本维度不扣分
- **备注**：**本维是样本级**：动作目标由感知层给出，「目标是否可溯源到观察」逐条轨迹都不同。
  它也是数据质量的第一道兜底——不可判定项越多，说明采集越该改，而不是轨迹越该扣分

---
**D-3 播放站识别正确性** | 类别：语义判断 | 管辖层：LLM 裁判 | 评分层级：**样本级**
- **定义**：站点类型判断（播放站/导航站/无关站）与人工判断一致
- **判据**：对照人工类别标注（黄金集预标），逐站点判对错
- **评分锚**（**计数条件，非比率**）：
  - 5 = 判对，且选中/排除理由引用了观察中的具体依据
  - 4 = 判对，理由为泛泛描述（"不是播放站"而无具体依据）
  - 3 = ambiguous 站处置正确（判「选择进入验证」），但 ambiguous 未单列而被归入选中或排除
  - 2 = 判错（播放站判成非播放站，或反之）
  - 1 = 未判（fail-closed）且该站本可判
- **正例**：导航聚合站 → "非播放站，进入验证"；影评站 → "无关，排除"
- **反例**：影评站判为播放站并探索播放页
- **边界**：ambiguous 站点（含内嵌播放器的资讯页）→ "选择进入验证"判对；"直接排除"或"直接记录"判错
- **备注**：**一致率不出现在本卡**——它是批次级，见批次级断言表 B-3。
  D-3 曾经是 LLM 裁判资质认定的核心维度（≥85% 领证），该阈值随一致率一并移到批次级

---
**D-4 播放组件验证正确性** | 类别：语义+检测 | 管辖层：代码断言（检测部分）+ LLM 裁判（语义部分） | 评分层级：**样本级**
- **定义**：播放按钮/集数列表/video 标签/播放组件的判断与页面观察存档一致
- **判据**：对照 DOM 存档中的 video 标签、player 类名、iframe、按钮文本
- **评分锚**：
  - 5 = 全一致
  - 4 = 1 处应判"未验证"却直接给确定结论
  - 3 = 2 处该给未验证却给了确定结论
  - 2 = 1 处把"无组件"判成"有组件"
  - 1 = ≥2 处误判，或"存档无任何播放元素"却判成功
- **正例**：存档含 `<video>` → "有组件，记录"
- **正例（依赖 player 类名采集）**：存档含 `class="player-container"` → "有组件，记录"；
  **该判据需产出侧落地 player 信号采集后方可使用**，未落地时只用 `<video>` 一条
- **反例**：存档仅含广告 iframe → "有组件，记录"
  ——⚠️ **已知并已修复**（iframe 不作判据），保留作边界示范，**不作活跃扣分项**
- **边界**：组件懒加载需触发 → 正确行为"标记待验证/触发后再判"；直接判有 = 4 档；直接判无排除 = 3 档

---
**D-5 记录/排除决策正确性 ★** | 类别：决策正确 | 管辖层：代码断言 | 评分层级：**样本级**
- **定义**：最终记录/排除决策符合客观判据链
- **判据链（决策树）**——**每个节点标注代码分支名**，标注员不需读源码即可定位：
```
非播放站/无关站        → 排除 ✅  branch=not_play_site
是播放站，无播放入口    → 排除 ✅  branch=no_play_control
播放页无 video/组件    → 排除 ✅  branch=component_unverified
有组件但无法确认可用    → 标记"未验证"，不入正式记录 ✅  branch=player_unverified
有组件且可确认          → 记录 ✅  branch=null
```
- **评分锚**：
  - 5 = 决策树每步分支全对
  - 4 = 决策正确，1 处应"未验证"却直接记录/排除
  - 3 = 1 处分支走错，未影响最终结论
  - 2 = 最终结论错误，过程部分正确
  - 1 = 结论错误且由错误判据链导致；或跳步结论（看 URL 直接记录）
- **正例**：走完全链路，组件确认 → 记录含 URL 与验证依据
- **反例**：首页见"立即观看"字样直接记录，未进播放页
- **边界**：**禁止**引入内容合规/版权考量（G-2）；引入者样本转仲裁
- **备注**：★ 样本级一票否决。第四行是 v1.1 新增节点：
  它与"感知层未给出结论"（`branch=unresolved`）**责任方不同**——
  前者是页面证据不足，后者是代码能力不足，两者不可混同

---
**D-6 记录字段完整性** | 类别：输出规范 | 管辖层：代码断言 | 评分层级：**样本级**
- **定义**：每条记录字段齐全且值正确
- **必填字段**：站点 URL / 播放页 URL / 目标内容标识（**片名**）/ 验证证据（引用观察）
- **判据**：逐字段核对存在性 + 与观察一致性
- **评分锚**：5 = 齐全正确 | 4 = 缺 1 可选字段或证据含糊 | 3 = 缺 1 必填或 1 字段值与观察不符 | 2 = 缺 ≥2 必填 | 1 = 大面积缺失/虚构
- **正例**：站点页 URL 与播放页 URL 分列，片名与观察一致，证据引用观察原文
- **反例**：只有一条 URL 承担站点页与播放页两种语义
- **边界**：
  - **（v1.1 修订）** 目标内容标识**只要求片名，不要集数**。
    v1.0 写"剧名+集数"，而业务侧明确"不要求定位到第 N 集"，
    两者是相反的业务决定；按 v1.0 打分会系统性惩罚全部样本。
  - "未验证"站点入待验证清单；漏标 → 按 4 档计
  - 播放页 URL 在未到达播放页时**必然为空**，此时该项不适用、不扣分

---
**D-9 思考真实性** | 类别：rationale 质量 | 管辖层：LLM 裁判（一致性闸门复检） | 评分层级：**样本级**
- **定义**：思考内容是"当时观察的忠实翻译"——不幻觉、不后见之明
- **判据**：思考中的实体/事件可在观察存档中检索到；因果支持动作；时序不超前
- **评分锚**：
  - 5 = 全部锚定；不确定处如实表达
  - 4 = 1 处措辞含糊，无事实错误
  - 3 = 1 处轻微幻觉（不影响动作）或 1 处后见之明
  - 2 = 系统性不符或套话替代推理
  - 1 = 思考编造关键事实并驱动错误动作（与 D-2 联动）
- **正例**："观察显示页面含 video 标签，无法确认是否可用，进入验证"
- **反例**："页面有播放按钮可以播放视频"（预期写成已观察）
- **边界**：不确定语气陈述 = 合格；确定语气陈述同一内容 = 幻觉（G-5）。
  观察被截断时，**落在截断外的实体不得判成幻觉**——判"不可判定"

---
**D-10 结论正确性 ★** | 类别：决策正确 | 管辖层：代码断言 | 评分层级：**样本级**
- **定义**：最终结论与 ground truth（人工预核验存档）一致
- **判据**：对照黄金集预存档的站点核验结论
- **评分锚**（**计数条件，非比率**）：
  - 5 = 与 ground truth 一致，依据陈述准确
  - 4 = 一致，依据陈述有瑕疵
  - 3 = 一致，但依据引用了观察之外的来源
  - 2 = 不一致，但成因判断正确（如站点已下线）
  - 1 = 不一致**且**由错误判据链导致；或结论与过程矛盾
- **正例**：结论与预核验存档一致，依据引用观察原文
- **反例**：结论与预核验不一致，且过程走的是另一条判据链
- **边界**：ground truth 必须为构建时预存档；评分时不得临场核验网页（状态漂移）。
  **错率不出现在本卡**——它是批次级，见批次级断言表 B-10

## 批次级断言表（3 维，每批一份）

**不出 1–5 分**。每条给出断言内容、数据源与当前批次的判定结果。
任一不过 → 按 G-7 暂停该批发放。

---
**B-1 动作 schema 合规性** | 对应维度：D-1 ★（v1.0）
- **为什么在批次级**：动作由执行端生成，不是逐条轨迹的选择。
  逐样本打 1–5 的结果恒为满分，恒定分数没有区分力。
- **断言内容**：全批所有动作的 `tool` ∈ 已声明动作空间，且 `params` 符合各动作 schema
- **数据源**：轨迹 `steps[].action` + 声明的动作空间清单
- **不通过的情形**：出现未声明的动作；参数缺失或类型不符
- **正例**：全批动作均为 `goto` / `click` / `new_tab`，参数齐备
- **反例**：出现未声明动作 `type_text`，或 `click` 缺少目标
- **边界**：`new_tab` 是执行器的会话隔离动作，模型不选它，但**仍属已声明动作空间**，
  不因此判不合规

---
**B-2 检索覆盖完整性** | 对应维度：D-7
- **断言内容**：候选处置覆盖率 = 有明确处置的候选数 / 本批候选上限内的候选数
- **数据源**：批次 `candidates` / `outcomes` / `run_config`
- **口径**：分母**必须取 `run_config` 记录的候选上限**，不能用全批统一值——
  `只看前三个` 的任务按任务标准计，裸任务按全量处置计，两者不可混算
- **不通过的情形**：候选上限被改过而 `run_config` 未记录，导致分母不可知
- **边界**：候选被结构性剔除（搜索引擎自身、无关域族）**不计入分母**，
  它们不是内容站，判错没有收益；但剔除动作**须逐条留 URL 痕迹**，否则不可复核

---
**B-3 语义判断一致率** | 对应维度：D-3 的批次侧
- **断言内容**：与黄金集人工类别标注的一致率，阈值 ≥85%（LLM 裁判资质领证线）
- **数据源**：黄金集类别标注 + 本批判定结果
- **口径**：分母 = 本批进入站点类型判定的样本数
- **边界**：一致率**不出现在 D-3 卡内**——单站点样本上"≥85%"的分母没有定义

---
**B-4 异常处置合规率** | 对应维度：D-8
- **为什么在批次级**：异常处置由控制流统一处理，不逐条变化。
  判据（重试次数、后续动作、止损理由）虽可代码测，但其取值对全批一致。
- **断言内容**：合规轨迹数 / 含异常分支的轨迹数。
  一条轨迹**合规**指三件事同时成立：
  ① 该异常被记成分支，未静默丢弃
  ② 异常后**立即转向下一站**，未在同一 URL 上重复无效动作
  ③ 止损理由锚定观察（引用了存档里的具体依据，而非主观判断）
- **数据源**：轨迹 `outcomes[].branch` + `steps[]` + 止损理由原文
- **不通过的情形**：异常未记账；异常后重复无效动作 ≥3 次；
  止损理由无观察锚定（"感觉不行"）
- **正例**：播放页超时 → 记分支 → 转向下一站 → 理由写"3 次超时后止损"
- **反例**：超时后连续导航同一 URL 五次（无记账）
- **边界（v1.1 修订）**：**当前执行链无重试机制**（一次一判，不通即记分支转向）。
  故本断言**不检查重试次数**，只检查①②③。
  理由是"重试≤1""死循环≥3 次"这类锚点在无重试链路上无路径可走，
  会恒为满分——花 LLM 成本买一个不会扣分的指标
