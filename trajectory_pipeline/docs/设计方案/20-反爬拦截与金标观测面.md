## 0. 一句话

**「人工能进、agent 被拦」不是一个数据集的置信度问题，是「观测面」这个轴缺了。**
把它写成「以谁为准」，等于问「温度计和体温计以谁为准」——两个观测面各自的事实都成立，
错的是拿 A 面上的读数去判 B 面上的对错。

## 1. 问题重述：一个词装了三件事

现在所有讨论都挤在「可访问」这个词上，而它至少是三个互不相同的问题：

| # | 问的是什么 | 现在谁在答 | 答错的代价 |
|---|---|---|---|
| **A** | **站点**上有没有能播的正片 | 黄金集（人工开浏览器看） | 错了就是金标缺陷，`gold_defect` |
| **B** | **我们这一轮**有没有看到那个站点 | 采集层（`blocked` / `unreachable_hard` / CF 挑战页） | 错了就是把「没看到」写成「看不了」，进负样本池 |
| **C** | 把 B 的结论当作 A 的结论，**评估器**算不算对 | `d5_scorer` 的决策树 | 错了就是给一条假负样本打 5 分，也就是**体制化**地承认这颗污染 |

今天的三处口径正好**互相打架**，而每一处单独看都自洽：

1. **正样本侧已经是「以人为准」**：W1 的正样本唯一来源就是人工复核
   （[`review_queue.py`](../../executor/review_queue.py) 文件头、[07 手册 §4](../07-人工复核与判读手册.md)）。
   代码对 ④ 一律不判成功，人看过页面才给 `confirm_success`。
2. **负样本侧事实上是「以 agent 为准」**：`blocked`（地区/验证码/反爬）**不在**
   `REVIEW_BRANCHES` 里 ⇒ 无人复核，直接进负样本池（实测池里 **33 行**）。
3. **rubric 站在第 2 条那边**并且给了满分：D-5 决策树明写
   「地区/DRM/验证码/反爬 → 排除 ✅ `branch=blocked`」（[rubric](在线视频场景rubric.md) L106）。
   也就是说：**同一件事，记成功要人点头，记看不了不要人点头，而且 rubric 还给 5 分。**

⇒ 用户的矛盾不是新问题，是这三条口径的**必然产物**。所以答案不是「选一个为准」，
是**把观测面提成轴，让 A / B / C 各答各的**。

   但页面是「恭喜，站点创建成功！」——站已死。「进了站」与「站上有东西」是两件事。

## 3. 判定：以谁为准

### 3.1 三条各自成立的事实

1. **人能进** ⇒ 站点上**确实有**可播放内容（至少对该地域、该时刻、该登录态成立）。
2. **agent 被 CF 拦** ⇒ **我们**这一轮没有拿到站点页面。这只说明**我们的观测面被拦**，
   对「站点有没有正片」**零信息**。
3. **两条同时成立不矛盾**——它们说的是两个面的两件事。

### 3.2 结论（推荐口径）

> **金标 = 在「声明的观测面」上观测到的站点事实；采集面的拦截 = 采集侧账，既不进金标，也不进负样本池。**
>
> 人浏览器不是「真值」，它是**一个被声明的参考观测面**（`surface=human-browser`）——
> 它给出的是「**这个站存在可播放内容**」的**存在性证据（下界）**，
> 不是「任何 agent 都必须能到达」的普适结论。

推论三条，都能直接落成代码判据：

- **A 面（金标）**：`golden.label` 只在**该行声明的观测面**上成立。跨面不可比。
- **B 面（采集）**：`blocked` / CF 挑战 / `unreachable_hard` / 采集降级
  ⇒ **不得**写成站点性质的负样本；它们进「采集侧账」，与样本池物理分开。
- **C 面（评估）**：金标与 pred **观测面不同**且 pred 侧是「被拦」⇒
  **不是分歧**，不出分歧卡，落采集侧账并**单列**（`loop=collection`，既有桶
  `evidence_missing` 就是它）。

### 3.3 为什么不采纳「以 agent 优化后的可访问性为准」

参考方案主张「黄金集以**经过工程优化的 agent 在真实环境中的表现**为准」。逐条对账：

| 它的理由 | 在本仓为什么不成立（或要改造） |
|---|---|
| 「完全依赖人工可访问性会让 agent 性能被高估」 | 那是**评估器/任务池**的问题，不是**金标**的问题。本仓的金标用途是 D-10 校准评估器，**不是**给 agent 打分。用 agent 能力当金标 ⇒ D-10 数字里同时装了「评估器对不对」和「采集强不强」，**不可归因**——直接违反 `CLAUDE.md` 的核心主张 |
| 「动态黄金数据集，agent 突破了就更新状态」 | 这是本仓明令禁止的动作：**冻结档不可变、新分支不回填、金标变动 = 新基线**（`gate` 见 `baseline_reset` 退 2）。逐版改写参考答案，前后读数就没法比了 |
| 「以优化后的环境为准」需要先定义「优化」 | 「优化」每升级一次 stealth/代理，就是**换了一个观测面**——按本仓已有的分代纪律（`branch_eras` / `rationale_era` / `label_schema_version`），换面必须**新起一个面代号**，而不是原地把旧读数重判 |
| 「难度系数、过程指标、人机混合」 | **采纳**，但落在**任务池 / 样本池的新轴**上，不动金标标签（§5.4） |

一句话：**它的「精神」（声明环境、分层、记难度、迭代）全收；它的「金标以 agent 为准」这一条必须拒**——
本仓一旦接受，`agreement` / D-10 就变成「采集能力的自评」，而评估器对不对再也测不出来。

### 3.4 有一条例外要写清

**如果观测面被声明的就是 agent 面**（例如将来做一个「stealth 面基准集」），
那么在那个集合里，「以 agent 可访问性为准」是对的。**所以不是禁止它，是必须分集**：

| 集合 | 观测面 | 用途 | 现状 |
|---|---|---|---|
| 现有黄金集 v1–v13 | **人浏览器**（名义上的；实际多是「按存档+经验判」） | 校准评估器（D-10） | 现行，但**没有写死观测面**（本方案 R2 补） |
| （将来）stealth 基准集 | camoufox + 某套 stealth 参数（`fingerprint` + 代理 + 版本号，全部声明） | 采集能力度量 / 难度分档 | 不存在 |

### 3.5 什么样算负样本（**判据，不是分支名清单**）

O-a 裁完之后「负样本」这个词必须重新钉死，否则会滑成「凡是没成功的都算」。

**四个条件，缺一不成立：**

| # | 条件 | 不满足时它是什么 |
|---|---|---|
| **1 面成立** | 结论出自**已声明的观测面**，且这一轮**真的拿到了站点自己的页面**（不是挑战页 / 错误页 / 降级正文 / 超时页） | 采集侧账 |
| **2 断言是站点性质** | 结论说的是「**这个站点/这个页面**没有可播放的正片，或明确拒绝提供（会员 / 登录 / 地区 / 404）」 | 采集侧账或未判明 |
| **3 证据能支撑否定** | `evidence` 引到页面正文 / 元素 / 状态码的**具体形态**。否定断言比肯定断言贵——说「没有」必须说清「看了什么、看到什么」 | 未判明 |
| **4 可复核** | 落在复核队列里，人能一次判掉（O-b 之后 `blocked` 也在队列里） | 未判明 |

**按这四条把 22 类分三档**（不新增分支，只定「进不进池」）：

| 档 | 分支 | 为什么 |
|---|---|---|
| **负样本**（站点性质、有页面证据） | `not_play_site` · `no_play_control` · `component_unverified` · `subscription_wall` · `partial_free` · `login_required` · `login_wall_or_blocked`(deprecated) · `broken` · `trailer_only` · `not_aggregator` · `not_article` · `aggregator_no_entries` · `article_no_links` · `no_site_search` · `site_search_no_results` | 页面在手，结论是关于站点的 |
| **未判明**（本来就不进池） | `unresolved` · `player_unverified` · `trailer_suspect` | `NON_SAMPLE_BRANCHES`，现状 |
| **采集侧账**（本轮新增出池） | **`blocked`**（O-a 裁定）· **`unreachable_hard`**（Q-17 待裁，同一判据）· `site_search_routed`（路由记账） | 第 1、2 条不成立：我们没看到站点 |

**分母的变化（实测 `negative.jsonl` 260 行）**：

| 动作 | 池子 |
|---|---:|
| 现状 | **260** |
| `blocked` 出池（O-a） | **227** |
| 若 Q-17 也裁成出池（`unreachable_hard` 52 行） | **175** |

⚠️ **`blocked` 这一支自己不匀**：实测 33 行里 **17 行证据写的是 CF/挑战页**
（采集侧），其余十几行是 v.qq 的「当前设备不支持播放 + 70017001.1」（站点自述的**设备/DRM** 拒绝）。
所以 O-a 的落地形态**不是把整支删掉**，而是：

1. `blocked` **一律先出池**（默认不给训练信号）；
2. 进复核队列（O-b），人只答一件事——**「站点侧的墙，还是我们的采集面被拦」**；
3. 人若判「站点自述」（地区/DRM/设备），走既有 `confirm_*` 通道**改签到具体负分支**
   （`subscription_wall` / `login_required` / `broken` 之一），**不新开第 23 类**；
   判「采集侧」则留 `collection_status=blocked`，**永远不进池**。

**出池 ≠ 删轨迹**：P1 存档照旧、P2 照样切样本（带 `collection_status` 与 `tool_surface`），
只是这条样本**不承担「这里看不了」这个训练信号**——它承担的是「被拦时怎么处置」那一条，
而那是另一个（目前还没立的）维度。

## 4. 与参考方案的逐条对账

| 参考方案的建议 | 本仓处置 | 落点 |
|---|---|---|
| 分层标注（`VERIFIED_AGENT_ACCESSIBLE` / `..._WITH_CHALLENGE` / `HUMAN_ACCESSIBLE_ONLY` / `INACCESSIBLE`） | **改造后采纳**：不新开分支（22 类封闭集不动，owner 已裁），落成**两个新轴**：金标的 `access_surface` + 样本的 `collection_status`（见 §5.3/§5.4） | R2 / R3 |
| 静态 403 ⇒ 硬性不可访问 | **拒绝**：403 在本仓归 `broken`（L0 初筛口径），且 CF 的 403 恰恰是最常见**可解**形态；把 403 当硬性不可用会制造一整类假负样本 | — |
| 「可优化访问」⇒ 应用对抗技术 | **采纳但先记面**：换 stealth 参数 / 加代理 = **换观测面**，必须先写面代号再跑，否则前后批次不可比 | §5.4 |

- **不把 CF 挑战页当站点**：没有站点页面证据就没有站点结论（「否定断言撑不住」的同一纪律）；
- **不因为「人能看到」就给 agent 打差评**：那是采集侧账，不是模型能力账。
