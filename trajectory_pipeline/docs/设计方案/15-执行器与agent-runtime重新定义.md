# 15 · 执行器与 agent runtime 的重新定义

**上游**：[`12-agent执行器升级方案.md`](12-agent执行器升级方案.md)（D-A1–D-A5，A2 已落地）· [`13-A2A3-agent循环与双模灰度实施设计.md`](13-A2A3-agent循环与双模灰度实施设计.md)（D-B1–D-B4）· [`04-camoufox执行层替换方案.md`](04-camoufox执行层替换方案.md)（D11 / D12）
**性质**：**架构重定义**。改的是「谁发起观察、谁做语义决策」，**不是**「产物长什么样」。

**一句话**：**代码层做护栏、LLM 层做探索、persona 管输入分布。**
agent runtime 是探索者，代码是护栏与调度；感知层不再当传感器，退位成三块静态资产。

> ⚠️⚠️ **2026-10-26：本文里的「camoufox」多数应读作「aria 面」**——
> owner 裁定执行层再换一次（**camofox-browser 走 MCP**），camoufox 已暂退
> （代码已删、**接不回来**），工具面增至三张：
> `obscura-1`（**只读存量**）/ `camoufox-1`（**只读存量**）/ `camofox-1`（**现行生产面**）。
>
> **本文的架构判断（D-A6–D-A11）与执行层名字无关**——「LLM 做探索、代码做护栏」
> 「目标编码 `{role,name}`」「`ref` 退场」「工具声明 = 调用面」**全部照旧成立**，
> 因为 camofox 落在**同一个 aria 面**上（方言仍是 `aria_role`）。
>
> ⚠️ **只有「落点」那两栏变了**：camoufox 的落点是

## 1. 前提变更

### 1.1 旧前提在代码里是什么

「LLM 是传感器不是驾驶员」不是一句口号，它是四条可检查的落法：

1. `Perceptor.decide(question, obs)` —— LLM 答**单步**判断题，不链式决策；
2. **观察由执行器 push**：`agent_loop._execute` 每步执行完动作后 `await self.driver.observe(...)`，再渲染成一条 user 消息塞回对话（[`agent_loop.py:1266`](../../executor/agent_loop.py#L1266)）；
3. **动作空间是代码给的常量**：`AGENT_TOOLS = ("goto", "click", "fill", "press")`（[`agent_loop.py:128`](../../executor/agent_loop.py#L128)）；
4. **工具声明与实际工具集脱节**：训练侧可见 11 条（4 已用 + 7 能力声明），agent 采集期只准发 4 条。

### 1.2 事实已经变了

- **A1（INC48）**：搜索页一级分类已是 agent 判（`CLASSIFY_SEARCH_LINKS` 四分类）；
- **A2a / A2b（INC49–INC54）**：站内导航整段交给 `agent_loop`，agent 链**不再问** ② `IS_REACHABLE` 与 ③ `FIND_PLAY_CONTROL`——那两题本来就归 agent；
- **agent 链只剩一题**：⑦ `PLAYER_OK`（[`visit.py::judge_player`](../../executor/steps/visit.py) 两条链共用）。

也就是说：**「传感器」只剩一个传感器在服务一个驾驶员**——它成了驾驶员的**终局验收员**。这个角色是对的，但它不该再被写成「控制流铁律」。

### 1.3 改的不是「LLM 参与多少」，是「谁发起观察」

这是本方案的全部要害。**LLM 参与多少不是变量**（A1/A2 已经把探索权交出去了）；**变量是观察由谁发起**：

- push 模式 → 模型**只能**在代码塞给它的固定载荷里挑，窗口外的看不见，元素只能靠代码给的 ref 指认；
- pull 模式 → 模型**自己决定看哪一面**（正文？链接？元素？第几条开始？），`role+name` 是它拿到的第一手事实，ref 不必存在。

**push 模式下的三样补丁，会在 pull 模式下一起塌掉**：`ref` 机制、I6 白名单、`{tag,label}` 自造编码。它们不是设计，是 push 的衍生物。

## 2. 新分界

### 2.1 三方职责表

| 事项 | **执行器（代码）** | **agent runtime（LLM）** | **感知层** |
|---|---|---|---|
| 浏览器会话 | **拥有**（生命周期 / 指纹 / tab 隔离） | 使用 | 不碰 |
| 红线闸门 | **拥有**（`FORBIDDEN_TOOLS` / cookie / profile / Authorization） | 无权 | 不碰 |
| 预算 | **拥有**（步数 / llm_calls / 超时） | 无权 | 不碰 |
| 拦截与处置 | **拥有**（gatekeeper 三档 + 死循环检测） | **接收引导** | 提供规则判据 |
| 观察 | **提供取观察的工具**，不再主动 push 固定载荷 | **主动拉**（§5.4） | 退位 |
| 动作选择 | **无权** | **拥有** | 退位 |
| 终局 | **拥有**（分支折算 / 收口 / 记账） | 自报（到达 / 放弃 / 链接） | 提供映射表 |
| 成功判定 | **拥有**（⑦ `PLAYER_OK` 终局验收） | 无线权 | 答那一题 |
| 落盘 | **拥有**（P1 / P2 / P3） | 无权 | 无 |

### 2.2 代码保留的五样——**归因地基，不交出去**

1. **步数 / llm_calls / 超时预算**；
2. **终止判定**（谁决定这次探索结束）；
3. **处置映射**（拦截 → 引导 / 升配 / 收口三档）；
4. **分支记账**（22 类封闭集，agent 永不直接产分支）；
5. **fail-closed**（`answer=None` 不猜；`None` 不中断采集，`False` 才中断）。

这五样交出去就没有「可归因」了。**重定义动的是探索权，不是这五样。**

### 2.3 agent runtime 拿到的决策权

- 下一个动作是什么（`goto` / `click` / `fill` / `press`）；
- **要看什么**（`snapshot` / `interactive` / `links`）——**这是新增的**；
- 什么时候自报终局（到达 / 放弃 / 交出链接）。

仍然没有：分支决定权、成功判定权、会话管理权、批次调度权、外链校验权。

### 2.4 感知层的新定位——三块静态资产

| 资产 | 从哪来 | 去哪 |
|---|---|---|
| **判断题文本** | `perception/questions.py` 的 11 道题的题面 + 输出契约 | **agent 任务指令的素材**（方案 12 §2.1 第 6 条已拍板：六道站内题内化进 agent 提示词） |
| **分支记账映射表** | `Question.negative_branch` + `branches.decision_branch` | **不动**。仍是「哪道题产出哪支分支」的唯一出处 |
| **规则检测器** | `ACCESS_HINTS` / `PAYWALL_WORDS` / `detect_block` / 搜索按钮词表 | **gatekeeper 仲裁兜底**（`intercept()` 已经在用） |

**感知层不再是热路径上的一个插件，而是「被复用的静态知识 + 一组可替换的规则实现」。**

## 3. 感知层七不变式的处置

| # | 不变式 | 处置 | 理由 |
|---|---|---|---|
| I1 | evidence 可溯源到 `Observation` | **保留** | 归档纪律的核心，与谁探索无关 |
| I2 | `confidence ∈ [0,1]` | **保留** | 同上 |
| **I3** | **幂等**（同 `(question, obs)` 重复调用同答） | 🔴 **退役** | 感知层退位后不在热路径上，幂等**无对象**。且 agent 决策本身不可幂等——这是 D-A4 已接受的代价，此处只是把它写实 |
| I4 | fail-closed（返 `None` 绝不猜） | **保留，但收口到执行器** | 「agent 自报不确定」≠ fail-closed。**fail-closed 是代码的收口纪律，不是模型的表态** |
| I5 | 无副作用（只读 `obs`，不触网、不持页面句柄） | 🟡 **改写** | 「不持页面句柄」这条**移交 agent runtime**（它现在要持定位器）；「不触网」留在感知层（它不联网） |
| **I6** | decision 型题 payload 完整，`ref` 可溯源 | 🔴 **退役** | ref 没了（D-A8）。**替代物**：定位参数必须是观察里出现过的 `role+name`，由 `count()` 预判 + strict mode 在**执行层**强制——比 LLM 白名单硬 |
| I7 | `answer=True` 时 payload 不得为空 | **保留** | 同 I1 |

**退役的两条是本方案唯一真正「破坏」的地方**——owner 明确授权。**保留的五条一条都不动**，因为它们是产物可审计的地基。

## 4. 判断点的重新安置

| 判断点 | 旧位置 | 新位置 | 谁判 |
|---|---|---|---|
| ①.5 `CLASSIFY_SEARCH_LINKS` | 感知层 | **不动**（A1 已是 agent 化的分类题） | 感知层（搜索页不归 agent 管——它判的是「这条链接是什么类型的站」，是分类不是导航） |
| ② `IS_REACHABLE` | 感知层（scripted 链问） | **退位**。agent 链早就不问；scripted 链随之下线 | 确定性部分 → `reachability.probe` + gatekeeper；语义部分 → agent 自己看 |
| ③ `FIND_PLAY_CONTROL` | 感知层（拿 ref 去点） | **退位**。这本来就是 A2 交给 agent 的第 5 处硬编码 | **agent** |
| ④ `PLAYER_OK` | 感知层（播放页终局验收） | **保留在感知层** | 感知层——**这是它唯一剩下的正当岗位**：它是**终局验收员**，不是导航传感器 |
| ⑤⑥⑥C（聚合 / 引荐 / 站内搜索） | 感知层 | **退位**：题面进 agent 任务指令，`negative_branch` 进分支映射表 | agent |

**新的判断点只有两个形状**：

1. **确定性拦截**（gatekeeper）：CF / 验证码 / 登录墙 / 付费墙 / 死循环 / 观察降级；
2. **终局验收**（④ `PLAYER_OK`）：agent 报「到了」，代码判「真到了吗、播放器起没起」。

比旧的「四个判断点都是流程分流点」简单得多，而**可归因性不降**——因为分流点从「每步问一次」变成「终局验一次」，中间过程由 agent 自己的轨迹承担（那是 P1 `steps[]` 的内容）。

⚠️ **副产物**：agent 链的负样本产地会变少（`not_aggregator` / `aggregator_no_entries` / `article_no_links` 在 agent 模式下本就无产地）。**「agent 批的负样本变少不是质量变好，是产地变少了」**——这条纪律照旧，且要在报表口径里显式标注。

## 5. 工具声明的新形态

### 5.1 为什么必须是同一套

现状三份集合：

| 集合 | 值 | 位置 |
|---|---|---|
| `actions.TOOLS` | 6 | [`actions.py:70`](../../executor/actions.py#L70) |
| `agent_loop.AGENT_TOOLS` | 4 | [`agent_loop.py:128`](../../executor/agent_loop.py#L128) |
| `toolcatalog` 可见集 | 11 | [`toolcatalog/__init__.py`](../../toolcatalog/__init__.py) |

**三份不对齐，就是三次骗模型**：训练侧说「有 11 个工具」，采集期只准发 4 个，模型训完发 `web_search` 直接协议违反。方案 12 §2.2 当年写的是「**agent 工具声明 = `visible_to_model()` 集**」——**实现时退成了 4**，因为 push 模式下 agent 只用得上 4 个。

**pull 模式让这个妥协失去依据**：agent 真的会调 `interactive` / `links`，那它们就该在声明里；声明里不该有的，就该从声明里去掉。**一道裂缝，两边同时闭合。**

### 5.2 新工具清单

**动作面**（模型可见）——名称 = `PageDriver` 原语名，与执行层调用面逐字一致：

| 工具 | 参数 | 语义层 | camoufox 落点 |
|---|---|---|---|
| `goto` | `url` | 打开网址 | `page.goto(url)` |
| `click` | `role`, `name` | 点一个可交互元素 | `page.get_by_role(role, name=name, exact=True).click()` |
| `fill` | `role`, `name`, `text` | 往输入框填文本（**设值**，不是追加） | `page.get_by_role(role, name=name, exact=True).fill(text)` |
| `press` | `key`, `role?`, `name?` | 按键 | `page.keyboard.press(key)` / `get_by_role(...).press(key)` |

**采集面**（模型可见，**新增**）：

| 工具 | 参数 | 语义层 | camoufox 落点 |
|---|---|---|---|
| `snapshot` | — | 读当前页：标题 / URL / 正文 | `page.content()` + 预处理 |
| `interactive` | — | 读当前页的可交互元素（`role` + `name`） | `aria_snapshot` + 可见性过滤 |
| `links` | — | 读当前页的链接 | DOM 链接枚举 |

> **三条都没有参数**（2026-10-20 实施后的定稿）。原草案的 `links(offset?, limit?)`
> 与 `extract(fields)` **两条都没进**：
> - `offset` / `limit` 是**整数**参数，而训练侧工具声明的 `type` 一律 `"string"`
>   （见 P3 契约「不加 enum」同款纪律——参数类型一旦放开就有第二个真源）。
>   窗口是**代码侧护栏**（执行器裁剪 + `exercised` 记账），不是模型旋钮。
> - `extract` 的 driver 签名是 **dict**（`extract(selectors)`），字符串参数的
>   function 定义**表达不了 dict**。它其实是代码侧工具（`RESULT_SELECTORS`
>   在用），不是模型的探索面。

⚠️ **采集面是「协议级」的，但它的「内容」是「面级」的**（R3 开工前必须钉）：

| | obscura | camoufox |
|---|---|---|
| `interactive` 返回 | `{ref, tag, label}`（MCP `browser_interactive_elements`） | `{role, name}`（`aria_snapshot`） |
| `links` 返回 | `CleanedLink`（NDJSON 解析） | 同形（DOM 枚举） |

**工具名可以共用**（都来自 `PageDriver` 协议），**返回内容不能**——采集面读到的
东西必须与动作面能定位的东西**同一套词汇**，否则模型读到了 `role` 却只能发
`ref`（obscura 面）或反过来（camoufox 面）——**那正是 push 模式的老毛病换了个马甲**。

所以采集面**当前只进 camoufox 面**（2026-10-20 实施口径）。R3 落地时若要给
obscura 面也加采集面，**必须同时把 obscura 的 `interactive` 输出换成
`{role, name}`**——那是方案 04 P3 的活，不是声明层的活。

**基础设施**（模型不可见，留 P1 动作流）：

| 工具 | 参数 | 说明 |
|---|---|---|
| `new_tab` | `url` | 会话隔离。**待定**：新架构下「开新标签看外链」是合法探索动作，但模型不关 tab 会泄漏——见 §8 待决项 O-1 |
| `close_tab` | — | 同上 |

**与浏览器无关的能力声明**（模型可见，7 条，`exercised=False`）：`web_search` / `web_fetch` / `view_image` / `desktop_screenshot` / `get_current_time` / `read_file` / `glob_search`——**两面共用，不随执行层变**。

**永不进声明**：`evaluate`（`main_world_eval` 能读页面 JS 全局状态，是采集面扩权，不是模型能力）· `count`（回执里已带 `video`/`iframe` 计数，不必单列）。

**两个面的规模（2026-10-20 实施后）**：

| 面 | 声明总数 | 模型可见 | 采集面 | 能力声明 |
|---|---|---|---|---|
| `obscura-1` | 13 | 11 | 0 | 7 |
| `camoufox-1` | 16 | 14 | 3 | 7 |
| **`camofox-1`**（2026-10-26 起，现行生产面） | 16 | 14 | 3 | 7 |

### 5.3 参数形状：为什么是 `role` + `name`

| | obscura 时代 | D12 之后 |
|---|---|---|
| 目标编码 | `{tag: "button", label: "播放"}` | **`{role: "button", name: "播放"}`** |
| 落到 API | `page.locator("button:has-text('播放')")` | `page.get_by_role("button", name="播放", exact=True)` |
| `<input>` 怎么表达 | tag 恒为 `input`，label 取 placeholder | role `textbox`/`searchbox`，name 取 placeholder |
| 图标按钮 | 只能给空 label | name 取 `alt` |
| 编造目标的兜底 | I6 LLM 白名单 | **`count()` 预判 + strict mode**（执行层硬事实） |

`role` 取值是**短闭集**（`button` / `link` / `textbox` / `searchbox` / `combobox` / `checkbox` / `radio` / `tab`），与枚举侧共用同一张表——**该表是唯一真源，不许手抄第二份**（枚举侧与声明侧漂移 = 真实存在的目标表达不出来）。

⚠️ **`name` 的空串率**：F5 实测 **41% 的元素没有可访问名**（其中 90/97 不可见）。所以：
- **枚举侧先过可见性**（否则 41% 的隐藏无名字元素灌进列表）；
- 无名字元素**不提供**定位路径（`get_by_role(role, name="")` → `count == 0` **不报错**，与「元素不存在」同形 → 会造出假负样本，见 [04 方案 §1.5 F5-c](04-camoufox执行层替换方案.md)）；
- 声明里 `name` 必填，但**模型若给了观察里没有的 name，执行层直接判「元素不存在」**（不猜、不静默）。

### 5.4 观察怎么供给——**回执 + 显式读**两条路

| | 谁发起 | 进不进动作流 | 进不进训练 `tool_calls` | 成本 |
|---|---|---|---|---|
| **回执** | 执行器（每个动作执行后） | ❌ 不进 | ❌（是 tool result，不是 tool_call） | 0 次额外 LLM 调用 |
| **显式读** | agent（`snapshot` / `interactive` / `links`） | ✅ 进 | ✅ | 1 次 LLM 调用 |

**为什么保留回执**：显式读会让每步成本翻倍（读 + 动 = 2 次 LLM 调用），而 `max_llm_calls` 只有 12——探索深度会腰斩。回执是「动作的顺带结果」，显式读是「我要看别的」。

**为什么必须有显式读**：回执是**裁剪过的**（正文 4000 字 / 链接 20 条 / 元素 50 条）。裁剪的边界由代码定，模型看不见边界外——**这正是 M-01「窗口 ≠ 候选集合」的成因**。有了 `links` 之后，模型可以**自己决定再读一次链接**（而不是只能看执行器塞的那 20 条），代码侧不必再赌「窗口够不够」。

⚠️ 「越过窗口」目前**只到「能重读」这一层**：`links` 无参数（§5.2），所以模型不能指定「第几条开始」。真要越过窗口，得在采集层加**代码侧**的分页语义（R3），而不是在声明里加一个整数参数。

### 5.5 方言轴与批次元数据

旧批次（361 份 P2 样本）全是 obscura 时代：`target = {tag, label}`，工具集 13 条（11 可见）。新批次是 camoufox 时代：`target = {role, name}`，工具集 16 条（14 可见）。**两套口径不同义，不许混池**（CLAUDE.md「并池是写入时的动作」）。

所以工具声明要有一条**方言轴**：

| | 值 | 内容 |
|---|---|---|
| **工具面** | `obscura-1` | 现状：13 条（11 可见），`click(tag, label)` |
| | `camoufox-1` | 16 条（14 可见），`click(role, name)` + 采集面 3 条（**只读存量面**，2026-10-26 起不再产出） |
| | **`camofox-1`** | 16 条（14 可见），`click(role, name)` + 采集面 3 条（**现行生产面**） |

**面不是第二个独立轴——它由 `driver` 一对一折算**（2026-10-20 实施后的定稿）：

```
P1 RunRecord.driver  ──surface_of_driver()──▶  工具面  ──▶  P2.tool_surface
                                                        └──▶  P3/T 的 tools[]
```

为什么这样收：原草案说「加一个 `工具面版本` 批次元数据字段」——那就有**两个轴**
（`driver` 与 `工具面版本`），而它们**必须一一对应**。两个都要人填的地方
**迟早会填错一半**，且错了不报错（只是训出「有时按标签点、有时按角色点」的模型）。
**只留一个轴**（`driver` 是执行层自己的名字，代码写死的），面由它折算，
**填错的机会只有一处，且那处由代码产生**。

落地：

| 位置 | 字段 | 说明 |
|---|---|---|
| **P1** | `RunRecord.driver` | 执行层实现名（`obscura` / `camofox`；`camoufox` 是**只读存量**名）。与 `executor_mode` **正交**（一个说「谁决策」，一个说「谁开浏览器」）——**它是工具面的唯一来源**。空串 = 没记（不是「未知」） |
| **P2** | 顶层 `tool_surface` | 面身份随样本冻结。**空串 = 这条 P2 没有面身份**（2026-10-20 之前建的）→ 按默认面 `obscura-1` 渲染——那是那批样本**真实跑出来**的面，不是兜底 |
| **P3 / T** | `meta.tool_surface` | 渲染期落进元数据，人工复核时能一眼看出这条是哪个方言 |

**认不出的 `driver` 直接抛**（`surface_of_driver` 抛 `ValueError`）——不猜、不静默回落。`driver` 是代码写死的名字，认不出意味着**代码与归档口径分叉了**，那属于要人看的事（CLAUDE.md「禁止投票/集成，分歧必须暴露给人看」）。

⚠️ 方案 04 §6 的 P6 早就写了「批次元数据（driver + fingerprint + **动作编码版本**）」——**driver 那一半已落地**（`RunRecord.driver`），fingerprint 与编码版本那两半随 R5 走。工具面版本不是「批次收尾时补的元数据」，是**渲染的前置条件**。

### 5.6 训练侧的可移植性口径

方案 04 §6.1 的验收线是「**动作可移植性**：从 P1 的 `steps[]` 里逐条取出动作，按**该面**的原始调用重放，能在脱离本项目的裸浏览器环境里跑通」。

**这条线只对动作面成立**，采集面不适用——`snapshot` / `interactive` / `links` 是**本项目的读页抽象**（camoufox 没有同名原语；`aria_snapshot` + DOM 枚举是我们自己建的）。所以口径要分开写死：

| 面 | 可移植性口径 |
|---|---|
| 动作面（`goto` / `click` / `fill` / `press`） | **调用逐字可移植**——裸浏览器里能原样执行（⚠️ **camofox 面是子串匹配，camoufox 面是精确匹配**——逐字可移植指「同一面内」） |
| 采集面（`snapshot` / `interactive` / `links`） | **行为可移植**（读页要素、越过窗口），**调用名不可移植**——部署环境的读页原语可能叫别的 |

**为什么可以接受采集面不逐字可移植**：目标 agent 的浏览器工具集本来就不是我们的。教它「先读要素、再按 role+name 点」是**可迁移的技能**；教它「调 `interactive()` 这个具体名字」不是。**声明里要写清语义，不许写死实现名**——但**要点名 `get_by_role`**（D12 §5.1：那是模型必须会用的定位语义，不是实现细节）。

## 6. 什么不动

| 资产 | 状态 |
|---|---|
| 22 类分支封闭集 + `BRANCH_PRECONDITION` | **一字不动** |
| fail-closed 纪律、`None` 不中断 / `False` 才中断 | **一字不动** |
| 正负样本纯度（四支「没判出来」不入池） | **一字不动** |
| `toolcatalog` 唯一真源的地位 | **不动**（只是多一条工具面轴） |
| persona 六维 | **不动** |
| 门禁 `testpaths` | **不动** |
| P1 / P2 / P3 **既有字段**的语义与形状 | **一字不动**（只**加**键，不改键） |

⚠️ **「P1 / P2 / P3 契约字段一字不动」这条，在 R1 / R2 实施后不再字面成立**——
D-A10 的原意是「重定义换的是『谁在探索』，不是『产物长什么样』」，
而 R1 落地时发现：**工具面必须落进产物，否则渲染侧无从知道该用哪套声明**
（§5.5）。于是**加**了三个键：

| 位置 | 新键 | 性质 |
|---|---|---|
| P1 | `RunRecord.driver` | 可选（空串 = 没记）。**新批次有、旧批次没有** |
| P2 | 顶层 `tool_surface` | 可选（空串 = 没有面身份）。**旧样本是「按默认面渲染」，不是「渲染不出来」** |
| P3 / T | `meta.tool_surface` | 随样本派生，必有 |

**为什么这仍然是「产物形状不变」**：三个键全是**附加的可选键**，
既有字段一个没改、一个没删、一个语义没变；**旧样本按默认面渲染出来的
产物逐字不变**（`obscura-1` 的声明文本与旧 catalog 逐字相同——R1/R2
的判据之一就是这条）。**可归因性资产（分支集 / 纯度 / fail-closed）一条没碰。**
