## 0. 判定标准：什么算「落地了」

落地不是「代码写了」，而是六条**可机械核**的判据。逐条核，核不过就是没落地。

| 编号 | 判据 | 怎么核 |
|---|---|---|
| **A1 不造** | 语料里的每一行正文 / 每一条元素 / 每一个链接都**逐字来自 P1 原文** | 精炼重建后每行 ∈ 原文行集（方案 25 A1 已有） |
| **A2 不截** | `semantic` 模式下 `body_text` 长度 **==** 选中行拼接长度（逐字相等，不多不少） | 新增：重建后 `len(body_text) == sum(len(l) for l in kept) + 分隔符` ⚠️ **一个刻意的例外**：动作目标（`keep`）**无条件补回** ⇒ 那一行不在模型选中的集合里 ⇒ 正文比「选中行拼接」长。**这是保真口径（模块 docstring 第 6 条）要求的，不是截断** ⇒ A2 的真实含义是「**渲染层一个字都没截**」 |
| **A3 可回退** | 精炼不可用（无旁挂 / 旁挂坏了 / 选中的行对不上原文）⇒ 输出与**没精炼时逐字一致** | 方案 25 A2 已有 |
| **A4 报账** | 任何内容减少都有留痕：`limits` / `truncated` / `body_refined*` / `elements_total` / `links_total` | **零无留痕截断**（§4 六项修完 ⇒ 人工核对） |
| **A5 采集不再丢** | 新批次 P1 的 `truncated.source` 为真的比例 **= 0**（除真实采集降级） | 重采一小批，逐条读 `truncated.source` |
| **A6 降级可见** | 采集降级 / 观察缺件 / 上游截断三类信号**仍然在语料里说破** | `[采集降级: …]` / `[内容不完整: …]` / `observation_missing` 占位仍在（§8） |

⚠️ **`truncated` 两支的语义在阶段 2 被重新划清**（§6.3 #9）：
`source` = **上游采集侧**截断 / `view` = **本层训练态渲染**裁剪 ⇒
「**模型少选了行**」**不算**截断（语义模式 `view` 恒 False）⇒ **A6 的
「上游截断」那一支仍然在**，但**本层裁剪**那一支在语义模式下**不再触发**
⇒ fail-closed 的训练信号怎么迁见 §6.4（**阶段 3**，**尚未做**）。

⚠️ **A5 与存量互斥**：存量 P1 的 6000 字截断**不可逆**——全量从未存在过，**任何下游 LLM 都救不回来**。⇒ 老批次的 `[内容不完整: 上游截断]` **必须保留**（要么重采、要么接受），**不能为了让标记消失而删标记**（那是「装作没截断」）。

## 2. 关键结论：四类不是同一件事

| 类别 | 条目 | 为什么不能一刀切 |
|---|---|---|
| ✅ **能直接禁**（纯自伤） | A12 · A13 · A17 · C8 · C9 · E7 | 裁的是**本来就短**的诊断文本，或裁在**去重之前**（⇒ 归因错） |
| ⚠️ **要用 LLM 替掉 / 提预算** | C1-C6（320/10/4/2000/50/50）、D1-D3（600/25/20、600/20/500）、A1（6000） | 裁的是**真实内容**；提预算解不了「送进 LLM 的选什么」，要用「让模型选」 |
| ❌ **物理不可禁** | E1（后端 128k 硬顶）、E2（超时是时间物理）、上下文窗口 | 只能「提到实测够用的值 + 换预算重试 + 报账」 |
| 🧹 **是清洗，别动** | C11 · C12 · A25 · F1 · F2 | 噪声行 / 重复行 / 坏行丢弃。**动它是把清洗变成截断**，而且会让「裁掉的是噪声还是内容」再也分不清 |

⚠️ **最容易犯的错**：把 C11/C12（规则剔噪）也当成「截断」给禁掉。那会得到**满屏导航与页脚**的训练语料——比 320 字更糟。

## 3. 两个独立问题，别混着做

**两条硬顺序**：

- **只做问题 2 不做问题 1** ⇒ LLM 在残骸里挑「核心内容」，挑得再好也是残骸。
- **只做问题 1 不做问题 2** ⇒ 全量正文进 SFT，一条回执几万字，成本爆炸 + 信噪比垮掉 + 模型学不动。

⇒ **问题 1 是问题 2 的前提**。但问题 1 要**重采**，所以问题 2 先落地（它可回退、可并行验证），采集层随后提。

## 4. 阶段 0 · 账本自洽（**前置**，零风险）

> 没有可信账本，「我裁了什么」答不上来 ⇒ 后面所有「我取消了截断」的判断都是猜。

### 4.1 E3 · `finish_reason=length` 且 content 非空 ⇒ **静默截断**（**最高优先级**）

```python
# llm/client.py:737-747
choice = data["choices"][0]
finish = choice.get("finish_reason")
content = choice["message"]["content"]
if not isinstance(content, str) or not content.strip():
    if finish == "length":
        raise _BudgetExhausted(...)
    raise ValueError("content 为空")
return content          # ← finish_reason="length" 且 content 非空 ⇒ 原样返回
```

**为什么这是「用 LLM 选核心内容」的直接腐蚀路径**：

模型输出的是**行号表**（`12 45 88 …`）。若输出被 `max_tokens` 截断：

1. `finish_reason="length"`，`content` 非空 ⇒ 客户端**原样返回**，**不报错、不进账本**；
2. `refine/refiner.py:156` 的 `parse_selection` 拿到半张表 ⇒ **当成合法选择**（前 12 行选了，剩下没选）；

## 5. 阶段 1 · 提预算（采集与送入**同时**成立）

### 5.1 输出预算：`8192` → **`131072`**

```python
# llm/client.py:91

```

**⚠️ 不能设 200000。** 200k 是**输入窗口**；`max_tokens` 是**输出预算**，后端上限 128k。写成 200000 的后果是链式的：

```python
# llm/client.py:670-681
if resp.status_code >= 400:
    error = f"http:{resp.status_code}"
    if resp.status_code < 500:
        self.breaker.record_4xx(resp.status_code)   # ← 4xx 不重试 + 记熔断
        return None, None, error
```

`CIRCUIT_BREAKER_THRESHOLD = 3`（`:150`）、`NON_TRIPPING_4XX = {408, 429}`（`:159`）
⇒ **连续 3 次 400 就熔断整批**，之后所有调用直接返回 `circuit:open`（`:647`）。

⇒ **症状是「判定全空、报表上像 LLM 判不了」，真相是「参数多写了一个零」。**
⇒ 输出预算设 **`131072`**（= 128k）。

`llm/client.py:652` 把 `max_tokens` **原样**发给后端，客户端**没有上限校验** ⇒ **改一个环境变量就生效，不需要动代码**：

```
TRAJECTORY_LLM_MAX_TOKENS=131072
```

#### 为什么对话层窗口（`_BODY_WINDOW` 等）本轮**刻意不动**

owner 的指令是「禁止做内容截断，所有阶段都不允许做」，但**对话层**这一处的
抬升**会把风险从「截断」换成「上下文溢出」**——而后者**更糟**：

1. **对话历史是逐轮累积的**（`agent_loop` 不裁 `self.messages`，见
   `agent_loop.py:1289` / `:1449` / `:1467` / `:1805`）⇒ 抬窗口 = 每一轮
   送出去的量都变大 ⇒ **累积到第 N 步就撞上模型上下文窗口** ⇒ 后端回
   **400** ⇒ 客户端按 4xx **不重试** + 记熔断 ⇒ **整批判分不可信**。
   截断只是「少给一点」，溢出是「整批报废」——**方向相反**。
2. **真实正文实测只有 ~3000 字**（本仓库真实 P1：3301 / 3253 / 2987 字）
   ⇒ `_BODY_WINDOW = 4000` **本来就装得下** ⇒ 抬它**在实际数据上零收益**，
   却把 1 条的风险兑现成 100% 的风险。
3. **读原语已提供按需全量通道**（`_READ_ELEMENT_LIMIT=200` /
   `_READ_LINK_LIMIT=200`）⇒ 模型想要更多时**可以主动拉**，不必靠抬高
   推送窗口。

⇒ 记为**残留项**（阶段 3 或单独一轮处置）：若将来要动，必须**先**把
`self.messages` 的裁剪策略补上（按轮次或按字符预算淘汰旧轮），**再**
抬窗口 ⇒ 否则就是在「禁止截断」的旗号下引入一个更糟的截断（400）。

⚠️ **`executor/orchestrator.py` 的原注释明说**：D-2 评分器靠
「`len(观察里存的)` 与 `elements_total` 的差」判断「目标是不是可能被裁掉了」，
而这个差**只有在两处截断对齐时才有意义**。⇒ 元素上限**四层**
（`SHARED_LIMIT=500` / `DEFAULT_LIMIT=200` / `OBS_ELEMENT_LIMIT` /
`_INTERACTIVE_WINDOW`）**要么一起改，要么一个都别改**。
⇒ 阶段 1 已把「**落盘 vs 采集**」这一对**对齐到 200**（⇒ 那个差归零）；
`_INTERACTIVE_WINDOW`（对话层推送窗口）**没动**——它数的是「送给 agent 的
那一份」，不是「落盘的那一份」，**不参与 D-2 那个差**。

⚠️ **`PERCEPTION_LINK_WINDOW`（分批宽度 20）与 `LLM_LINKS`（窗口 200）
不必相等**：不变量是「**批 ≤ 窗口**」（批比窗口小是安全的，批比窗口大才
危险——那一批会被感知层静默裁掉）。⇒ 同步断言由 `==` 改为 `<=`。

## 6. 阶段 2 · 取消 P2 硬顶，改「语义渲染」模式

> ⚠️ **「调大 320」不够，方向也错**。硬顶是规则层的**固有职责**（`_digest_body` 就是干这个的），不是可调参数；而精炼分支被明文限定为「**换一种裁法**」，**不能替代上限**：
> ```python
> # assembler/observation_view.py:333-335
> text, _noise, truncated = _digest_body("\n".join(ordered), ..., limit=limit)
> # 「硬预算：重建后仍走一遍 _digest_body 的填预算逻辑」
> ```
> ⇒ 必须**新增一条渲染路径**，而不是调大常量。

### 6.1 模式开关

```python
observation_view.render(obs, focus=..., keep=..., refined=..., mode="capped" | "semantic")
```

| | `capped`（现状） | `semantic`（新） |
|---|---|---|
| 正文上限 | 320 硬顶 | **无字符硬顶** |
| 内容来源 | 规则：剔噪 → 按相关度填预算 | **只有 LLM 选中的行**（从 P1 原文逐字重建） |
| 兜底 | 有 | 无（LLM 没选 = 就没有） |
| `limits.body_chars` | 上限值（有 keep 溢出时**账实不一致**） | **实际长度**（单一真源） |
| `truncated.view` | 触顶时 true | **恒 false** ⇒ **2 键契约要升版或重定义**（⚠️ **已重新定义**，见 §6.3 #9：`source` = 上游采集侧截断 / `view` = 本层渲染裁剪） |
| 回执标记 | `[内容不完整: 本次裁剪]` | 不出现（改由 `[内容已精简: 保留 N 行]` 承担） |

⚠️ **语义模式的元素 / 链接也是模型选的**（§6.3 #11）⇒ 「无字符硬顶」在
三段都成立（正文 / 交互元素 / 链接），**不是只对正文**。

⚠️ **语义模式不可用时整条回退 `capped`**——且回退的是**纯规则裁剪**
（老协议只选了正文 ⇒ 元素 / 链接**没被选过** ⇒ 拿它渲语义模式会造出
「正文是模型的、元素是规则的」**混口径**观察）。回退时
`truncated.view` **强制为 true**（诚实记账）。

### 6.2 「让模型选，不让模型写」—— 这条不能破

`refine/prompt.py:16-17` 写得很清楚：
> 提示词里**不许**出现「总结」「概括」「提炼」这类词：它们会把模型从「选行」推向「写摘要」，而摘要的失效模式是**不可验证**的。

理由是**结构性**的（方案 25 §2.1）：模型**只报行号**，文本由渲染层从 P1 原文行**逐字重建** ⇒ 只可能**漏**，不可能**造**。

改成「让模型写摘要」⇒ 事实层被污染、实体检索失效、语料不可比。
⇒ **「禁止截断」绝不能顺手把这条防线拆了。**

### 6.4 fail-closed 的训练信号不能凭空消失

`[内容不完整: …]` 现在是教模型「看到缺件就说判不了」的载体（`rationale/gates.py:148-174` 的 `observation_shortfall` 同款）。全都不截断 ⇒ 这条信号没了 ⇒ **模型被教成「永远敢下结论」**。

⇒ 必须把 fail-closed 的训练信号**迁到**：
- 采集降级（`[采集降级: …]`）、
- `observation_missing` 占位、
- **故意给不完整观察**的负样本线上。

**不能只是把标记删了。**

> ✅ **阶段 2 已把前两类保住**（2026-11-17）：语义模式下 `truncated.view`
> 恒 False ⇒ **只有「本层裁剪」那一支不触发**——而那一支本来就**不是**
> 「证据不全」（是**模型自己的选择**）。真正证据不全的三类信号**逐条验过
> 还在**（`tests/unit/test_semantic_render.py::TestfailClosed信号还在`）：
> `[采集降级: …]` / `observation_missing` 占位 / `[内容不完整: 上游截断]`。
> ⇒ **第三类（故意给不完整观察的负样本线）仍未做**——那是**造数据**，
> 不是改渲染层，留给阶段 3。

#### 6.4b 第三类信号的落地记录（2026-11-18 · 阶段 3）

**第三类信号已落地**——新增 `assembler/failclosed.py`（**唯一真源**）+
`assembler/builder.py::build_failclosed_from_archive` /
`build_failclosed_all` + 命令行 `cli build --stage failclosed`。

**造什么**（与主池样本**同构**，同一套渲染、同一套收尾话术，差别只有三处）：

| 差别 | 做法 | 为什么这么定 |
|---|---|---|
| **缺件那一步的观察不完整** | 三种方式：`body_truncated` / `elements_missing` / `body_missing` | 都对应**真实采集里会发生**的成因——造的样本必须像真的缺件，否则教出来的行为在真场景里对不上 |
| **轨迹在缺件那一步截断** | 后面的动作与观察都拿掉 | fail-closed 的 agent 是「看到缺件就停并如实说」，不是「看到缺件还继续点下去」 |
| **结论改判成 fail-closed** | `outcome.branch` = `unresolved` ⇒ 期望答案由它**派生**（不手写） | 手写话术 ⇒ 两份话术会漂 ⇒ 训练语料里出现「两种说法」⇒ 模型学到「看情况换说法」 |

**三条硬纪律**（每条都有测试钉住）：

1. **缺件标记必须是真的**——回执里**如实**出现 `[内容不完整: 上游截断]` 或
   `[采集降级: …]`。标记是假的 ⇒ 这条线教的是「标记可以乱写」。
   ⚠️ `body_truncated` **只置 `truncated.source`**，不动 `view`——`view`
   说的是「本层训练态渲染裁掉了」，那是规则层的事，改了它就是**谎报**。
2. **只可能漏，不可能造**——正文行是原文的**子集**（砍的是尾部，因为真实
   的上游截断是「预算用尽 ⇒ 后面没了」）；期望答案里没有任何「这个站点是
   什么」的信息，只有「我判不了」。
3. **只有缺件那一步对应的站点改判**——别的站点确实被访问过、确实被排除过
   ⇒ 一并改成「判不了」＝**改写真实事实** ⇒ 训练语料里出现假事实。

**不进主池**：落点是 `output/pipeline/failclosed_samples/`（与 `samples/`
**平级、不同名**）⇒ 主池的读侧**扫不到它**（`select_archives` 只扫
`<根>/*.json`，不递归）。⚠️ 目录名里带 `failclosed` 是为了让「池里多了个
目录」这件事在 `ls` 下一眼可见——起个像 `samples2` 的名字 ⇒ 读的人以为
「主池分了两批」⇒ 于是把两批混着训练。

**留痕**：「这条是造出来的」记在**既有键** `degraded_from`（追加
`failclosed_line`）——读样本的人本来就会看它 ⇒ 不新开顶层标记键；另加两个
顶层键 `failclosed_cut_mode` / `failclosed_cut_step`（缺在哪、缺的是什么）。
⚠️ **`sample_id` 与原样本不同**（`<原 id>__fc-<缺件方式>`）——同 id 会
**覆盖**主池里那条真实样本，而文件系统的行为是**静默覆盖**。

**实测**（pilot 根下 4 份真实存档 × 3 种方式 = **12 条**）：回执出现
`[采集降级: body_text]` / `[内容不完整: 上游截断]`；收尾派生为
「无法确认能否播放，不予记录」；**非决定性站点保留真实原因**（如
「地区限制/验证码/反爬阻断，排除」）。测试：
`tests/unit/test_failclosed_line.py`（**24 条全绿**）。

#### 6.5d-3 缺口 C：读步观察（正文为空）压根没进精炼 ⇒ **语义精炼对读步完全失效**

**现象**：15 条观察在生产路径上回退 ⇒ 渲染层退回规则裁剪（元素 10 / 链接 4
条硬顶）⇒ **正是本方案要禁掉的截断**。

**根因**：`refine/reader.py::iter_observations` 的老规矩「**正文为空的观察
不进清单**」——那条规矩是**规则模式**的规矩（规则模式只精炼正文 ⇒ 没正文
就没得选 ⇒ 不进清单**是对的**）。照搬到**语义模式**就错了：

- 语义模式是**三段协议**（正文 + 元素 + 链接）⇒ 读步观察（`read=interactive`
  / `read=links`）的**元素 / 链接照样该由模型选**；
- 而读步观察**只采了被读的那一块**（方案 23 R4-1）⇒ **正文天然是空的**
  ⇒ 「正文为空」是**正常状态**，不是「这条观察没东西」；
- ⇒ 这些观察**压根没发过 LLM 请求** ⇒ 旁挂里没有它们的记录 ⇒ 渲染层查不到
  ⇒ **整条回退规则裁剪** ⇒ 10 / 4 条硬顶原封不动地留在语料里。

**修法**（判据**按渲染层的口径** ⇒ 唯一真源 `common/view_candidates.read_blocks`）：

| 项 | 改动 |
|---|---|
| **判据分开** | `iter_observations(archive, *, semantic=False)`：规则模式**一字不改**（正文为空 ⇒ 不进清单，零回归）；语义模式 ⇒ 正文为空**但有元素 / 链接**的观察**进清单**；三块都空的**不进**（没有候选 ⇒ 不值得发请求） |
| **「哪几块」按渲染层口径判** | `read_blocks`（**唯一真源**）——`snapshot` 只渲染正文 ⇒ 它那些元素**不算候选**（渲染层不会渲染它们 ⇒ 模型选了也白选） |
| **「没有候选」不是失败** | `refine_body` 在语义模式下把「三块都空」记成 `not_needed`（不是 `failed`）——否则报表会把「没东西可选」说成「精炼失败」（这两件事的处置完全不同） |
| **调用量代价** | 三档真实存档：**174 → 188** 次（**+8.0%**）——与候选集键那次（**+8.9%**）同量级 |

⚠️ **这条修法改的是「精炼侧收哪些观察」，不是「渲染层怎么裁」**⇒ 渲染层的
契约（`limits` 7 键 / `truncated` 2 键 / A1 A2 A3）**一个字没动**。
